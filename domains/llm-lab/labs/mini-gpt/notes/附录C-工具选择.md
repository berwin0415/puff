# 附录 C：为什么用 Python 和 PyTorch

> **什么时候看**：想换工具、或者好奇"为什么不用 TensorFlow"的时候。正文不需要先读它。

## 为什么是 Python

先说结论：**模型是用 Python 写的，但真正干重活的不是 Python。**

三个理由：

1. **生态**：PyTorch、TensorFlow、JAX 都优先支持 Python；教程、论文代码、开源模型也基本都是 Python 写的，遇到问题搜得到答案。
2. **代码接近公式**：定义一个网络层，Python 里几乎就是照抄数学表达式；换成 C++ 或 Java，相当一部分篇幅要花在类型和样板代码上。
3. **它只是调度员，不是工人**：矩阵乘法、卷积这些重活最终跑在 PyTorch 的 C++ / CUDA 内核里，Python 只负责把运算排好队。所以"Python 慢"在这里几乎不影响训练速度——慢的是纯 Python 写的大循环，而我们把循环交给了张量运算。

### 为什么不用更熟悉的语言

- **TypeScript / JavaScript**：前端工程师最顺手，但深度学习生态薄。TensorFlow.js 主要面向浏览器推理，训练和自定义算子支持有限；而且要和 CUDA 打交道，Python 是最近的入口。
- **C++**：性能最好，但写起来慢、调试重。它适合写训练框架本身，不适合"边学边改结构"。
- **Julia**：科学计算快、语法也友好，但社区和现成模型少得多。

一句话：**这个项目要的是"改一行、跑一次"，不是"跑得最快"。**

## 先说"框架"是什么

写模型要用大量现成的数学工具：矩阵乘法、自动求导、各种网络层。如果每一样都自己实现，光是把矩阵乘法写对、写快，就要花掉大部分精力。

**框架就是把这类工具打包好的库。** 你不用关心显卡怎么调度、梯度怎么求，调用它提供的函数就行。

本项目的框架是 **PyTorch**。

## 为什么是它

它不是唯一的选择，但对"边写边看"的学习方式最合适：

| 工具 | 特点 | 适不适合这里 |
| --- | --- | --- |
| **PyTorch** | 每行代码立刻执行，能 `print`、能断点；梯度是一个能直接看的张量 | 适合 |
| TensorFlow | 生产部署成熟，早期以"先搭图、再运行"为主 | 调试体验对新手不友好 |
| JAX | 函数式、编译优化强 | 心智模型更绕，不适合第一次学 |
| 纯 NumPy 手写 | 最彻底 | 得先自己实现自动求导，第一步就卡住 |

还有三个现实理由：绝大多数教程和开源模型都用它，遇到问题好搜；Windows 上有官方提供的 CUDA 构建；它的自动求导足够透明——梯度不是黑盒，就是一个你能直接打印出来的张量。

## 它的边界

"从零搭模型"容易被误解成"连矩阵乘法都自己写"。实际的分工是：

- **它负责**：张量运算、自动求导、`Linear` / `Embedding` / `LayerNorm` 这类现成的层。
- **我们自己写**：模型怎么搭、注意力怎么算、训练循环怎么写、怎么采样。

**没有用 `nn.Transformer`，也没有用 `transformers` 库。**

所以"从零"指的是：**结构从零搭，不是运算符从零实现。**
