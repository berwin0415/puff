## 0. 先认识三个词

后面所有内容都建立在这三个词上：

| 词 | 一句话解释 |
| --- | --- |
| **token** | 模型处理的最小单位。它不是文字，而是一个**整数**（比如字符 `H` 对应 20）。模型全程只和整数打交道。 |
| **模型** | 一个函数：输入一串整数，输出下一个 token 的概率分布。它没有别的能力，"生成文本"是反复调用它的结果。 |
| **参数** | 函数内部那些**会被训练改变**的数字。所谓"训练"，就是不断微调这些数字。 |

一个具体的量级：本项目的模型有 **824,897 个参数**，处理 **65 种 token**（莎士比亚剧本里出现过的全部字符）。

**两个"大小"别混**（后面每篇都会用到，这里一次说清，不再重复）：

- `vocab_size` 是**有多少种 token**——本项目 65。它决定输入表有多少行、输出层吐出多少个分数；
- `d_model` 是**每种 token 用多少个数字表示**——本项目 128。它决定模型内部每个位置上的向量有多宽。

## 1. 一句话概括

**LLM = 一个"预测下一个 token"的函数 + 让它变好的机制 + 喂养它的数据管道。**

拆开看就是下面四个组件。缺任何一个，整条链路都跑不起来。

## 2. 第一层：训练一个模型需要四样东西

| # | 组件 | 它解决什么问题 | 输入 → 输出 |
| --- | --- | --- | --- |
| 1 | **分词器** | 模型只吃数字，而文本是字符 | 文本 → 整数序列 |
| 2 | **模型** | 得有个东西来"预测" | 整数序列 → 每个位置对每个 token 的分数 |
| 3 | **损失函数** | 得能量化"预测得多差" | 分数 + 正确答案 → 一个数字 |
| 4 | **梯度下降** | 得能自动把参数调好 | 损失 → 参数更新 |

这四样构成一个闭环：

```
数据 → 模型 → 预测 → 损失 → 梯度 → 更新参数 → 更好的模型 → 回到数据
```

先记住这个闭环，比记住任何模型结构都重要——后面所有的复杂度，都只是把"模型"这一格换得更复杂。

## 3. 数据怎么流动

以生成一个字符为例，一个 token 从头到尾的旅程：

```
文本 "Hello"
   │
   │ ① 分词：查词表，把每个字符换成一个整数
   ▼
[20, 43, 50, 50, 53]                 长度 T 的整数序列
   │
   │ ② 嵌入 + 位置编码：每个整数换成一个 d_model 维的向量
   ▼
(B, T, d_model)                      每个位置一个向量
   │
   │ ③ N 层 Transformer：注意力 + 前馈网络，形状不变
   ▼
(B, T, d_model)                      还是每个位置一个向量
   │
   │ ④ 输出层：把每个向量投影成 vocab_size 个分数
   ▼
(B, T, vocab_size)                   每个位置对每个 token 的分数
   │
   │ ⑤ softmax + 采样
   ▼
下一个 token → 拼回输入 → 从头再来一次
```

图里三个符号：`B` 是同时处理的文本条数（批次），`T` 是每条文本的长度，`d_model` 是每个 token 用多少个数字表示（本项目是 128）。

**两个关键观察**：

1. **形状在整个 Transformer 里保持不变**（一直是 `B × T × d_model`）。注意力、前馈、残差都不改变形状，只改变数值。只有输入（嵌入）和输出（输出层）两端会换维度。
2. **最后一层输出的是分数，不是概率**。分数可以是任意实数；经过 softmax 才变成加起来为 1 的概率。

## 4. 训练循环只有四步

不管模型多大，训练都在重复同样四件事：

```python
logits = model(x)                      # 1. 前向：算出预测
loss = cross_entropy(logits, y)        # 2. 算损失：量化这次错得多离谱
loss.backward()                        # 3. 反向：算出每个参数的梯度
optimizer.step()                       # 4. 更新：按梯度把参数挪一点
```

外加一行 `optimizer.zero_grad()`——因为梯度是**累加**的，不清零会越积越大。

这四步从模型只有一层到有几十层都不会变。**模型的复杂度全部堆在第 1 步的 `model(x)` 里面。**

## 5. 第二层：那个"模型"里面有什么

第 2 节的"模型"是一个黑盒。打开它，一个 Transformer 语言模型由这些零件组成：

| 零件 | 作用 | 删掉会怎样 |
| --- | --- | --- |
| **嵌入** | 把 token 的整数 id 查表换成一个向量 | 模型无法处理数字之外的输入 |
| **位置编码** | 告诉模型每个 token 排在第几位 | 分不清语序，"猫追狗"和"狗追猫"变成同一件事 |
| **自注意力** | 让不同位置的 token 互相参考 | 每个位置只能看自己，退化成"只看前一个字符" |
| **前馈网络** | 对每个位置单独做一次非线性变换 | 只剩信息的搬运，没有加工能力 |
| **残差连接** | 把子层的输入原样加回输出 | 深层网络梯度传不动，层数越多越难训 |
| **层归一化** | 把每个位置的数值拉回稳定范围 | 深层训练容易发散 |
| **输出层** | 把向量投影成词表大小的分数 | 无法产生预测 |

这些零件的必要性分三档：前四个决定模型**能不能表达**，残差与归一化决定它**能不能训得动**，输出层决定它**能不能给出答案**。

**一个常见误解**：以为注意力是 LLM 的全部。实际上注意力只负责"在位置之间搬运信息"，前馈网络才负责"就地加工"，两者在同一层里交替出现，缺一不可。

## 6. 本项目是怎么搭出来的

上面这些零件不是一次写完的。本项目用八步逐个加上去，每一步都先把上一步的**具体缺陷**暴露出来，再补上对应的零件。

**这张表是全书唯一的进度对照表**，其余各篇不再重复；想知道"现在走到哪、比上一步好了多少"，回这里看。

| 步骤 | 加了什么 | 暴露的问题 / 结果 |
| --- | --- | --- |
| 1 | 环境与自动求导 | 确认 GPU 与梯度机制可用 |
| 2 | 字符级分词 | 文本变成整数，词表 65 项 |
| 3 | 计数式 bigram | 语言模型 = 概率分布；验证集出现 `inf` |
| 4 | 换成梯度学习 | 同样的事用梯度做一遍，损失 2.490 |
| 5 | 上下文 8 + 隐藏层 | 突破单字符上限，损失 1.888 |
| 6 | 单头注意力 | 赢过取平均，但缺位置信息，反而退步 |
| 7 | 完整 Transformer | 位置编码 + 残差 + 前馈，损失 1.651 |
| 8 | 训练工程化 | 学习率调度，最终损失 **1.556** |

表中的损失都是在**没参与训练的验证集**上测的，越低越好。完整目标与验收标准见 [ROADMAP.md](../ROADMAP.md)，每一步的详细讲解从 [01-环境.md](./01-环境.md) 开始。

## 7. 哪些东西这里不做

"最小"是有边界的。下面这些在真实产品里很重要，但和"理解模型怎么运转"无关，本项目全部跳过：

- 分布式训练、多卡并行、混合精度
- 混合专家（MoE）、多模态、长上下文技巧
- RLHF、DPO、指令微调
- KV cache、量化、推理引擎
- 自己训练 BPE 分词器

它们解决的是"把这个模型做得更大、更快、更听话"，而不是"它是怎么工作的"。等你能说清这张总览图，再去看它们会容易得多。
