# 第 6 步：单头自注意力

> **一句话**：让模型自己算出"该重点看前面哪些字符"，而不是把所有位置平等对待。
> **这一篇要回答**：模型能不能自己决定该重点看哪几个字？

## 这一步解决什么问题

第 5 步把所有历史字符**平等地**拼在一起：位置 0 和位置 7 的权重是写死的，模型不能选择"这个字符更值得看"。

注意力把这件事交还给模型：**每个位置根据内容，自己算出该重点看前面哪些位置。**

这一节先做一个"取平均"的对照，再换成 Q/K/V。结果会有点反直觉——注意力确实大幅赢过取平均，**但还没赢过第 5 步的固定窗口**。原因正好指向第 7 步。

## 读完你会知道

- 注意力和"取平均"的本质区别是什么；
- Q、K、V 各自回答什么问题，为什么要除以 `√d`；
- 因果掩码如果去掉，训练会以什么方式"作弊"；
- 为什么单头注意力会输给第 5 步那个更笨的结构。

## 怎么读这篇

**标记约定**：出现 `（→ 第 N 步）` 表示那个概念在后面那一步才正式讲解，这里只要知道名字就行。

**本文范围**：只做**一个头**、**一层**，也没有位置编码。这不是完整的 Transformer——那正是第 7 步的内容。本文的重点是看清"注意力在替代什么"。

## 对照组：取平均

最朴素的汇总方式：把前面所有字符的向量加起来除以个数。

```
输出(t) = (向量(0) + 向量(1) + ... + 向量(t)) / (t+1)
```

它有个致命毛病：**所有位置权重相同**。`thou art` 和 `art thou` 的平均结果完全一样，而这两个片段的下一个字符很可能不同。

## 注意力：权重由内容决定

每个位置产生三个向量——查询、键、值（Q、K、V）：

| 向量 | 名字 | 它在回答什么 |
| --- | --- | --- |
| **Q** | Query（查询） | "我现在想找什么信息？" |
| **K** | Key（键） | "我这里能提供什么信息？" |
| **V** | Value（值） | "如果被选中，我实际贡献什么内容？" |

计算过程只有四步：

1. **匹配**：当前位置的 Q 和前面每个位置的 K 做点积，得到一组分数
2. **缩放**：分数除以 `√d`（d 是向量长度）
3. **归一化**：softmax，把分数变成加起来为 1 的权重
4. **汇总**：用权重对 V 加权求和

```
权重 = softmax(Q·Kᵀ / √d)
输出 = 权重 · V
```

**为什么要除以 `√d`？** 向量越长，点积的数值越大。分数一大，softmax 就会变得极端（一个位置接近 1，其余接近 0），梯度随之消失，模型学不动。除以 `√d` 把分数拉回合适的范围。

**为什么必须有因果掩码？** 训练时整段文本同时在模型里，如果不加限制，位置 5 就能看到位置 6 的答案——这是作弊。掩码把"未来"位置的分数设成 `-inf`，softmax 之后它们的权重就是 0。**生成时没有未来可看，训练时也不许看。**

**注意力比取平均好 0.613**，这是干净的胜利：同样是"从前面汇总信息"，一个权重写死，一个权重学出来。

## 为什么注意力会输给一个更笨的结构

看这张注意力权重表，输入是 `thou art my`，最后一行是最后一个字符 `y` 看向前面各位置的权重：

```
'y'  0.968
' '  0.012
' '  0.012
'h'  0.005
'm'  0.001
```

**它把 96.8% 的注意力放在了自己身上。**

这个行为很合理：输出是前面所有 V 的加权平均，如果它不看自己，当前字符的身份就丢了。在**没有位置信息**的情况下，模型唯一的自保办法就是"死死盯住自己"。

于是它退化成了一个"只能看到自己"的模型——这解释了为什么它的 2.452 和"只看一个字符"的 2.458 几乎一样。

缺的两样东西是：

1. **位置编码**：注意力本身分不清"这个 token 在第几个位置"。没有它，模型不知道谁离自己近、谁离自己远。
2. **残差连接 + 前馈网络**：现在每个位置的输出完全来自加权平均，当前字符自己的信息只能靠"注意自己"来保留。残差会把输入原样加回去，从结构上解决这个问题。

这正是第 7 步要补的。

## 脚本在验证什么

1. **两个模型用同样的窗口、同样的步数、同样的数据**，只换汇总方式，保证对比干净。
2. **打印两边的参数量**：注意力多了 3 个投影矩阵（8,385 → 20,673），这个差距要摆出来。
3. **把注意力权重直接打出来**，而不是只报损失——否则"它学会了什么"完全看不见。
4. **和第 5 步的数字并排放**，避免读者误以为"注意力一定更强"。

## 回顾

- **做了什么**：同一个 32 字符窗口，分别用"取平均"和"单头 Q/K/V 注意力"训练一遍。
- **关键数字**：取平均 3.065，注意力 2.452，改进 0.613——**但两者都还没赢过第 5 步的 1.888**。
- **一个关键证据**：输入 `thou art my` 时，最后的 `y` 把 0.968 的权重给了自己。
- **在总览图上的位置**：数据流第 ③ 步里"注意力"那一格。
- **留给下一步**：缺位置编码、缺残差、缺前馈网络——第 7 步一次补齐。

## 本步新名词

累计索引见 [glossary.md](./glossary.md)。

- **自注意力（self-attention）**：同一个序列内部，各位置互相参考的机制。
- **查询、键、值（Q、K、V）**：注意力里的三个投影向量。"我想找什么 / 我能提供什么 / 我实际贡献什么"。
- **注意力权重（attention weights）**：softmax 之后、加起来为 1 的分配比例，表示"这个位置看了谁多少"。
- **因果掩码（causal mask）**：把每个位置右边（未来）的分数设成 `-inf`，保证它只能看左边。

## 自测详解

### 1. 取平均和注意力的本质区别

**权重是不是学出来的。**

取平均的权重是固定的：前面有 n 个位置，每个都是 1/n。不管内容是什么，分配方式完全一样。

注意力的权重是算出来的：由 Q 和 K 的点积决定，而 Q、K 本身是可训练的参数。模型可以学会"看到 `q` 就重点看后面那个 `u`""看到句号就看句首"。**同样是从前面汇总，一个写死，一个学出来。**

### 2. Q/K/V 各在回答什么

用一个找书的比喻：

- **Q（查询）**：你手上的搜索词——"我想找什么"
- **K（键）**：每本书的标题标签——"我这里能提供什么"
- **V（值）**：书的实际内容——"如果选中我，你得到什么"

先用 Q 和每本书的 K 比匹配度（点积），决定看哪几本（softmax 权重），再看它们的 V（加权求和）。

三者都来自同一个输入向量、经过三个不同的线性层——**所以叫"自"注意力：查询方和被查询方是同一个序列。**

### 3. 为什么要除以 `√d`

因为点积的长度随维度增长。两个 d 维向量做点积，结果的方差大致正比于 d。d=64 时，分数很容易到几十甚至上百。

softmax 对大的输入非常敏感：分数差 20，权重就几乎是一个 1 和一堆 0。**权重一极端，梯度就几乎为 0**——模型学不动（附录 B里的"梯度消失"）。除以 `√d` 正好把这个方差拉回 1 附近。

### 4. 去掉因果掩码会怎样

训练时，每个位置都能看到**后面**的字符，包括它要预测的那个答案。模型会立刻学会"抄答案"：损失飞快降到接近 0，看起来训练大获成功。

但生成时没有"后面"可看——第一个 token 生成时，后面还不存在。于是模型完全不会工作。

这是个特别隐蔽的坑，因为**训练曲线会非常漂亮**。因果掩码不是优化项，是正确性问题。

### 5. 为什么输给第 5 步？0.968 说明什么

因为**缺位置编码**。

注意力本身对位置不敏感：把输入顺序打乱，输出只是跟着打乱。模型知道"前面一共有 8 个位置"，但不知道"当前这个在第几个、谁离我最近"。而第 5 步的固定窗口天然带着位置信息——第 8 个位置永远对应"最近的字符"。

0.968 是模型的应对方式：**既然分不清位置，那就死死盯住自己**，至少保证当前字符的信息不丢。代价是它对前面 31 个字符几乎视而不见——所以它的表现和"只看一个字符"差不多。

第 7 步加入位置编码后，这个局面会改变；再加入残差（把输入原样加回去）之后，模型就不再需要通过"注意自己"来保命了。
