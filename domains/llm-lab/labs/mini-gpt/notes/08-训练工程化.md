# 第 8 步：训练工程化

> **一句话**：模型结构不动，只改训练方式和采样方式，把验证损失从 1.651 压到 1.556。
> **这一篇要回答**：结构已经够好，还能从哪里再挤出性能？

## 这一步解决什么问题

第 7 步的架构已经完整了，但训练方式还很粗糙：学习率从头到尾固定在 `3e-4`，梯度不做任何限制，也从来不看验证集。

这一步补上三件事，并回答一个一直悬着的问题：**训练完之后，怎么把模型变成一个能用的生成器。**

1. 学习率：warmup + 余弦调度
2. 梯度裁剪
3. 按验证集保存最佳 checkpoint

最后是采样策略：温度和 top-k 采样。

## 读完你会知道

- 为什么训练开头要 warmup，结尾要降温；
- 梯度裁剪在防什么，没触发时它有没有价值；
- 为什么保存"验证集最好"的那一版，而不是最后一步；
- 温度和 top-k 分别在改变什么，能不能叠加。

## 怎么读这篇

**标记约定**：出现 `（→ 第 N 步）` 表示那个概念在后面那一步才正式讲解，这里只要知道名字就行。

**本文范围**：模型结构一个字没改（还是第 7 步的 4 层 × 4 头）。所有提升都来自"怎么训练"和"怎么采样"。

## 三件工程手段

### 调整一：学习率为什么要先升温、再降温？

```
warmup 阶段： lr 从 0 线性升到 8e-4（前 300 步）
之后：        lr 按余弦曲线从 8e-4 降到 1e-5
```

**为什么要 warmup？** 训练刚开始时，模型参数是随机的，梯度的统计量（Adam 内部的均值与方差估计）也几乎是空的。这时候直接上大学习率，参数会被一个毫无参考价值的梯度推得很远——常见的结果是损失先飙升，甚至直接发散。

先让学习率从接近 0 开始，等于给优化器几百步"熟悉地形"的时间。

**为什么要降温？** 训练后期模型已经接近一个好的位置，大步子只会在附近来回跳。让学习率逐渐趋近于 0，参数才能稳稳落进去。第 7 步固定 `3e-4` 的效果，就是一直在好位置附近晃。

### 调整二：梯度为什么要剪？

```python
grad_norm = clip_grad_norm_(model.parameters(), 1.0)
```

算完梯度后，先看所有梯度的总长度。如果超过 1.0，就整体按比例缩回去。

它防的是**偶发的梯度爆炸**：某个批次的文本恰好触发了某种极端模式，梯度突然变得极大，一步就能把之前几千步的训练毁掉。裁剪保证单步更新的幅度有上界。

这次训练里 `grad_norm` 一直在 0.3 左右，从没触发过裁剪——**它是一份保险，不是必需品**。但训练大模型或换数据集时，它经常是"能跑完"和"中途 NaN"的区别。

### 调整三：为什么要按验证集保存？

每 500 步在验证集上算一次损失，只保存验证集最好的那一版：

```python
if val_ce < best["val"]:
    best = {...}
    save_checkpoint(...)
```

**为什么不能直接保存最后一步？** 因为训练损失会一直下降，验证损失却会在某个点之后开始上升——那之后模型在"背"训练集，继续训练只会更糟。保存最佳 checkpoint 就是最简单的一种早停。

checkpoint 里必须同时存**权重**和**结构参数**：只有权重的话，加载时你不知道该用几层、几头、多宽的模型，state_dict 根本对不上。

## 实测

```

参数量         : 824,897
调度           : warmup 300 步 → 余弦降到 1e-05
梯度裁剪       : 1.0

  第     0 步  lr = 2.67e-06  loss = 4.2850  grad_norm = 0.96
    → 验证：训练 2.157 / 验证 2.179
    → 验证：训练 1.776 / 验证 1.908
  第  1000 步  lr = 7.71e-04  loss = 1.8731  grad_norm = 0.28
    → 验证：训练 1.607 / 验证 1.778
    ...
  第  5000 步  lr = 6.85e-05  loss = 1.4448  grad_norm = 0.32
    → 验证：训练 1.351 / 验证 1.557
  第  5999 步  lr = 1.00e-05  loss = 1.4504  grad_norm = 0.32
    → 验证：训练 1.350 / 验证 1.556

最佳一步:
  第 5999 步   训练 1.350   验证 1.556
第 7 步基线（固定学习率）: 验证集 1.651
改进                      : +0.095
```

**1.556 是整个项目到目前为止最好的验证损失。**

注意最佳出现在最后一步——说明这 6000 步还没到开始过拟合的拐点。如果继续训练，验证集迟早会掉头向上，那时"保存最佳"才会真正发挥作用。**这个机制现在没生效，不代表它没用，只是这次还没到需要它的时候。**

另外注意 `grad_norm` 始终在 0.3 左右。裁剪阈值是 1.0，所以**它一次都没触发**。这是一份保险，不是提升来源——提升来自学习率调度。

## 采样策略：同一个开头，五种性格

模型训练完之后只是一个"给前文、吐概率分布"的函数。下面五种抽法用的是**同一个模型**，只改怎么从分布里取：

### 贪心（每步取最大）

```
ROMEO:
I have my lord, and the prince of the common of the common
That we will be the state of the common of the common
That which I will not stand the state of the country.

CORIOLANUS:
I will not so so so
```

**最确定，也最无聊。** 一旦进入"the common of the common"这种循环，就再也出不来。第 3 步和第 4 步的换行符死循环，是同一个问题的极端版本。

### 温度 0.5（更保守）

```
ROMEO:
I am I thee to their cousin with the death?

First Servant:
I have you shall have so soul to be not on him.

BUCKINGHAM:
What say you are in that I should swear this state
Shall be the brave of the w
```

温度低于 1，会把概率分布"压尖"：高概率的选项更占优。结果更通顺、更像语法正确的句子，但缺少变化，容易重复常见句式。

### 温度 1.0（按模型本来的分布）

```
ROMEO:
Say thinks, beat time buy thy mocking.

Nurse:
And we go brows thus night--

KING RICHARD II:
Do lose this the shall burns of tranion my sile,
and few the great death that live amazed
law-precious an
```

这是模型**本来的**概率分布，没有放大也没有压缩。可读性和多样性最平衡——`Say thinks, beat time buy thy mocking` 几乎像一句真的台词。

### 温度 1.5（更狂野）

```
ROMEO:
Say he? heaven?
Hoi know up you caithdrum, given. not guess'd
Give you rebury?

GLOUCESTER:
ComI lose Waim the shear but stop.

EDWARD:
Loise, and Senver ups awhileblens.
Blied umpridely.
```

温度高于 1，分布被"压平"，低概率选项也有了机会。多样性大增，但很快散架：`caithdrum`、`Senver`、`Blied umpridely` 都已经是随机拼贴。

### top-k 10（只在最可能的 10 个里抽）

```
ROMEO:
Say thinks, beat time is bite me?

First Murderer:
No, by your suppling sounds, sir. Why, thou art this?

SICINIUS:
As if then a treat was friar?
If your servant with that the purge hold
Before the w
```

top-k 和温度是**两个不同维度**的操作：

- 温度改的是**分布的形状**（压尖或压平），所有候选都还在；
- top-k 改的是**候选的集合**，直接砍掉尾部，只在前 k 个里按原比例抽。

所以它们可以叠加使用：先 top-k 砍掉垃圾选项，再调温度控制剩下的多样性。

## 脚本在验证什么

1. **同一个模型、同一份数据**，只改训练方式，隔离出"工程手段"的贡献。
2. **每 500 步同时报训练与验证**，看得到两条曲线什么时候分开。
3. **checkpoint 存完再读回来**，并且真的用它生成——确保存下来的东西是可用的，而不只是"文件存在"。
4. **五种采样策略用同一个开头**，让差别只来自采样方式。

## 本步新名词

累计索引见 [glossary.md](./glossary.md)。

- **学习率调度（learning rate schedule）**：训练过程中按计划改变学习率，而不是固定一个值。
- **warmup**：训练开头让学习率从接近 0 线性升上来，给优化器熟悉地形的时间。
- **余弦退火（cosine decay）**：学习率按余弦曲线逐渐降到接近 0，让参数在后期稳稳落位。
- **梯度裁剪（gradient clipping）**：梯度总长度超过阈值时整体按比例缩小，防止单步更新过猛。
- **checkpoint**：把模型权重连同结构参数一起存盘，之后可以原样加载。
- **温度（temperature）**：除以 logits 的系数。小于 1 让分布更尖（保守），大于 1 让分布更平（多样）。
- **top-k 采样**：只在概率最高的 k 个候选里采样，砍掉长尾。

## 自测

1. 为什么训练开头需要 warmup，而不是直接上最大学习率？
2. 余弦调度让学习率在后期趋近于 0，好处是什么？
3. 梯度裁剪这次一次都没触发，为什么还要加它？
4. 为什么保存"验证集最好"的 checkpoint，而不是最后一步？
5. 温度和 top-k 分别在改变什么？它们能叠加吗？

## 自测详解

### 1. 为什么要 warmup

因为训练刚开始时，**优化器对地形一无所知**。

AdamW 会为每个参数维护梯度的一阶矩和二阶矩估计，这些估计在开头几步几乎是从零开始的，噪声很大。此时用大学习率，等于拿一个极不可靠的方向去大步前进——参数可能被推到很糟糕的区域，损失先飙高再慢慢爬回来，严重时直接发散。

warmup 的做法是前 300 步把学习率从 0 线性升到 8e-4。等优化器的估计稍微稳定了，再给足步长。

### 2. 余弦退火的好处

训练后期参数已经接近一个好的位置，**大步子只会在附近来回跳**，永远落不进最优点。

让学习率按余弦曲线平滑降到 1e-5，等于把步子越缩越小，最后"停"在谷底附近。这也是为什么第 8 步的验证损失（1.556）比第 7 步固定学习率（1.651）稳定地低一截——不是因为模型更强，而是因为它终于肯收敛了。

### 3. 梯度裁剪没触发，为什么还要加

因为**你不能等到出事才加保险**。

这次训练里 `grad_norm` 一直在 0.3 左右，远低于阈值 1.0，所以一次都没触发。但"这次没触发"是事后才知道的。换一个数据集、换一种结构、或者只是换了随机种子，就可能出现某个批次的梯度突然飙到几十——那时如果没有裁剪，一步就能把几千步的训练毁掉，而且只表现为 loss 变成 `NaN`，极难排查。

加它的成本几乎为零（一次范数计算），收益是"在异常发生时不会静默失败"。

### 4. 为什么保存验证集最好的，而不是最后一步

因为**训练损失和验证损失的走向迟早会分家**。

训练损失几乎总是下降（模型在训练集上越来越熟练），但验证损失会在某个点之后开始上升——那之后模型开始背训练集，泛化能力反而变差。保存最后一步，等于主动选择"背得最熟但最不会举一反三"的那一版。

保存验证集最好的一版，是最简单的早停策略。**注意这次最佳恰好出现在最后一步**，说明 6000 步还没到过拟合拐点，这个机制这次没被用上。这很正常：机制是为"万一"准备的。

### 5. 温度和 top-k 各改什么

**温度改形状，top-k 改集合。**

- 温度 `T`：把 logits 除以 T 再 softmax。T < 1 让差距放大（分布变尖，更保守）；T > 1 让差距缩小（分布变平，更疯狂）；T = 1 就是模型本来的分布。
- top-k：先排序，只保留概率最高的 k 个，其余概率置零再重新归一化。它不改变保留下来的那些候选之间的相对比例。

两者可以叠加：先用 top-k 砍掉长尾（避免偶尔抽到离谱字符），再用温度调节剩下候选的多样性。很多生产系统还会用 top-p（累计概率到 p 就截断），思路和 top-k 一样，只是边界是动态的。
