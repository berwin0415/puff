# llm-lab

本目录是**个人学习区**：从零手写一个最简易的 LLM（mini-GPT），目标是理解，不是交付产品。
它**不是** `@puff/*` 应用或共享包，不参与 pnpm workspace，也不会被根脚本递归执行。

## 定位

- 只服务于一件事：把 Transformer 的每个零件亲手写出来、跑起来、讲清楚。
- 只依赖 PyTorch 的张量与自动求导，**不使用 `transformers` 等现成实现**。
- 所有产物（代码、讲解、语料、进度）都收敛在本目录内，不做跨目录引用。

## 目录约定

```
llm-lab/
├─ AGENTS.md        本文件：目录规范
├─ README.md        入口：当前进度、怎么跑
├─ ROADMAP.md       目标与步骤阶梯（含验收标准与状态）
├─ PROGRESS.md      进度日志（保证学习连续）
├─ requirements.txt Python 依赖
├─ notes/           每一步的讲解正文
├─ scripts/         可运行的步骤入口（stepNN_*.py）
├─ src/minigpt/     会随步骤演进的实现
├─ data/            语料
└─ checkpoints/     训练产物（不入库）
```

## 讲解文档的结构

`notes/` 里每篇按固定结构写，顺序不要变：

1. `# 第 N 步：标题`
2. `## 这一步解决什么问题` —— 先说清楚为什么需要它
3. `## 怎么读这篇` —— 标记约定 + 本文范围（不写什么）
4. 正文若干节 —— 就地解释，**必须贴脚本的真实运行输出**
5. `## 本步新名词` —— **本步新引入的术语**，一条一句短定义
6. `## 自测` —— 用来检验是不是真的懂了；开头注明"先自己答一遍再看详解"
7. `## 自测详解` —— **每一道题都给出答案**，并说清答案背后的道理，不能只给结论

第 7 节不许省略：只有题目没有答案，自测就退化成摆设。第 4 节里的运行输出也不能省——**没有真实输出的讲解等于没验证过**。`notes/00-总览.md` 与 `notes/glossary.md` 是地图与索引，不适用这套结构。

补充讲解用 `NNb-标题.md` 命名（如 `01b-梯度.md`），适用于某一节没讲透、但又不值得单独占一个步骤的主题，按同样的结构写（它不是某一步，所以第 5 节改称「本文提到的名词」）。

术语的**定义写在讲解正文里**（就地在第一次被用到的上下文），`notes/glossary.md` 只做累计索引与一句话提醒，避免同一个定义维护两处。

跨越全流程的名词（如 `vocab_size`、`d_model`）放在 [notes/glossary.md](./notes/glossary.md) 里统一说明，避免每篇重复。

**术语登记规则（重要）**：一个术语往往**提前出现**——不是在正式讲解它的那一步，而是被当作例子顺口提到（"超参数，比如学习率"）。规则是：

- **后续还会反复使用的**术语一旦出现，就**必须**在 `notes/glossary.md` 留下记录，不允许"还没学到所以先不登记"。（一次性的局部术语——比如某个具体报错里出现的名字——就地一句话解释即可，不必登记。）
- 还没有正式讲解的，登记进「见过了，但还没讲到」一节，写明它将在哪一步展开。
- 讲完那一步后，条目移到主表，并从「见过了」一节删除。

这条规则的存在理由：一个词在文档里飘了二十几次才被解释，读者会以为是自己漏读了。

**前向标记规则**：正文里遇到属于后续步骤的概念，就地标注 `（→ 第 N 步）`，并且**不展开**——只说清它大概是什么、解决什么问题。概念的正式讲解只出现在它所属的那一步。

理由：提前展开会让当前这篇文档失焦，也会让后面那一步变成重复。读者此刻需要的是"知道有这么个东西、它排在哪里"，不是"现在就学会它"。

**就地可懂规则**：标记之外，**不许直接使用一个本文和前面文档都没给过定义的词**。若该概念的正式讲解在后面，就在它**第一次出现的地方**补一句"够用就行"的最小定义，再挂上标记。

反例：在一篇讲梯度的文档里直接写"让损失变小"，而"损失"从头到尾没被定义过——读者只会卡在那里，不会觉得"反正后面会讲"。

## 环境与脚本

- Python `3.11`，虚拟环境固定在 `llm-lab/.venv`（不入库）。
- 首次安装：

  ```powershell
  py -3.11 -m venv .venv
  .venv\Scripts\python -m pip install -r requirements.txt
  ```

- 运行任何脚本一律使用虚拟环境里的解释器：

  ```powershell
  .venv\Scripts\python scripts\step01_check_env.py
  ```

- 临时的 `python -c "..."` 不会加载 `_bootstrap`，中文输出会变成乱码；这类一次性命令要加 `-X utf8`（或先设 `PYTHONUTF8=1`）。脚本内已经自动处理，不用管。

- 本目录**没有** `package.json`，不实现根 `AGENTS.md` 里 `dev` / `build` / `lint` / `typecheck` / `clean` 的脚本契约——那是 `apps/*` 的约定。

## 命名

- 目录与文件名：小写 + 连字符或下划线；步骤入口带 `stepNN_` 前缀。
- **代码标识符用英文，注释与 docstring 用中文。** 本目录是学习用途，读代码时少一层翻译更省事。
  这条**偏离仓库根规则**（根 `AGENTS.md` 要求用英文），是本目录的明确例外。若将来把这里的代码挪出本目录复用，需要先把注释改回英文。
- **程序输出（`print` 的内容）不在上述约定范围内**，按各处可读性自行决定，不追求全目录统一。

## 格式

- UTF-8 + LF，与仓库根 `.gitattributes` 一致。
- Python 代码不在 Biome 的检查范围内；靠根 `.gitignore` 排除 `.venv/`、`__pycache__/`、`checkpoints/`，避免 `pnpm check` 去扫描第三方包。

## 每一步完成后必须做的事

1. 更新 `ROADMAP.md` 中对应步骤的状态。
2. 在 `PROGRESS.md` **末尾**追加一条记录，并写清「下次从这里继续」。
   追加时不要拿正文里的句子当锚点：那些句子在多个条目里重复出现，会让新条目插到中间去，打乱时间顺序。
3. 在 `notes/` 补上这一步的讲解，各节齐全：**`## 本步新名词` 与 `## 自测详解` 都不许省**；新术语同步进 `notes/glossary.md`。
4. 在仓库根执行 `pnpm check`，确认 Biome 仍然通过。
