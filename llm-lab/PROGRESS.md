## 2026-09-30 · 第 2 步：字符级分词（已完成）

**做了什么**

下载 tiny shakespeare 语料（1,115,394 字符），实现字符级分词器并完成双向往返验证，把词表存成 `data/processed/vocab.json` 供后面每一步复用。

## 2026-09-30 · 补两道题的深挖

**做了什么**

针对第 1 步的两处疑问做了专门的实验与补充：CUDA Toolkit 与驱动版本的关系，以及 `x.grad` 到底是什么。

新增 `scripts/step01_grad_demo.py`，用六步实测把梯度的行为摊开：backward 之前是 `None`、算出来是 `2x`、同一张图不能二次 backward、梯度是**累加**的、清零后才回到 `2x`、中间张量不保留梯度。

实测过程中自己先踩了一个坑：原计划直接演示"梯度累加"，结果第二次 `backward()` 直接抛 `RuntimeError: Trying to backward through the graph a second time`——因为反向传播会把计算图消耗掉。正确做法是**重新做一次前向再 backward**。这个意外比原计划更有教学价值，两条都写进了详解。

关于驱动，拿到了本机的确切数据：`nvidia-smi` 报告 `CUDA UMD Version: 13.4`，即驱动最高支持 CUDA 13.4；PyTorch 带的是 12.8 runtime，12.8 ≤ 13.4。另外注意到新版 `nvidia-smi` 已把旧的 `CUDA Version` 行改名为 `CUDA UMD Version`——这也解释了为什么按旧名字去搜会搜不到。

**代码变化**

- 新增 `scripts/step01_grad_demo.py`。
- `notes/01-环境.md`：Q1 补「Toolkit 和驱动版本之间是什么关系」，Q4 补「`x.grad` 到底是什么」。
- `AGENTS.md`：补充临时 `python -c` 需要 `-X utf8` 否则中文乱码。
- `README.md`：把新脚本加进运行清单。

**现在能回答的问题**

- 驱动是唯一硬约束：它决定机器支持的 CUDA 上限，runtime 必须 ≤ 这个上限，而 Toolkit 只影响编译、不影响能否运行。
- 驱动比 Toolkit 新永远安全，反过来会报 `CUDA driver version is insufficient for CUDA runtime version`——错误发生在运行时。
- 驱动版本号和 CUDA 版本号是两套独立编号，不能直接比大小。
- `x.grad` 是 `∂y/∂x`，与 `x` 同形状；它的含义是敏感度，而它的三个行为特性（None 起始、累加、图被消耗）直接决定了训练循环怎么写。

**还答不上来的问题**

- 为什么 PyTorch 要把梯度设计成累加而不是覆盖（只知道这是设计选择，理由留到第 4 步写了训练循环之后再回头看）。

**做了什么**

讲解的主线是三跳：一个数进一个数出（斜率）→ 多个数进一个数出（梯度）→ 为什么"减去梯度"能让损失变小。最后回答数学门槛。

实测做了三组对照，第一组最有说服力：手算的 `2(w-3)` 和 autograd 给出的梯度**完全一致**，说明 autograd 没有魔法，做的就是链式法则。第二组用三种学习率展示步长的影响——0.1 稳步但慢，0.5 一步到位（这个抛物线的最优步长恰好是 0.5），1.1 直接发散，20 步后损失从 9 涨到 13200。第三组用两个参数，展示梯度就是"两个斜率打包"，形状与参数完全对应；这段循环的形状和第 4 步要写的训练循环已经一模一样。

关于数学门槛，结论是：**需要，但不能先学完再开始。** 全程真正用到的只有六个工具（斜率、偏导数、矩阵乘法、softmax、对数、链式法则），且都在用到时才补。不需要熟练求导技巧、线代证明、概率论公理化，也不需要任何证明能力。唯一例外是梯度本身——它现在就得懂，因为后面每一步都在用。

## 2026-09-30 · 第 3 步：bigram（统计版）（已完成）

**做了什么**

用纯计数做出第一个语言模型，并就此把「语言模型是什么」「交叉熵」「困惑度」「采样」四件事讲清楚。实现分两处：`src/minigpt/bigram.py`（`BigramCounts` 类）与 `scripts/step03_bigram_counts.py`（入口脚本）。

这一步刻意不用任何神经网络：没有梯度、没有参数、没有学习率。目的是把"语言模型是一个概率分布"和"怎么训练它"彻底分开——如果连数数都能算出一个损失，就说明损失与神经网络无关。

**实测结果**

- 计数表 65×65 = 4,225 格，只填了 1,380 格（33%）——**三分之二的组合是空的**，这直接预告了后面的灾难。
- 空格后面最常接 `t`（0.141），因为英语里 the / to / that 都以"空格 + t"开头。没人告诉它，是计数里自己浮出来的。
- 训练集交叉熵 2.452 nats，困惑度 11.6；瞎猜的基线是 65。
- **贪心采样写出了 200 个连续换行符**——因为 `\n → \n` 是那一行的最大值，掉进去就出不来。这是"贪心会陷入死循环"的最小例子，而且失败得极其安静，不报错不警告。
- **未平滑的验证集交叉熵 = inf**。原因是有训练时没见过的组合，概率为 0，而 `-log 0` 是无穷大。加 1 平滑后降到 2.482（困惑度 12.0），代价仅仅是训练集从 2.452 涨到 2.455。

**代码变化**

- 新增 `src/minigpt/bigram.py`、`scripts/step03_bigram_counts.py`、`notes/03-bigram-统计版.md`。
- `notes/glossary.md`：`交叉熵`、`困惑度` 从「见过了」移入主表（清了 2 条欠债）；新增 `大语言模型`、`语言模型`、`概率分布`、`bigram`、`nats`、`平滑`、`贪心解码` 七条；`验证集` 进「见过了」（第 8 步展开）。
- `ROADMAP.md`、`README.md` 状态更新。

顺带发现 glossary 一直缺 `大语言模型（LLM）`——这个词从第 0 步第一行就在用，却从未登记。

**现在能回答的问题**

- 语言模型的输出是**概率分布**而不是"下一个字"，因为只有分布才能量化"模型有多犹豫"。
- 为什么用 `-log p` 而不是 `1 - p`：后者封顶在 1，分不清"很差"和"几乎没给机会"，而 `-log p` 恰好等于惊讶程度，且 p=0 时给出 inf。
- 困惑度的读法：平均在多少个候选之间犹豫；它不依赖词表大小，所以能跨分词器比较。
- 为什么"没见过的组合"会导致无穷大的损失，平滑如何用极小的代价换回对未知的容忍。

**还答不上来的问题**

- 平滑的强度该取多少（现在是拍脑袋加的 1），以及有没有比"给每个格子加同一个数"更聪明的做法——留给后面遇到时再说。

## 2026-09-30 · 文档约定演化（合并条目）

> 这一条**合并了此前 7 条单纯关于"文档该怎么写"的记录**（名词解释成为固定结构、给自测题补上详解、修掉术语登记的漏洞、重写第 1 步文档、01b 收缩范围、review 第 2 步文档、Python 注释改用中文），它们占了 200 多行，把真正的学习记录淹没了。规则本身已经沉淀进 `AGENTS.md`，这里只留结论与教训。其中最后一条发生在第 3 步之后，为集中记录放在这里。

**做了什么**

来回改了七轮"怎么把讲解写得让人读得下去"。值得注意的是：**其中五轮是同一个毛病换了个地方复发**——上一轮定的规则只覆盖了当时遇到的那种情况。

沉淀出四条规则，都写进了 `AGENTS.md`：

1. **术语登记**——一个词常常提前出现（被当例子顺口提到，比如"超参数，比如学习率"），所以"出现即登记"；还没正式讲的进 glossary 的「见过了，但还没讲到」，写明何时展开。
2. **前向标记**——属于后续步骤的概念只标 `（→ 第 N 步）`，不展开。

4. **每篇必须贴真实运行输出**，自测必须配详解。

## 2026-09-30 · 第 4 步：bigram（梯度版）（已完成）

**做了什么**

把第 3 步那张 65×65 的计数表，换成一张同样 65×65 的可训练权重表，用反向传播学出来。

设计上刻意保持其余环节一字不动——同样的数据切分、同样的交叉熵、同样的采样方式——这样两版可以逐项对账。新增两个模块：`src/minigpt/bigram_model.py`（模型）与 `src/minigpt/training.py`（采样批次、算损失、评估、训练循环）。

**实测结果**

```
训练前         : 交叉熵 4.5306   （均匀瞎猜的理论值是 ln(65) = 4.1744）
训练 2000 步后 : 训练集 2.458   验证集 2.490

和第 3 步对账:
  数出来的（加 1 平滑）  验证集 2.482
  学出来的              验证集 2.490      → 相差 0.008
  逐行比较最大概率的选择：93.8% 的行一致（61/65 行）
```

四个值得记的观察：

1. **训练前的 4.53 对应第 3 步的"瞎猜困惑度 65"。** `exp(ln 65) = 65`——困惑度与交叉熵在这一刻对上了。实际值比理论基线还差，因为随机初始化的表参差不齐，比均匀分布更糟。
2. **两版数值几乎重合**（2.482 vs 2.490）。梯度下降没学到新东西，学到的是同一张表，只是换了条路。
3. **验证集不再是 `inf`。** 第 3 步要靠人为加平滑才能绕过的坑，这里天然没有——softmax 的指数函数永远不为 0。同一个"没见过的组合"，计数版判死刑，梯度版只给一个很小的概率。
4. **贪心复现了同样的死循环**（一路输出换行符）。这反过来印证两版确实等价——连缺陷都一模一样。
