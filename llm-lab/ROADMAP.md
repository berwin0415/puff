# 路线图

目标：**从零手写一个最简易的 LLM**，并把每个零件讲清楚。全程不使用 `transformers` 等现成实现。

最终形态：字符级 mini-GPT，参数量约 1～10M，在 tiny shakespeare 上训练到能生成形似莎士比亚的文本。

组件全貌与数据流见 [notes/00-总览.md](./notes/00-总览.md)——每一步对应图上的哪个零件，那里有张表。

状态取值：`未开始` / `进行中` / `已完成`。

## 每一步的验收标准

验收标准不是「代码写完了」，而是**你能用自己的话讲明白**。

### 第 1 步：环境

- 环境能跑通：`step01_check_env.py` 打印出 GPU 型号、架构、显存，且 CPU 与 GPU 的矩阵乘法结果一致。
- 能解释：为什么 5070 Ti 必须装 cu128 及以上的 PyTorch。
- 能解释：torch / CUDA runtime / 显卡驱动三者是什么关系。

### 第 2 步：字符级分词

- `encode(decode(ids)) == ids` 往返无损。
- 能解释：为什么模型见到的不是文字而是整数，以及词表大小意味着什么。

### 第 3 步：bigram（统计版）

- 训练出计数表，能采样出文本（此时质量很差是正常的）。
- 能解释：语言模型到底是什么；交叉熵在衡量什么；`-log(p)` 的直觉含义。
- 理解对数似然与困惑度跟生成质量的关系。

### 第 4 步：bigram（梯度版）

- 用 `nn.Embedding` + 交叉熵复现第 3 步的效果。
- 能解释：为什么必须「可微」——梯度是把模型往上叠的前提。
- 能说清一次完整的训练循环：前向 → 损失 → 反向 → 更新。

### 第 5 步：加隐藏层

- 在 bigram 上加一层 MLP，loss 明显低于第 4 步。
- 能解释：参数量、过拟合、学习率分别在这段训练里起什么作用。

### 第 6 步：单头自注意力

- 先实现一个「只能看前面若干位置的加权平均」作为对照，再替换成 Q/K/V + 因果掩码。
- 能解释：Q、K、V 各自在算什么；为什么要除以 √d_k；因果掩码为什么必须有。
- 能手算一个 3 个 token 的例子并和代码输出对齐。

### 第 7 步：完整 Transformer block

- 多头注意力 + 残差 + LayerNorm + 前馈网络 + 位置编码，堆成一个 mini-GPT。
- 能解释：每个零件如果被拿掉，会发生什么。
- 能解释：为什么需要位置编码，注意力本身缺了什么。

### 第 8 步：训练工程化

- 模型训练到 loss 收敛，采样出像样的文本。
- 能解释：学习率、warmup、梯度裁剪各自解决什么问题。
- 能解释：temperature 与 top-k 如何改变采样结果。
