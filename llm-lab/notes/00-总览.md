# 总览：一个最简易的 LLM 由什么组成

先看地图，再看路。这份文档给出全貌，每一步开工前回来看一眼，就知道自己站在哪儿。

## 一句话

一个 LLM = **一个"预测下一个 token"的函数** + **让它变好的机制** + **喂养它的数据管道**。

## 只有四样东西不可省略

把这句话拆到底，真正"没有就跑不起来"的组件只有四个：

| # | 组件 | 解决的问题 | 输入 → 输出 |
| --- | --- | --- | --- |
| 1 | 分词器 | 模型只吃数字，文本是字符 | 文本 → id 序列 |
| 2 | 模型 | 需要有个东西来"预测" | id 序列 → 每个位置的词表概率 |
| 3 | 损失函数 | 得能量化"预测得多差" | 概率 + 正确答案 → 一个数 |
| 4 | 梯度下降 | 得能自动把参数调好 | 损失 → 参数更新 |

**其余所有东西都不是"能跑"的必要条件，而是"跑得好、稳、快"的条件。** 位置编码、多头注意力、残差连接、层归一化、学习率调度、梯度裁剪——这些全部属于第二类。它们很重要，但它们是在你已经有一个能跑的模型之后，用来解决具体问题的。

这条区分能救你很多时间：当你看不懂某个组件时，先问它是"让它能跑"还是"让它跑得更好"。前者必须立刻搞懂，后者可以先当作一个黑盒用着。

## 数据流全图

```
【准备阶段 · 只做一次】

  原始文本 ──分词器──> id 序列 ──切成等长窗口──> (x, y) 样本对 ──分批──> 批次
                                                    │
                                    x = 一段文本, y = x 右移一位

【训练循环 · 重复几万次】

        批次 ──> ┌───────────────── 模型前向 ─────────────────┐
                 │  embedding：id → 向量                        │
                 │  位置信息：让模型知道谁在前谁在后            │
                 │        ↓                                     │
                 │  ┌──── Transformer block × N 层 ────┐        │
                 │  │  注意力：token 之间互相看       │        │
                 │  │  前馈网络：每个位置各自加工     │        │
                 │  │  （两者都套残差 + 归一化）      │        │
                 │  └──────────────────────────────────┘        │
                 │        ↓                                     │
                 │  lm_head：隐藏向量 → 词表大小的分数          │
                 └───────────────────┬──────────────────────────┘
                                     ▼
                        交叉熵损失：预测的 next token 错得多离谱
                                     │
                                     ▼
                          反向传播：每个参数的梯度
                                     │
                                     ▼
                          优化器：按梯度调整参数
                                     │
                    ┌────────────────┘
                    ▼  回到"模型前向"，重复

【生成 · 训练完之后】

  给一个开头 ──> 模型 ──> 取最后位置的词表概率 ──> 采样出一个 token
       ▲                                                      │
       └──────────────── 拼回输入，再来一遍 ──────────────────┘
```

## 关键认知：训练循环只有四步

上面那张图看着复杂，但循环体只有四步，而且从第 4 步到第 8 步**一步都不会变**：

```
前向 → 算损失 → 反向 → 更新参数
```

后面所有的复杂度都堆在**"前向"里面**——也就是模型结构。第 5 步给它加一层隐藏层，第 6 步把"取平均"换成注意力，第 7 步把注意力变成多头、再配上残差和归一化，但外面的训练循环纹丝不动。

这是整条学习线里最让人安心的事实：**你不需要一次理解全部，每步只动前向里的一小块。**

## 三个最容易被忽视的组件

这三个不在"最简四件套"里，但缺了它们，模型会以一种**看起来很诡异但不会报错**的方式失败：

**位置编码。** 注意力本身是置换不变的：把输入的顺序打乱，输出只是跟着打乱，模型自己察觉不到。没有位置信息，"猫追狗"和"狗追猫"对它是一样的。这个故障不会让训练报错，只会让模型永远学不好语序。

**残差连接和归一化。** 没有残差，梯度穿不过十几层，深层网络根本训不起来；没有归一化，训练会不稳定。它们是"让深度成为可能"的两个零件，第 7 步会具体验证。

**采样策略。** 训练完之后你手上只有一个函数：给定前文，输出下一个 token 的概率分布。**它不会自己写文章。** 那套"取一个字、拼回去、再来一次"的循环必须你自己写。第 3 步就会第一次用到它，虽然那时候模型还很笨。

## 明确不用做的事

"最简易"这三个字值得认真对待。下面这些经常被误以为是必备项，实际上**在整条学习线里都不会出现**：

- 分布式训练、多卡并行、混合精度
- 混合专家（MoE）、多模态、长上下文技巧
- RLHF、DPO、指令微调
- KV cache、量化、推理引擎
- 自己训练的 BPE 分词器（列在最后一步之后，可选）

它们都是真实且重要的工程问题，但它们解决的是"把这个模型做得更大更快更听话"，而不是"理解一个模型是怎么运转的"。你现在不需要它们。

## 怎么用这份文档

每次开始某一步之前，回到这里先定位：这一步动的是图上哪个零件？它属于"不可省略的四件套"还是"让它更好的零件"？它改变训练循环，还是只改前向里面的一小块？

能在图上指出位置，你就不会迷路。

## 本文提到的名词

这篇是总览，所以它把后面所有步骤的术语先扫了一遍——这里只给一句话的第一印象，真正讲透在各自的步骤里。全部术语的累计索引见 [glossary.md](./glossary.md)。

- **模型（model）**：一个函数，输入一些数字、输出一些数字。LLM 就是"输入一串 token id、输出下一个 token 的概率分布"的函数。
- **参数（parameter / weight）**：函数里那些**会被训练改变**的数字。所谓"训练"，就是调整这些数字。
- **前向传播（forward pass）**：把输入喂进模型、一路算到输出的过程。后面每一步新增的复杂度几乎都在这里。
- **损失函数（loss function）**：用一个数衡量"预测得多差"。它是训练唯一的指挥棒——模型没有别的目标。
- **梯度（gradient）** 与**反向传播（backpropagation）**：梯度告诉我们每个参数该往哪边调；反向传播是自动算出全部梯度的方法。
- **训练循环（training loop）**：前向 → 算损失 → 反向 → 更新参数，四步反复。从第 4 步到第 8 步它都不会变。
- **推理（inference）**：训练完之后用模型算结果，参数冻结不动。
- **自回归（autoregressive）**：把刚生成的 token 接回输入，一次生成一个——这是所有文本生成的工作方式。
- **token**：模型实际处理的最小单位。注意它是**整数**，不是文字。
- **嵌入（embedding）**：把一个 token id 查表换成一串向量，模型从此才开始处理真正的数字。
- **输出头（lm_head）**：最后一层，把隐藏向量变成"每个 token 各得多少分"。
- **未归一化分数（logits）**：softmax 之前的原始分数。它可以是任意实数，还不是概率。
- **采样（sampling）**：从概率分布里按概率随机挑，而不是永远挑分数最高的那个。
- **超参数（hyperparameter）**：由你设定、训练不会自动改变的量，比如学习率、层数、`d_model`。
