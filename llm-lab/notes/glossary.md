## 跨步骤的基础概念

有些名词不属于任何单独一步，但会一直出现，统一在这里说清楚。

### `vocab_size` 与 `d_model`

这两个是最容易被混在一起的一对，因为它们都带个"大小"。它们其实是**正交**的：

- **`vocab_size`（词表大小）**：模型认识多少种 token。本项目是 65。
- **`d_model`（模型维度，也叫 hidden size、隐藏维度）**：每个 token 用多少个数字来描述。本项目第 7 步会定在 128～384 之间；作为对照，GPT-2 small 是 768，GPT-3 是 12288。

一句话区分：`vocab_size` 回答"**有多少种东西**"，`d_model` 回答"**每一种东西用多长的向量表示**"。

一个 token 在模型里的旅程，注意每一步的**形状**：

```
文本 "First"     →  id 序列       (T,)              一串整数
                 →  embedding     (T, d_model)      每个整数换成一串向量
                 →  N 层 block    (T, d_model)      形状全程不变
                 →  lm_head       (T, vocab_size)   每个位置给出所有 token 的分数
                 →  softmax       (T, vocab_size)   变成概率
```

（`T` 是序列长度；加上批次就是 `(B, T, d_model)`。）

两条要记住的：

1. **`d_model` 是贯穿整个模型的高速公路宽度。** 从 embedding 进去，经过所有注意力和前馈层，最后一维始终是 `d_model`，直到 `lm_head` 才投影成 `vocab_size`。词表大小只在头尾两端出现，中间全是 `d_model`。
2. **"维度"这个词是重载的。** `(T, d_model)` 里 `T` 是序列维、`d_model` 是特征维；三维时还有批次维。以后看到"维度"，先确认说的是哪一个。

量级感受：本项目 `65 × 128 = 8,320`，整个 embedding 表就这么大。而 GPT-2 small 的 embedding 是 `50,257 × 768 ≈ 3,860 万`参数——比我们整个模型大几百倍。

### 梯度

**梯度 = "每个参数各有一个斜率"的打包**，形状与参数完全相同。它的每个元素回答同一个问题："只把这个参数调大一点点，损失会怎么变？"

更新参数时写成 `w ← w - 学习率 × 梯度`，那个减号就是"往损失变小的方向走"。

这是整条学习线上唯一一个"不理解就寸步难行"的数学概念。完整解释（含手算与 autograd 的一致性验证、三种学习率的行为对比、以及到底需要多少数学基础）见 [01b-梯度.md](./01b-梯度.md)。
