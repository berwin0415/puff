# 第 4 步：bigram（梯度版）

## 这一步解决什么问题

第 3 步的数数版有个天花板：**它只能处理"数得出来"的东西。**

一旦模型不再是一张二维表——比如中间插进一层隐藏层、注意力要在几万个 token 之间算关系——那些参数就没法数了。它们必须能被**学**出来。

所以这一步换一种方式填表：不数，而是**顺着梯度一点点调**。

模型形状刻意保持不变（还是 65×65），数据、损失、采样三个环节一个字不改，唯一换掉的是"表里的数字从哪来"。这样就能直接和第 3 步对账——这也是验证"梯度下降真的在工作"最干脆的办法。

## 怎么读这篇

**标记约定**：出现 `（→ 第 N 步）` 表示那个概念在后面那一步才正式讲解，这里只要知道名字就行。

**本文范围**：只讲"怎么把表换成可训练的"和"训练循环长什么样"。模型结构本身从第 5 步才开始变——所以 `d_model`、隐藏向量、`lm_head` 这三样在这篇里还不存在（glossary 里它们的展开步骤也从第 4 步改成了第 5 步，原因就在这里：本文的模型没有中间向量，token 查到的一行分数直接就是 logits）。

## 一张表，两种填法

| | 第 3 步（数数） | 第 4 步（学习） |
| --- | --- | --- |
| 表的形状 | 65 × 65 | 65 × 65 |
| 表里放什么 | 出现次数，归一化成概率 | 任意实数，softmax 之后才是概率 |
| 数字从哪来 | 数一遍语料 | 随机初始化，再按梯度一点点调 |
| 怎么改进 | 只能改平滑系数 | 梯度指哪就往哪调 |
| 验证集表现 | 未平滑时 `inf` | 2.490 |

表里的数字换了个名字叫 **logits**（第 0 步见过）：不再是"概率"，而是"分数"。分数可以是任意实数，softmax 之后才变成加起来为 1 的概率。为什么要多这一道转换？因为**概率必须落在 0 到 1 之间，而参数需要能在整个实数轴上自由移动**——梯度调整的是分数，不是概率。

## 为什么必须"可微"

数数是**不可微**的。把 `count[a][b]` 从 5 改成 6，损失会变多少？能算出来，但那个变化是离散的、阶梯状的——没有"斜率"可言，也就没有梯度。

换成一张权重表之后，每个数字都是连续可调的参数，损失对每个参数都有梯度，于是可以顺着梯度调。这叫**可微**。

**这是把模型往上叠的唯一前提。** 只要前向的每一步都可微，整条链就可微，梯度就能从损失一路传回每一个参数。第 6 步加入注意力、第 7 步堆十几层，靠的都是这一条。

## 训练循环：只有四行

`src/minigpt/training.py` 里的核心就是这四行：

```python
logits = model(x)                      # 1. 前向：算出预测
loss = cross_entropy_loss(logits, y)   # 2. 算损失：量化这次错得多离谱
optimizer.zero_grad()                  #    清掉上一轮累积的梯度
loss.backward()                        # 3. 反向：算出每个参数的梯度
optimizer.step()                       # 4. 更新：按梯度把参数挪一点
```

一步步说：

- **前向**：把一批文本喂进去，得到每个位置的 65 个分数。
- **算损失**：拿这些分数和正确答案比，用第 3 步学过的交叉熵压成一个数。
- **反向**：`backward()` 沿计算图倒着走，给每个参数算出梯度。（→ 就是第 1 步补充里那件事，现在链条长了一点）
- **更新**：`optimizer.step()` 按梯度把参数挪一点。它挪多少、怎么挪，由**优化器**决定——这里用的是 AdamW。

那行 `zero_grad()` 不是可选项。第 1 步补充里实测过：**梯度是累加的，不覆盖**。不清零，这次算出的梯度会和上次的叠加在一起，参数一步比一步迈得大，训练会自己跑飞。

**这四行从第 4 步到第 8 步都不会变。** 后面几步变复杂的只有"前向"里面的模型。

## 实测

```
设备           : cuda
tokens         : 1,115,394（训练 1,003,854 / 验证 111,540）
参数量         : 65 × 65 = 4,225（和第 3 步计数表的格子数一样）

训练前         : 交叉熵 4.5306
                 均匀瞎猜的理论值是 ln(65) = 4.1744（困惑度 65.0——和第 3 步的基线对上了）
                 比理论值还差一点：随机初始化的表并不是均匀分布，而是参差不齐的

训练（前向 → 算损失 → 反向 → 更新，共 2000 步）:
  第     0 步   loss = 4.5138
  第   500 步   loss = 2.5011
  第  1000 步   loss = 2.4681
  第  1500 步   loss = 2.4692
  第  1999 步   loss = 2.4595
```

**训练前的 4.53 值得停一下。** 理论值是 `ln(65) = 4.1744`，正好对应第 3 步的"瞎猜困惑度 65"——`exp(4.1744) = 65`。困惑度和交叉熵在这里第一次对上了：**困惑度就是 `exp(交叉熵)`，反过来交叉熵就是困惑度的对数。**

实际值 4.53 比理论值还差一点，因为随机初始化的表并不是均匀分布，而是参差不齐的——有些字符一开始就被压得特别低。

训练开始后一路降到 2.46 附近，然后基本不再下降。**这个平台期不是训练失败了，而是这个模型的能力上限**——它只有一个字符的上下文，能榨出来的信息就这么多。

## 和第 3 步对账

```
和第 3 步对账:
  数出来的（加 1 平滑）  训练集 ——       验证集 2.482
  学出来的              训练集 2.458   验证集 2.490
  未平滑的计数版验证集是 inf（概率 0 导致），学出来的这里给出 2.490 而不是 inf——因为 softmax 永远给非零概率

逐行比较最大概率的选择：93.8% 的行一致（一共 65 行）
```

三件事：

**数值几乎重合。** 第 3 步（数出来 + 平滑）验证集 2.482，第 4 步（学出来）2.490。它们本来就该一样——同一个模型，两种求法。梯度下降没有学到什么新东西，它学到的是**同一张表**，只是换了一条路。

**93.8% 的行做出了相同的选择**（61/65 行）。剩下 4 行的差别出现在那些字符出现得极少的行上——本来就不多的样本里，计数版和梯度版在"几乎平局"的位置上做了不同取舍。这不该让人意外：**两者接近但不完全相同**，平滑是人为加的偏置，而梯度版没有。

**验证集不再是 `inf`。** 这是最值得记住的一条。第 3 步要靠人为加平滑才能避免的灾难，这里天然就没有——因为 `softmax` 的输出**永远大于 0**：分数再低，指数也不会变成 0。一句"没见过的组合"在这两个版本里的下场完全不同：计数版判它死刑，梯度版只是给它一个很小的概率。

## 贪心还是死循环

```
贪心（每步取最大）：
  '\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n'
```

和第 3 步一模一样：换行符后面还是换行符，一路走到黑。

这不是巧合。**它恰恰证明学到的东西和第 3 步是同一张表**——连"换行符后面最常接换行符"这个毛病都原样复现了。换了个求法，得到的还是同一个模型，包括它的缺陷。

按概率采样得到的自然是另一种结果：

```
'\nAu ay IIn eall Clloimeabs bind.\nWI ithisur ig wen.\nn omef br want\nNurninoure ...'
```

质量与第 3 步的采样相当——所以真正的进步要靠第 5 步往后，而不是靠换一个求法。

**这一步换来的不是更好的结果，而是更好的"可以继续往上叠"的地基。**

## 脚本在验证什么

`scripts/step04_bigram_gradient.py`：

1. **同一份数据、同样的切分**（90% / 10%），让两版的损失可以直接比。
2. **训练前先量一次基线**，确认随机初始化的模型确实"什么都不会"。
3. **和第 3 步逐行对账**，而不是只看损失数值——损失接近可能只是巧合，表里的选择一致才说明学对了。
4. **两版的贪心输出都跑**，用同一个失败模式反过来印证两者等价。

## 本步新名词

累计索引见 [glossary.md](./glossary.md)。

- **可微（differentiable）**：函数的每个输入都有梯度，于是能顺着梯度改进它。数数不可微，权重表可微——这是能不能用梯度训练的分水岭。
- **优化器（optimizer）**：决定"每个参数具体挪多少、往哪挪"的策略。梯度只给方向，优化器负责把它变成实际的一步。（→ 第 8 步讲怎么调它）
- **AdamW**：本步使用的优化器。它给每个参数维护自己的一份步长，比"所有参数统一步长"更稳。（→ 第 8 步展开）
- **权重表（weight table）**：`nn.Embedding` 内部就是一个 `(vocab_size, vocab_size)` 的矩阵，每一行对应当前字符、每一列对应下一个字符的分数。
- **参数（parameter）**：模型里会被训练改变的数字。本步有 4,225 个，全在那张表里。
- **叶子张量（leaf tensor）**：直接创建、梯度会被保留的张量。`model.parameters()` 拿到的全是叶子张量，中间算出来的不是——第 1 步补充里埋的那个区分，到这里开始有实际用处。

## 自测

1. 为什么第 3 步那种"数数"的做法，往后就走不通了？
2. 训练循环的四步分别是什么？`zero_grad()` 能省掉吗，为什么？
3. 训练前的损失是 4.53，而 `ln(65) = 4.17`。这两个数各自说明什么？
4. 为什么学出来的模型在验证集上不会出现 `inf`，而第 3 步的计数版会？
5. 贪心采样两版都输出一堆换行符，这说明了什么？

## 自测详解

### 1. 为什么数数往后走不通？

因为数数**只能填"输入和输出一一对应"的表**。这里是"当前字符 → 下一个字符"，65×65 个格子，每个格子数一遍就行。

但模型一旦变复杂就失效了：中间插入隐藏层后，参数不再是"某个字符到某个字符的计数"，而是"某个维度的数字到另一个维度的数字的变换"——没有东西可数。注意力更是如此，它要在任意两个位置之间算关系，参数量跟语料里的出现次数根本对不上。

所以必须换成**可微**的表示：参数是连续可调的，损失对它们有梯度，于是不管结构多复杂，都能用同一套办法（前向 → 算损失 → 反向 → 更新）把参数调好。

### 2. 四步是什么？`zero_grad()` 能省吗？

**前向 → 算损失 → 反向 → 更新。**

- 前向：把输入喂进模型，得到 65 个分数
- 算损失：和正确答案比，用交叉熵压成一个数
- 反向：`backward()` 沿计算图倒着走，算出每个参数的梯度
- 更新：`optimizer.step()` 按梯度把参数挪一点

`zero_grad()` **不能省**。梯度是**累加**的，不是覆盖的——这是第 1 步补充里实测过的结论：连着两次 `backward()`，梯度会变成两次之和。

省掉清零的后果很隐蔽：第一次参数正常挪，第二次挪了两倍的量，第三次三倍……梯度会指数级累积，参数很快跑到荒谬的位置，训练自己跑飞。而且它**不会报错**，你只会看到损失莫名其妙地爆炸。

### 3. 训练前的 4.53 和 `ln(65) = 4.17` 各说明什么？

`ln(65) = 4.17` 是**理论基线**：如果模型对 65 个字符一视同仁地猜，每个正确答案的概率都是 1/65，损失就是 `-ln(1/65) = ln(65) = 4.1744`。这正好是第 3 步那个"瞎猜的困惑度 65"的对数——**困惑度 `exp(交叉熵)` 在 65 上就是它**，两个概念在这里第一次对上。

实际的 4.53 比基线还高一点，说明**随机初始化的模型连瞎猜都不如**。因为它的表是随机数，softmax 之后分布参差不齐：有的字符一上来就被压到很低的概率，撞上它损失就很大。平均下来比均匀分布还差，这很正常。

两个数一起看，意义是：训练开始前模型确实什么都不会（对照基线能看到这一点），训练之后 4.53 降到 2.46，这个落差就是**梯度下降真正带来的东西**。

### 4. 为什么学出来的不会 `inf`？

因为模型输出的是 **logits，要经过 softmax 才变成概率**。softmax 是 `exp(x) / 求和`，而指数函数**永远不会等于 0**——分数压到再低，`exp(-100)` 也是个很小的正数。

所以"训练时没见过的组合"在梯度版里只会拿到一个极小的概率，`-log` 之后是个很大的数，但**不是无穷大**。而在第 3 步的计数版里，这一格计数是 0，归一化后概率就是 0，`-log 0` 直接是无穷大——一个位置就能把整段文本的平均损失拉到 `inf`。

这是**表示方式本身带来的差别**：计数版把"没见过的"和"不可能的"当成同一件事（都记作 0）；梯度版从数学上就不允许出现 0 概率。

顺带一个值得记住的观察：第 3 步要人为加平滑才能绕过的坑，第 4 步天然没有。**有时候问题的消失不是因为被解决了，而是因为换了个表达方式。**

### 5. 贪心两版都输出换行符，说明什么？

说明**两者学到的是同一张表**。

第 3 步是数出来的表，第 4 步是学出来的表，两者的验证集损失只差 0.008，93.8% 的行做出完全相同的选择。贪心路径依赖"每行里最大的那一格"，两版在那里给出了相同的答案，于是走出一模一样的死循环。

这件事有两层意义。一层是**验证**：梯度下降确实学会了数数所学的东西，没学错。另一层是**提醒**：第 4 步换的是求法，不是模型能力——能力上限由"只看一个字符"这个结构决定，换求法改变不了它。

真正要往上走，得改结构。这是第 5 步的事。
