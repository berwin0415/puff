# 第 3 步：bigram（统计版）

## 这一步解决什么问题

前两步把文本变成了整数。现在要造出这条学习线上的第一个**语言模型**——而且这次连神经网络都不用，只要数数。

用数数不是因为它好用（它很差），而是因为它**把"语言模型是什么"和"怎么训练它"这两件事分开了**。数数没有梯度、没有参数、没有学习率——如果连它都能算出一个"损失"，你就知道损失跟神经网络无关，它只是在衡量"模型对正确答案有多意外"。

它还有一个作用：给后面每一步立一个必须超越的基准。**困惑度 11.6。** 第 4 步之后你会回来跟它比。

这篇同时清掉 glossary 里挂了两轮的两个名词：**交叉熵**和**困惑度**。

## 怎么读这篇

**标记约定**：出现 `（→ 第 N 步）` 表示那个概念在后面那一步才正式讲解，这里只要知道名字就行。

**本文范围**：只讲"怎么用计数造一个语言模型"，以及由此引出的概率、损失、采样三件事。神经网络的任何内容都不在这里。

## 语言模型到底是什么

一句话：**给定前文，输出下一个 token 的概率分布。**

关键在后半句：不是"输出下一个 token"，而是输出**一串概率**。以输入 `Th` 为例，它不是回答"下一个是 `e`"，而是给出 65 个数字，其中 `e` 的概率最高，`a` 低一些，`z` 几乎为零。

为什么要"分布"而不是"答案"？因为没有分布就没法量化"模型有多不确定"，也就没有损失可言。这是后面全部内容的起点。

模型能看到多长的前文，由**上下文长度**决定。这一步我们只让它看 **1 个字符**，这种模型叫 **bigram**（二元组）——一次只看相邻的两个单位。

## 数一数就是一个语言模型

整个过程只有三步：

1. **数**：遍历全文，统计每一对相邻字符 `(a, b)` 出现了多少次
2. **归一化**：对每个字符 `a`，把它的那一行计数除以行和，得到 `P(b | a)`
3. **查表**：要预测时，看当前字符落在哪一行，取出那一行

跑出来是这样：

```
tokens         : 1,115,394（训练 1,003,854 / 验证 111,540）
vocab size     : 65
计数表         : 65×65 = 4,225 个格子，填了 1,380 个（33%）
空格后面最常接 : 't' 0.141, 'a' 0.079, 's' 0.072
```

看第三行：**空格后面最常接的是 `t`，概率 0.141。** 因为它学到了英语里 `the`、`to`、`that` 都以"空格 + t"开头。这不是谁告诉它的，是从计数里自己浮出来的。

但要记住最后一行的数字：**4,225 个格子里有 2,845 个是空的（67%）。** 那些是训练时从没出现过的组合。这个数字待会儿会咬人。

（另外注意：我们把最后 10% 的文本留出来不参与训练，叫**验证集**，专门用来检查它是不是真的学到了规律。→ 第 8 步正式讨论）

## 交叉熵：把"意外程度"变成一个数

现在有了概率分布，怎么评价它好不好？

思路很直接：拿真实文本喂给它，看它给**正确答案**打了多少概率。打得多就是好模型。

但概率不能直接当损失用——我们希望"越好越小"，而概率是"越好越大"。于是取负对数：

```
单个位置的损失 = -log P(正确答案)
```

先看它长什么样：

```
模型给正确答案的概率 p = 1.0   -> 损失 0.00
模型给正确答案的概率 p = 0.5   -> 损失 0.69
模型给正确答案的概率 p = 0.1   -> 损失 2.30
模型给正确答案的概率 p = 0.01  -> 损失 4.61
```

三件事要读出来：

- **完全确定时零惩罚。** `p = 1` 说明模型早就知道答案，损失 0。
- **惩罚按对数增长，不是线性。** 概率从 1 掉到 0.5，损失才 0.69；再掉到 0.1，损失翻到 2.30；掉到 0.01，已经 4.61。**越接近"完全没料到"，惩罚上升得越陡。**
- **`p = 0` 时是无穷大。** 你根本没给正确答案留位置，惩罚就是无限的——马上就会看到这个 `inf`。

为什么偏偏用对数？因为 `-log p` 恰好等于"这件事发生时，你获得的信息量"，也就是**惊讶程度**。用日常语言记它就行：模型越意外，罚得越狠。

把整段文本**每个位置**的损失取平均，就得到**交叉熵**：

```
训练集交叉熵   : 2.452 nats
训练集困惑度   : 11.6    （瞎猜的困惑度是 65.0，即词表大小）
```

名字里的"交叉"，是指它在比较两个分布：模型预测的那个分布，和真实答案（可以看成"把全部概率给正确答案"的分布）。

补一句术语：这个量在有些地方叫**平均负对数似然**。和"交叉熵"是同一个东西，见到时不要以为是新概念。

## 困惑度：换算成人能感觉的单位

交叉熵的单位是 **nats**——因为用的是自然对数。它准确实用，但很难有感觉：2.452 是好还是坏？

于是有了**困惑度**：

```
困惑度 = exp(交叉熵)
```

它的含义可以直接读出来：**模型在每一步，平均在多少个候选之间犹豫。**

- 我们的模型：2.452 nats → 困惑度 **11.6**
- 完全瞎猜的基线：词表 65 个字符，均匀瞎猜的困惑度就是 **65**

所以"11.6"翻译过来是：**它每一步大约在 11.6 个候选中犹豫**，而瞎猜是在 65 个里面犹豫。它确实学到了东西——但离"毫不犹豫"（困惑度 1，也就是说模型每次都给正确答案概率 1）还差得很远。

困惑度还有一个好处：**它不依赖词表大小。** 两个用不同词表的模型，交叉熵没法直接比，但困惑度可以。这一点在后面换分词器时会很有用。

## 采样：模型不会自己写文章

一个必须早点接受的事实：训练完之后，你手上只有一个函数——给它前文，它吐出概率分布。**它不会自己写文章。** 那套"抽一个、拼回去、再来一次"的循环，得你自己写。

两种最朴素的抽法，结果天差地别：

```
采样（按概率抽，每次结果都不同）:
  '\nth remofed hexpselteredoca meaman youd INAlste grecofurey h fotherere hath
   thig berelisseanongilost.\ntho y we w ke RYORD:\nWidarthofr nd; my f tsoo ...'

贪心（每步都取概率最大的那个）:
  '\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n\n...'
```

**按概率抽**的结果是 `th remofed hexpselteredoca` 这种——单词大多是假的、语法是乱的，但**一眼就能看出是英语**：有空格、有大小写、有标点、有换行。它学到的是字符层面的统计规律，仅此而已。

**贪心**的结果是 200 个连续的换行符。原因简单得让人无话可说：换行符后面最常接的还是换行符（剧本里连续空行很多），于是一旦掉进去，就永远爬不出来。这是"贪心会陷入死循环"的最小例子，而且它不会报错、不会警告——只是安安静静地输出 200 个空行。

这就是为什么真实模型必须用采样，而不是每步取最大。（→ 第 8 步会讲 temperature、top-k 这些控制随机性的手段）

## 概率为零的灾难

现在把留出来的那 10% 验证集拿去做评估：

```
把没见过的组合拿去验证:
  未平滑的验证集交叉熵 = inf
  加 1 平滑后           = 2.482 nats（困惑度 12.0）
  代价：训练集从 2.452 涨到 2.455——平滑是拿训练集上的自信去换对未知的容忍
```

**交叉熵变成了 `inf`（无穷大）。**

原因就在前面那张 `-log(p)` 表里：验证集里只要**有一个组合在训练时没出现过**，模型给它分配的就是概率 0，而 `-log 0 = 无穷大`。一个无穷大足以把整段文本的平均损失拉到无穷大。

这不是小毛病，这是所有"死记硬背式"模型的通病：**它把"没见过的"和"不可能的"当成了同一件事。** 训练语料再大也穷尽不了所有可能，所以这个毛病一定会出现。

最小的修法叫**平滑**：给每个格子的计数都加一个很小的数（这里加 1，叫拉普拉斯平滑），然后再归一化。这样任何组合都分到一个极小的非零概率。

代价几乎可以忽略：训练集上只从 2.452 涨到 2.455。但验证集从无穷大变成了 2.482——**它现在能面对未知了**。

这条经验在整条学习线上反复出现：**模型在训练数据上表现好，什么都说明不了；要看它在没见过的数据上表现如何。**

## 为什么它注定很差

回头看这个模型能看到的上下文：**只有一个字符。**

所以它永远学不会：看到 `th` 之后大概率是 `e`、`q` 后面几乎一定是 `u`、句子开头的字母要大写。每一件都需要比一个字符更长的上下文。

但它有一个值得记住的优点：**它一次反向传播都不需要，就跑通了整条链路。**

```
数据 → 分词 → 模型 → 概率分布 → 损失 → 采样
```

每个环节都齐了。第 4 步要做的事情因此非常小：**把这张查表换成一张可训练的矩阵。** 数据、损失、采样这些环节原封不动。

## 脚本在验证什么

`scripts/step03_bigram_counts.py`：

1. **词表是加载的，不是重建的**——直接读第 2 步存下的 `vocab.json`。这一步顺带验证了"词表和权重绑定"这条规矩是能被执行的。

## 本步新名词

累计索引见 [glossary.md](./glossary.md)。

- **语言模型（language model）**：给定前文，输出下一个 token 的概率分布的函数。
- **bigram（二元组）**：只看相邻两个单位的模型——上下文长度只有 1。
- **概率分布**：一串非负、加起来等于 1 的数，表示每个选项的可能性。模型每一步吐出的就是这样一串数。
- **交叉熵（cross-entropy）**：平均每个位置的 `-log P(正确答案)`，衡量模型对正确答案有多意外。越小越好。也叫**平均负对数似然**。
- **nats**：交叉熵的单位，因为用的是自然对数。用自然对数就记 nats，用 2 为底就记 bits。
- **困惑度（perplexity）**：`exp(交叉熵)`。读作"模型平均在多少个候选之间犹豫"。它不依赖词表大小，所以能跨模型比较。
- **平滑（smoothing）**：给每个计数加一个小常数再归一化，避免没见过的组合得到概率 0。加 1 的那种叫**拉普拉斯平滑**。
- **贪心解码（greedy decoding）**：每步都取概率最大的 token。确定但容易陷入死循环。
- **采样（sampling）**：按概率随机抽，而不是永远取最大。这里第一次真正用到。（→ 第 8 步讲怎么控制随机性）
- **验证集（validation set）**：留出来不参与训练的那部分数据，用来检查模型在没见过的情况下的表现。（→ 第 8 步正式讨论）

## 自测

1. 语言模型的输出到底是什么？为什么不是"下一个字符"？
2. 损失为什么用 `-log p`，而不是用 `1 - p`？
3. 困惑度 11.6 是什么含义？完全瞎猜的话是多少？
4. 验证集的交叉熵为什么是 `inf`？加 1 平滑为什么能解决，代价是什么？
5. 为什么贪心采样会写出 200 个换行符？

## 自测详解

### 1. 语言模型的输出是什么？

**一串概率**，长度等于词表大小（这里是 65），加起来等于 1。

输入 `Th` 时，模型不是回答"下一个是 `e`"，而是给 65 个字符各打一个分：`e` 最高，`a` 次之，`z` 几乎为零。

为什么必须是分布？因为**没有分布就没有损失**。损失要衡量的是"模型给正确答案打了多少概率"，如果模型只输出一个答案，就没有任何东西可以量化"它有多犹豫、有没有把正确答案放在候选里"。第 4 步之后，"输出 65 个数字"这件事会变成一层具体的矩阵运算——但含义今天已经定下了。

### 2. 为什么用 `-log p`，而不是 `1 - p`？

因为 `-log p` 的惩罚曲线形状才是对的。对比一下：

| 模型给正确答案的概率 | `1 - p` | `-log p` |
| --- | --- | --- |
| 1.0 | 0 | 0 |
| 0.5 | 0.5 | 0.69 |
| 0.1 | 0.9 | 2.30 |
| 0.01 | 0.99 | 4.61 |
| 0.001 | 0.999 | 6.91 |
| 0 | 1 | **inf** |

`1 - p` 有个明显的毛病：它**封顶在 1**。模型给正确答案概率 0.1 和 0.000001，在 `1 - p` 看来几乎一样糟（0.9 和 0.999999），但在 `-log p` 看来差了十倍以上。而"模型几乎没给正确答案留位置"恰恰是最需要被狠狠惩罚的情况。

`-log p` 还有一层意义：它等于"这件事发生时带来的信息量"，也就是惊讶程度。p 越小，发生它就越出乎意料，信息量越大。这不是凑出来的，是信息论里对"意外"的标准度量。

最后，`p = 0` 时 `-log p = inf`——这个看似麻烦的性质，正好把"完全没考虑过这种可能"从"表现不好"升级成"不可接受"，这是对的。

### 3. 困惑度 11.6 是什么意思？

读作：**模型在每一步，平均在 11.6 个候选之间犹豫。**

完全瞎猜的基线是**词表大小 65**——因为均匀分布下，每个字符被选中的概率都是 1/65，模型"在 65 个选项之间犹豫"。我们的模型把 65 降到了 11.6，说明它确实从计数里学到了东西。

另一个有用的读法：困惑度等于"模型的不确定程度相当于从多少个等概率选项里猜"。11.6 介于 11 和 12 之间，不是整数很正常，它是个统计平均值。

困惑度还有个实际好处：**它不依赖词表大小**。交叉熵的数值会随分词方式变化（词表大、token 少，每个 token 更难猜），困惑度则可以用来跨分词器比较——第 8 步之后如果换 BPE，这一点就有用了。

### 4. 验证集交叉熵为什么是 `inf`？

因为**验证集里出现了训练时没见过的字符组合**，模型给这些组合的概率是 0，而 `-log 0 = 无穷大`。只要有一个位置是无穷大，整段文本的平均值就是无穷大。

根源在于：这个模型把"没见过的"和"不可能的"当成了同一件事。它只见过训练数据，于是认为训练数据之外的一切概率为零。语料再大也穷尽不了所有可能组合（这里是 65×65=4225 个格子填满 1380 个），所以这个问题必然出现。

加 1 平滑（拉普拉斯平滑）的做法是：算概率之前先给**每个**格子的计数加 1，再归一化。这样任何组合都至少分到一个极小的非零概率，`-log` 就再也不会是无穷大。

代价是**训练集上的表现会略微变差**——因为那些原本概率很高的组合被稀释了。实测里训练集交叉熵从 2.452 涨到 2.455，几乎可以忽略；而验证集从无穷大变成了 2.482。

这就是一次典型的取舍：**拿一点"对已知的自信"，去换"对未知的容忍"。** 后面每一步都会遇到这个取舍的不同版本。

### 5. 为什么贪心会写出 200 个换行符？

因为**换行符后面最常接的还是换行符**。剧本里连续空行很多，所以计数表里 `\n → \n` 那一格是这一行里最大的。贪心一旦走到换行符，下一步还是选换行符，再下一步还是——永远出不来。

这不是 bug，是贪心的固有缺陷：**它只看当下这一步，不看后面会发生什么。** 每一步都选"眼前最好"的，合起来却是一个死循环。

有意思的是它失败得**极其安静**：不报错、不警告，只是老老实实输出 200 个空行。如果没有把生成结果打印出来看，你根本不会发现——这也是为什么每一步都要把真实输出贴出来。

按概率抽就不会卡死，因为换行符后面总还有一定概率跳到别的字符。代价是结果不稳定，同一个开头每次跑的都不一样——第 8 步会讲怎么在这两者之间调节。
