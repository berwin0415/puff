# 第 5 步：加隐藏层

> **一句话**：把上下文从 1 个字符扩到 8 个，中间加一层非线性变换，第一次突破"只看当前字符"的天花板。
> **这一篇要回答**：损失为什么卡在 2.46 下不去？

## 这一步解决什么问题

第 4 步的损失卡在 **2.46**。那不是训练没跑够，而是一个**结构上限**：

> 只看 1 个字符时，"下一个字符"能提供的信息就那么多。`P(下一个 | 当前)` 的最优值就是 2.46，换任何求法都压不下去。

所以这一步第一次**改结构**，做两件事：

1. 把上下文从 1 个字符扩到 **8 个字符**——让它能看到 `thou ar` 而不是只有 `r`；
2. 中间插一层**隐藏层**，让这 8 个字符先经过一次非线性变换，再决定下一个字符。

## 读完你会知道

- 为什么 2.46 是结构上限，而不是"训练不够"；
- `d_model` 是什么，它和 `vocab_size` 分别管什么；
- 隐藏层和激活函数各自解决什么问题，没有它们会怎样；
- 过拟合在数字上长什么样。

## 怎么读这篇

**标记约定**：出现 `（→ 第 N 步）` 表示那个概念在后面那一步才正式讲解，这里只要知道名字就行。

**本文范围**：只讲"多给几个字符 + 加一层隐藏层"带来的变化。怎么让模型自己决定"该重点看哪几个字符"（注意力），是第 6 步的事。

这也是 `d_model` 第一次真正落地——第 0 步和 glossary 里提过它，但从这一步起它才真的出现在代码里。

## 两个改动

### 改动一：上下文从 1 个字符变成 8 个

第 4 步的模型是 `P(下一个 | 当前字符)`。这一步变成：

```
P(下一个 | 前面 8 个字符)
```

输入从"一个整数"变成"8 个整数"。这 8 个字符怎么交给网络？最直接的办法是**把它们拼起来**：

```
8 个字符 × 每个 64 维 = 512 个数 → 隐藏层
```

代码里用的是 `Conv1d(kernel_size=8)`。不要被名字吓到，它在做的事就是"在位置 t 取前 8 个字符的向量拼接，乘一个线性层"——只是权重在所有位置共享，所以参数量和序列长度无关。

### 改动二：中间插一层隐藏层

```
8×64 个数字 → 线性层 → 256 维 → ReLU → 线性层 → 65 个分数
```

`ReLU` 是**激活函数**，作用是把负数变成 0。它看着简单，却是整个网络的关键：**没有它，两层线性层叠起来仍然等价于一层线性层**（矩阵乘法可以合并），模型就退化成一个更复杂的查表，学不到"字符组合"这种东西。

## `d_model`（模型维度）第一次变成代码

`d_model` 与 `vocab_size` 的分工，[附录A-技术地图](./附录A-技术地图.md) 开头已经说清，这里只看它落到代码里的样子：

```python
self.embed = nn.Embedding(vocab_size, d_model)   # 65 行、每行 64 个数
```

`nn.Embedding(65, 64)` 就是一张 65 行 × 64 列的表：**第 i 行是字符 i 的向量**。这张表本身就是参数，会被训练改变。（→ 第 7 步还会用到它，并且再叠加一份位置信息）

表里没有文字，全是实数——65 × 64 = 4,160 个数，和别的权重矩阵没有任何区别。"查表"就是按下标取一行：`embedding.weight[20]` 取出的就是字符 `H` 的那 64 个数。

### 为什么不直接把 id 当数字用？

因为整数当输入会带进两个假信息：

- **大小没有意义。** `H` 的 id 是 20、`G` 是 19，它们相邻只是因为字符表按字母排了序。把 20 当成"数值 20"喂进去，等于宣称"`H` 比 `G` 大 1"——可这个大小关系没有语义。换一种排序方式，输入全变，意思却没变，模型学到的东西就废了。
- **一个数装不下多维信息。** 一个字符需要同时携带"是不是元音""常出现在词首吗""后面爱接什么"这些信息，一个标量表达不了；64 个数可以。

换成向量之后，模型才能做加权求和、点积、投影——注意力和线性层全靠这些运算，而整数只能比较相不相等。

**那为什么不"算"出来，而要"查"？** 因为查表就是"one-hot 乘矩阵"的省事写法：`one-hot(20) @ W` 的结果恰好是 `W` 的第 20 行。直接取这一行，就省掉了整个矩阵乘法。

这张表一开始是随机数。实测本项目训练后的表里，`T` 和 `t` 的向量最接近（余弦相似度 0.35），空格和换行次之（0.18），`q` 和 `Q` 是 0.22。这些对应关系没有人手工设计，是"预测下一个字符"这个目标顺带塑造出来的。

## 实测

```
设备           : cuda
上下文窗口     : 8 个字符（第 4 步是 1 个）
d_model        : 64（每个字符被表示成多少个数字）
隐藏层         : 64×8 → 256 → 65
参数量         : 152,193（第 4 步是 4,225）

训练前         : 训练集 4.151

训练 3000 步:
  第     0 步   loss = 4.1584
  第   500 步   loss = 1.9042
  第  1000 步   loss = 1.8477
  第  1500 步   loss = 1.7756
  第  2000 步   loss = 1.7259
  第  2500 步   loss = 1.7475
  第  2999 步   loss = 1.7295

训练集         : 1.725
验证集         : 1.888
第 4 步基线    : 训练集 2.458（只看 1 个字符的上限）
改进           : +0.570（验证集）
```

**参数量从 4,225 涨到 152,193，涨了 36 倍。** 这是第一次感受到"模型变大"是什么速度——而这才刚开始。

**损失从 2.46 掉到 1.89，降了 0.57。** 换个说法：困惑度从 `exp(2.458) ≈ 11.7` 降到 `exp(1.888) ≈ 6.6`。**模型每一步从"在 12 个候选里犹豫"变成了"在 6.6 个候选里犹豫"。**

## 第一次见过拟合

注意这两个数：

```
训练集 1.725
验证集 1.888
```

训练集比验证集低 **0.163**。这个差距叫**过拟合**：模型在训练数据上背得越来越熟，但那份熟练没有完整地迁移到没见过的文本上。

原因很直白：模型有 15 万个参数，而 8 个字符的上下文组合非常稀疏——同一个 8 字符片段在训练集里可能只出现一次。模型可以把那一次的答案记下来，但这不叫学会，叫背下来。

第 8 步会专门处理它（验证集、早停、正则化）。现在先记住这个现象：**训练损失低不代表模型好，训练集和验证集的差距才是信号。**

## 脚本在验证什么

1. **先量训练前的损失**（4.15），确认新结构起点和第 4 步差不多——随机初始化什么都学不到。
2. **同一份数据、同样的切分**，让 1.74 能和 2.46 直接比。
3. **同时报训练集和验证集**，过拟合从这一步起就是可见的，而不是等到第 8 步才发现。
4. **参数量和结构都打印出来**，让"改结构"这件事有具体代价可看。

## 回顾

- **做了什么**：上下文从 1 个字符扩到 8 个，中间加一层 256 维隐藏层（`ReLU`），参数量从 4,225 涨到 152,193。
- **关键数字**：训练集 1.725 / 验证集 1.888，比第 4 步的 2.458 好 0.57；困惑度从 11.7 降到 6.6。
- **第一次见过拟合**：训练集比验证集低 0.163，模型开始"背"只出现一次的片段。
- **在总览图上的位置**：数据流第 ② 步的嵌入 + 第 ③ 步的第一个可训练加工层。
- **留给下一步**：8 个字符被**平等地**拼在一起，模型无法选择"该重点看谁"。

## 本步新名词

累计索引见 [glossary.md](./glossary.md)。

- **模型维度（`d_model`）**：每个 token 用多少个数字表示。本步是 64。它决定模型内部向量的宽度，全程不变。
- **隐藏层（hidden layer）**：输入和输出之间的中间层。它的输出叫**隐藏向量**，不是最终答案，而是"模型内部的中间表示"。
- **激活函数（activation function）**：插在线性层之间、给网络加非线性的函数。没有它，多层线性等于一层。
- **ReLU**：最简单的激活函数，`max(0, x)`——负数变 0，正数不变。
- **参数量（parameter count）**：模型里所有会被训练改变的数字的个数。本步 152,193。
- **过拟合（overfitting）**：训练集上表现很好，但在没见过的数据上不行。第 5 步第一次明显出现：训练 1.524 / 验证 1.741。（→ 第 8 步处理）
- **上下文窗口（context window）**：模型一次能看多少个 token。本步 8，第 7 步会扩到 128。

## 自测

1. 为什么第 4 步的 2.46 不能靠"多训练一会儿"或者"换个优化器"突破？
2. `d_model = 64` 和 `vocab_size = 65` 分别在管什么？为什么不能只留一个？
3. 如果去掉 `ReLU`，这个网络会发生什么？
4. 训练集 1.725、验证集 1.888，这个差距说明什么？为什么模型越大越容易这样？
5. 困惑度从 11.7 降到 5.7，用一句话翻译成人话。

## 自测详解

### 1. 为什么 2.46 突破不了？

因为 2.46 不是"训练不到位"，而是**信息上限**。

第 4 步的模型只能看一个字符，它学到的本质是 `P(下一个 | 当前字符)` 这张条件概率表。这张表的最优值由数据决定，是一个固定的数（约 2.45）。你可以用数数得到它，也可以用梯度下降得到它——但换任何方法，都不可能比"知道当前字符"这个条件下的最优预测更准。

要变好，只能给模型**更多信息**（更长的上下文）或**更强的关系建模能力**（隐藏层、注意力）。所以第 4 步是"换求法"，第 5 步才是"改结构"——**结构决定了天花板，训练只决定你能多接近天花板。**

### 2. `d_model` 和 `vocab_size` 各管什么？

- `vocab_size = 65`：**有多少种 token**。它决定输入表有多少行（每个字符一行），也决定输出层吐出多少个分数。
- `d_model = 64`：**每个 token 用多少个数字表示**。它决定每个字符被表示成一个多长的向量。

两个都不能少：只有 `vocab_size` 的话，字符只是一个整数，没法做加权、求平均、算相似度；只有 `d_model` 的话，模型不知道要区分哪些字符。

一句话：`vocab_size` 是"字典里有多少个字"，`d_model` 是"每个字用多少个数字来描述它的含义坐标"。第 0 步给过这个说法，现在你可以在代码里看到它变成 `nn.Embedding(65, 64)`——一张 65 行 64 列的表。

### 3. 去掉 `ReLU` 会怎样？

网络会退化成**一层线性变换**。

两层线性层 `y = W₂(W₁x + b₁) + b₂` 展开就是 `y = (W₂W₁)x + (W₂b₁ + b₂)`——还是一个 `Wx + b` 的形式。中间那层 256 维的隐藏层虽然在，但它没有增加任何表达能力，只增加计算量。

线性模型只能学"输入的加权和"。而"看到 `th` 之后常见 `e`"这种规律，需要的是**组合判断**（两个条件同时成立时才有某个结论），本质是非线性的。`ReLU` 就是给网络这个能力的开关。

这也解释了一个常见困惑：**为什么模型明明"层数多了"，效果却没变好**——很可能中间少了激活函数，或者激活函数被放在错误的位置。

### 4. 训练集 1.725 / 验证集 1.888 说明什么？

说明模型开始**背训练数据**了。

0.163 的差距是过拟合的典型表现：模型在训练集上能降到 1.725，但在从没见过的验证集上只能到 1.888。多出来的那 0.163 就是"背下来的部分"——它在训练集上有效，换个文本就失效。

**模型越大越容易这样**，因为参数量决定了"能背多少"。15 万个参数可以记住大量 8 字符片段对应的答案，而 8 字符的组合空间远比语料大，所以记住的东西在验证集上大多用不上。

这也是为什么从这一步开始，**只看训练损失会骗人**。第 8 步会引入验证集上的模型选择与早停，就是为了对抗这件事。

### 5. 困惑度 11.7 → 5.7 是什么意思？

**模型每一步从一个字符开始猜时，平均在 11.7 个候选之间犹豫；现在变成了 6.6 个。**

或者说：原来要猜 11.7 次才能碰上一次，现在只要猜 6.6 次。少了一大截。

这不是"准确率从多少涨到多少"——语言模型的输出是概率分布，不是单选题。困惑度衡量的是"这个分布有多不确定"，它同时考虑了模型有没有把正确答案排在前面、以及排得多靠前。
