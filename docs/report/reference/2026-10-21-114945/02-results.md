### 3.1 失败具体发生在哪里

- **OpenClaw：**普通工具一轮没有按要求读全分页；扩展两轮分页失败。浏览器三轮都用满二十次调用，101/202 未提交，303 已提交并下载正确文件但未正常结束，严格验收仍失败。数量拒绝另两轮无副作用，却缺真实执行层拒绝证据。
- **Deep Agents：**普通工具有一轮每页一百条；扩展 202 曾超限查询后补分页，仍违反过程约束；扩展 303 还选错商品。回执和状态保存并不修正错误的业务选择。
- **Agents SDK：**扩展一轮分页超限；敏感任务两轮由模型自行拒绝，没有敏感副作用，但没有触发要验证的执行层规则。这两轮代表测试覆盖不足，不能解释为发生越权写入。
- **DSH：**原五类基本任务均通过，但随后冷读发现旧业务状态保存接法不兼容。原批次说明当轮业务执行成立，不能证明持久化生命周期已经成立。

### 3.2 浏览器余量

原三种子的模型请求分别为 DSH **20/20/16**、OpenClaw **20/20/20**、Deep Agents **18/20/17**、Agents SDK **20/20/18**。通过二十次上限以内的任务，仍可能没有应对额外重试的余量。该现象值得后续在目标网站验证，不能从本地固定页面推导任意网页能力。

### 3.3 诊断、取消和冷读单列

| 路线 | 当前观测 | 能力边界 |
| --- | --- | --- |
| DSH | 缺文件与注入 504 诊断通过；两次取消缺原生 `turn/end`，未通过 | Goal 安全点暂停另有成功证据，不能倒推旧取消通过 |
| OpenClaw | 修正后的 HTTP 取消有同 run 停止证据，但容器发生 OOM，整体失败 | 不能仅凭一条停止事件给完整取消结论 |
| Deep Agents | 公开 drain、真实 `GraphDrained` 与同步 checkpoint 有实测 | 当前 superstep 完成后的协作停止，不是即时中止所有工具 |
| Agents SDK | 公开 immediate cancel 有实测 | 不代表已提交副作用可撤销，也不代表 after_turn 的完整恢复已验 |

四路线原生业务状态冷读均已取得有效结果：DSH 23 项、其他三者各 22 项。冷读的任务是不调用模型和业务操作而重建会话/业务态；DSH 允许原生加载追加合法边界事件，不能把它写成所有状态文件字节完全不变。冷读没有继续未完成任务。

材料边界决定可如何汇总：

- **DSH F1、F2、F8 分别保留。** F1 与后两组候选镜像、状态保存接法不同；F2 到 F8 又强化了进程完整性验收。不能声称新镜像已在同一判定下完成统一的二十五轮。
- **Deep Agents 可以做有说明的五种子描述。**候选镜像及详细/业务/进程判定源码经源记录核对一致，但完整 bench 镜像不同。描述结果为工具 4/5、浏览器 5/5、扩展 2/5、两个拒绝测试各 5/5，共 21/25、175 次请求；保留原三组与新增两组，未重评旧轮。

这里的“最终”只指基本任务的最后两组输入，没有完成后续故障、授权或成本专项。

## 5. 真实暂停、释放资源与续跑

两路线使用各自独立暂停变体，先有不暂停基线，再在任务已产生写入且仍运行时请求暂停。每条正式链都确认旧 Worker 删除、等待 600 秒、模型/工具静默、代理重建且预算持续、新 Worker 同镜像从原生状态继续；恢复没有重新提交原任务提示。

| 路线 | 原生续跑 | 完整业务 | 三条链模型请求 | 累计活跃时间 |
| --- | --- | --- | --- | --- |
| DSH Goal | 3/3 | 3/3 | 12 / 9 / 14，共 35 | 41.70 / 39.38 / 48.37 秒 |
| Deep Agents drain/checkpoint | 3/3 | 1/3 | 5 / 6 / 6，共 17 | 32.77 / 35.73 / 39.96 秒 |

Deep Agents 的 101/202 报告和三笔写入正确，但分页审计不合格；原生继续、预算及已完成写入不重发的分项仍有效。DSH 101 使用追加只读离线全链复核，修正了判定器对官方会话头默认值的误判；原 16/17 失败与哈希保留，没有重跑候选挑选成功。

六条链共 52 次模型请求、18 笔实际写入。六条不暂停基线另有 49 次请求，四条实施中止另有 15 次；这些不能从研究投入中删除，也不能与六条成功完成执行的恢复链混为同一分母。

| 共享服务内存样本均值范围 | 58.63–59.04 MiB | 58.12–58.59 MiB |

## 6. 故障：冒烟已结束，正式矩阵中止于采样完整性

最新候选材料分别为 DSH `fault-round-order`、Deep Agents `fault-send`。同材料、两种服务模式的 seed101 无故障基线中，DSH 为 2/2、20 次模型请求；Deep Agents 为 0/2、10 次模型请求，两轮均因分页失败。因此，故障轮中的分页失败不能直接归因于故障注入。

以下四故障冒烟均为 seed101、非幂等业务服务，每个格独立运行。

| 故障 | DSH | Deep Agents |
| --- | --- | --- |
| 首次模型请求注入 504 | 完整通过；11 条计数含 1 次注入 | 完整通过；8 条计数含 1 次注入 |
| 工具写入前失败一次 | 完整通过；13 次 | 完整通过；8 次 |
| 提交成功后丢回执 | 完整通过；12 次 | 分页业务失败；6 次；已提交操作未重发 |
| 写入前杀 Worker | 完整通过；15 次 | 分页业务失败；5 次；原生崩溃恢复等 11 项独立检查通过 |
| 四格完整业务 | **4/4；51 条计数** | **2/4；27 条计数** |

两组各有一次本地超时注入，因此 51/27 是持久预算计数，不全部是远程请求。两条 kill 都有真实杀 A、删除 A、新 B 使用原状态和预算继续的证据；这些样本没有重发已经提交的操作。

正式计划为每路线 **4 故障 × 2 服务模式 × 3 种子 = 24 格**。DSH `i23-dsh-round-formal-001` 在截点前已经停止：

1. `model_timeout / idempotent / 101` 完整通过，12 条计数。
2. 同故障/模式的 202 格业务结果通过；9 项外层检查中 8 项通过，仅资源采样因 `fault_resource_sampling_gap` 失败，触发完整性停止。

因此是 **1/24 格有效完成，另有一格因实验完整性问题不能给候选能力结论**；不是“1/24 成功率”，也不是二十三次候选失败。Deep Agents 正式矩阵、两路线其他基线及故障最终种子尚未完成。旧 DeltaChannel 解码、Send 诊断和 DSH Goal 轮次观察错误导致的中止仍保留，见[故障记录](../../../validation/fault-recovery-execution.md)与[原件索引](evidence/index.md)。
