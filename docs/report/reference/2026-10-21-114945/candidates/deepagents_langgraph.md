# Deep Agents + LangGraph 候选附录

资料截点：**2026-10-21 11:49:45，Asia/Shanghai**。本附录仅采用截点前已结束运行及其既有判定；截点仍运行中的 I24 removal202 不预填结果。共同口径见[分组结果](../02-results.md)，各组原件见[证据索引](../evidence/index.md)。

## 测试对象、版本与入口

本候选组合固定 Deep Agents `0.7.28` / commit `0089e635dce525055272883b53bc222f385beac1`，以及 LangGraph `1.2.16` / commit `98043c37abc60374030f960a03a6e0d4c0112643`，两者均 MIT。测试使用本地 SDK 和 SQLite checkpointer，没有以托管 LangSmith/LangGraph 服务替代。

普通入口由官方 `create_deep_agent` 执行，显式挂载 `AsyncSqliteSaver`，使用可信 thread_id 与同步持久化。详细阶段、I22 pause、I23 fault-send、I24 multi-user 和 I25 instance-runtime 各自冻结材料，不能拿普通入口的一次通过覆盖后续变体。它被选入专项的原因是已有公开图控制与 checkpoint 证据，便于检验从原图继续；这不等于业务效果或生产投入已最优。

## 接入与能力来源

官方提供 Agent 循环、图调度、状态 schema/reducer、checkpoint、`RunControl.request_drain`、`GraphDrained` 与原 checkpoint 续跑。HTTP/MCP 工具、业务规则和状态字段、可信绑定、生命周期、后端和资源策略由本仓库接入。

普通任务排除框架自带文件、执行、委派及待办工具，业务操作走共同工具服务。新增查询仅转发一次 receipt；业务态通过公开 `ToolRuntime` 和 `Command(update=...)` 进入原生图状态，reducer 保留并行工具的独立观察。收到 write 回执只记写入应答，只有实际查询及 scope/operation 匹配才确认业务态。源码与具体接口见[接入说明](../../../../../adapters/deepagents_langgraph/README.md)。

drain 的语义是当前 superstep 完成后停止下一批调度，可能在暂停请求后继续完成已开始的模型或工具工作。它不是即时抢占，更不能撤销服务端已提交写入。

## 同题任务与状态读取

初筛两次新容器工具任务均完整通过，各 6 次模型请求、3 笔写入，模拟累计限额通过。详细正式组与最终补充分开记录：

| 任务 | 原 101/202/303 | 新增 404/505 | 失败或余量 |
| --- | --- | --- | --- |
| tools | 2/3；17 次请求 | 2/2；12 次请求 | 原 101 使用 page_size=100 |
| browser | 3/3；55 次请求 | 2/2；38 次请求 | 202、505 均用满调用额度 |
| sensitive | 3/3；6 次请求 | 2/2；4 次请求 | 五组均有真实执行层拒绝 |
| extension | 1/3；21 次请求 | 1/2；12 次请求 | 202、404 分页违规；303 还选错商品 |
| extension-denied | 3/3；6 次请求 | 2/2；4 次请求 | 五组均在写入前拒绝超量 |
| 固定五类组合 | 12/15；105 次请求 | 9/10；70 次请求 | 原组 21 笔、新组 14 笔实际写入，包含错误业务写入 |

extension/303 实际购买 14、15、07，应选 14、18、06；回执查询和原生状态如实保存了实际错误选择，因此不能把这一失败归为状态未保存。分页失败即使报告和写入正确也保留：要求既查全页，又每次最多 5 条，事后补页不能消除曾发出 page_size=100 的违规。

两批候选镜像、任务及相关判定源码一致，bench 完整镜像不同。已有报告允许按核对后的共同口径描述五种子结果，但不把它称作同一完整镜像组合的 25 轮批次。正式的完整通过数包含拒绝测试，不是成功业务任务分母。详见[候选报告](../../../../validation/deepagents_langgraph.md)。

冷读最初因 SQLite 在只读挂载上仍尝试建立 WAL 辅助文件失败。修订后仅在已排除写者及未合并 journal/WAL 的前提下使用 immutable 只读模式，最终 **22 项通过**，新容器重建原业务态且无新增模型/工具调用。没有删除 WAL、改写原数据库或把该探针宣称为任务续跑。

## 暂停、故障、用户边界与实例专项

| 专项 | 截点前已结束结果 | 解释及未完成部分 |
| --- | --- | --- |
| I22 暂停 | 三种子原生暂停/恢复 3/3；完整业务 1/3 | 已真实 drain、删 A、等 600 秒、重建代理，新 B 用 `None` 从原 checkpoint 继续；101/202 分页业务失败，303 完整通过 |
| I23 fault-send | 两模式正常基线 0/2；非幂等 seed101 四故障冒烟 2/4 | 基线、丢回执和强杀失败均为分页；强杀的原生换容器恢复等 11 项外层检查全部通过，已提交操作未重发。正式矩阵与最终种子未完成 |
| I24 removal101 | 产品边界/真实重叠/重连，以及资源/生命周期分项通过；整体 false | A 主任务和两取消通过，仅 B 主任务业务失败；host 采样/超额/errors 为空，正向清理通过。独立 202 截点仍在运行 |
| I25 两用户探索 | 按需与常驻各 3/5 可评分业务；分别 33/34 条请求计数；整体均 false | 原业务态冷读或对象保留、新任务唤醒、杀 A 后 B 原生进展及观察/资源/清理通过；业务失败保留，A 未恢复 |

I22 的继续没有重发原始提示，也未重复已完成写入；“原生恢复成立”和“完整业务失败”必须同时报告。早期链因 Docker 对象判断、PregelTask 序列化形状、代理切换采样空档中止，均另留记录，不算恢复通过。见[暂停报告](../../../../validation/pause-recovery.md)。

I23 的旧判定曾假设 checkpoint 直接保存完整 messages，但实际采用 DeltaChannel；后来又因诊断 JSON 不能编码原生 Send 中止。修订针对诊断投影和独立物理解码，未改 graph 状态、saver 或恢复输入。字段缺失/诊断不能编码不等于框架没有保存状态。新 fault-send 冒烟证明强杀后原生继续成立，仍不能用冒烟替代故障矩阵。见[故障记录](../../../../validation/fault-recovery-execution.md)。

I24 的模拟后端从认证凭证绑定 principal、任务、attempt 和固定 Worker，授权后路由控制与状态接口；它是本仓库外置应用层，并未接入用户现有产品租户系统。当前单次 Worker 控制服务不支持同 Worker 的 A→B→A 复用。旧 fresh101 的业务与退出采样失败保留，新 removal101 的通过分项不能倒填旧记录。[多用户报告](../../../../validation/multi-user-design.md)明确了这些边界。

I25 resident 入口保留的是真实模型、工具、图和 saver，不是空壳容器；常驻或关闭由实验宿主策略选择。两种策略在相同材料下探索了生命周期，但前置完整业务基线失败，`formal_i25_eligible=false`，两轮 `cost_subset_passed=false`、`i25_complete=false`、`savings_percent=null`。常驻 N=5/10 是启动前固定配额拒绝，没有 RSS/OOM 实测；按需 N=5/10、其余种子、用户轮换、同入口 I24 和真实后端开销仍缺。观察到的两用户内存/唤醒差异不构成生产节省比例。见[实例成本报告](../../../../validation/instance-cost-flow.md)。

## 维护投入与适用条件

这条路线实际承担了本轮最深的应用层接入：业务 schema/reducer、MCP、SQLite 冷读、暂停索引、Delta/Send 诊断、模拟认证后端、HTTP 控制服务和常驻入口。官方仍承担图执行及恢复；本仓库承担任务所有权、控制授权、工具路由、生命周期和业务正确性验收，不能合称“框架自带云端运行平台”。

维护点包括锁定依赖与 graph 结构、checkpoint 格式、可信 thread/工具绑定、连接重建、容器退出删除竞态和观察器协议。后几项有相当部分是研究设施投入，并非每项都需带进生产；当前也没有可靠人工工时、版本升级成本或交付工期。详见[工程清单](../../../../validation/engineering-inventory.md)。

该证据适合支撑**团队愿意建设应用运行层，且重视图状态可观察、公开控制和原生 checkpoint 续跑**的后续评估。业务遵循波动、写入不确定窗口的完整覆盖、同 Worker 复用授权和完整成本模型仍是待验证条件，不能以原生恢复通过替代它们。
