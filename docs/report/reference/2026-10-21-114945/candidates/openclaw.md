# OpenClaw 候选附录

资料截点：**2026-10-21 11:49:45，Asia/Shanghai**。本附录保留已有运行和独立追加审计的结论，不覆盖原判定。共同结果口径见[分组结果](../02-results.md)，运行原件见[证据索引](../evidence/index.md)。

## 测试对象、版本与入口

测试对象为 MIT 开源 `openclaw/openclaw`，固定提交 `b6e0872bdb7228e22fac7608345e0529a35ec46e`，源码声明版本 `2026.10.5`。它是现有业务路线的比较基线。实验不推定 Hogee 现网的部署、休眠或租户策略。

镜像运行真正的官方 Gateway，由可信同容器客户端向 `/v1/chat/completions` 投递 Agent/session 请求，官方插件接入公共工具或 Playwright MCP。当前是单任务 Gateway 变体；并未用一个自写循环替代 Gateway。固定源码支持一个 Gateway 内多个 Agent、每个 Agent 多会话，因而不能从当前容器布局推断框架必须每用户常驻一个容器。

本轮从固定源码执行官方 `build:docker`，保留其资产构建，单独的 Control UI 未启用。同版本名 npm 包的 provenance 指向另一个提交，未用它替换当前源码。材料细节见[接入说明](../../../../../adapters/openclaw/README.md)与[候选报告](../../../../validation/openclaw.md)。

## 接入与能力来源

Gateway、Agent 循环、原生事件、会话数据库、插件和 hook 来自官方。实验提供 Gateway 生命周期、HTTP/MCP 转发、任务与 session 的可信绑定、业务状态扩展、下载来源校验及控制证据关联。工具保留原始 schema 和粒度，模型自行规划业务步骤。

业务扩展用公开 `before_tool_call` 阻止超量写入，用 SessionExtension 与公开 session facade 保存实际 operation/receipt 状态，没有另建业务 checkpoint 数据库。HTTP 工具返回的真实回执与原生状态逐项核对；本地状态提交和远端写入不是同一事务。Gateway 的 HTTP Bearer 具有实例级 owner/operator 权限，不是每用户窄权限凭证；产品层仍要鉴权、绑定和路由。

## 分组实测与失败

I09 初筛的两个新容器工具任务均完整通过，模型请求为 10/9 次，各 3 笔写入，模拟累计限额也通过。详细阶段的结果明显不等同于初筛：

| 正式 101/202/303 任务 | 完整通过 | 全组模型请求 | 主要结果 |
| --- | --- | ---: | --- |
| tools | 2/3 | 29 | 202 报告和写入正确，但分页过程不符合要求 |
| browser | 0/3 | 60 | 三轮均用满调用额度；101/202 未提交，303 已提交并下载正确文件，却未正常结束 |
| sensitive | 3/3 | 12 | 真实执行层拒绝，未发生敏感写入 |
| extension | 1/3 | 31 | 查询与业务态可用；101/303 因分页失败 |
| extension-denied | 1/3 | 10 | 202/303 无业务写入，但未触发所要验证的数量规则 |
| 固定五类组合 | 7/15 | 142 | 19 笔实际写入；失败轮调用保留在总数内 |

以上任务使用同一详细 build-002 镜像，15 个不同 Worker 的 Docker 快照均没有 OOM 标记。缺少数量 guard 触发证据，不等于发生了违规写入；浏览器 303 的业务产物正确，也不能覆盖原生未正常结束。旧浏览器冒烟曾有 schema 参数错误后纠正，不能凭单轮把所有请求开销归因于这些错误。完整逐轮结果见[候选报告](../../../../validation/openclaw.md)。

最终镜像从完整成功的 extension/202 取得状态，删除旧 Worker 后，新容器在断网及只读挂载下通过 **22 项冷读检查**：业务态和实际回执来源一致，无新增模型或业务调用。该探针没有继续未完成任务，不能充当暂停恢复。

### 取消必须同时解释接口和进程证据

旧取消 001 用 HTTP 投递任务，却调用另一条控制路径的 `chat.abort`。返回 `aborted=true` 但 runIds 为空，此后仍发生三次 write，任务最后自然结束。它证明本次接线没有停止该 HTTP run，不能扩大为框架完全不支持取消。

修正版通过官方 HTTP 客户端断连向同一 run 传播取消，记录了原生 `agent_end.success=false`、assistant 的 aborted、公开 wait 的终态和断连后无新增写入，原控制判定为 9/9。但同轮 manifest 记录 **OOMKilled=true**，后续独立进程审计保留整体失败。取消的原生停止证据成立，与资源健康未通过同时成立；不能把 9/9 单独写成稳定取消通过，也不能把原生停止一概归因于后续清理杀进程。该样本没有覆盖已派发写入在途时取消。[取消与追加审计](../../../../validation/openclaw.md)保留完整时间线及边界。

## 维护投入

接入已处理源码构建的内存/并发限制、Node 与配置代际、只读缓存目录、原生工具命名、Gateway/HTTP/插件事件关联，以及取消入口与任务投递入口一致性。构建采用官方支持参数限制并发，未删官方资产或伪造构建产物。新增查询、数量规则和 SessionExtension 都是本仓库业务接入；保存的 `BUSINESS_EXTENSION.patch` 不是上游核心 fork。

维护重点是 Gateway 生命周期、可信凭证边界、插件/session 契约及原生终态与容器状态的共同判断。自动构建耗时和依赖体积不能倒算人工工作量或常驻内存；目前没有候选版本升级实测或可靠研发人时。见[工程投入清单](../../../../validation/engineering-inventory.md)。

## 适用条件与未知项

若已有 OpenClaw 产品需要沿用 Gateway、插件生态及会话机制，本轮证据可用于定位应补的边界：浏览器在固定调用额度下的完整结束、分页要求、取消资源异常，以及产品后端授权。当前没有为这条路线完成安全暂停、新 Worker 继续、突然故障恢复、多用户或成本专项。

未进入 I22 后续两路线是本轮投入范围选择。固定源码存在 Gateway suspend/restart recovery 线索，但所选 HTTP 会话是否满足恢复资格、原执行身份与预算如何续接仍要实测。它继续作为业务对照，不因本轮失败预先淘汰，也不据源码多会话机制认定共享部署已经安全。选择依据见[专项选择记录](../../../../validation/selection.md)，恢复入口边界见[接口核对](../../../../validation/recovery-interfaces.md)。
