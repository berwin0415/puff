# 云端 Agent Harness 选型实验报告

阶段性结果 · 资料截点 **2026-10-21 11:49:45（Asia/Shanghai）**

本报告评估八条开源路线实现云端通用助手的能力、缺口及投入。研究问题是：在有限研发时间内，怎样取得能完成工具和网页任务、过程可追踪、业务容易扩展、暂停后可释放资源并继续工作的运行方案，同时为未来多用户接入保留边界。

截至截点，八候选完成容器初筛，四路线完成同题详细实验；DeepSeek Harness（DSH）与 Deep Agents + LangGraph 完成三种子暂停专项。故障正式矩阵、多用户及实例成本仍未收尾。本报告支持下一阶段的技术投入选择，**尚不支持最终产品迁移决定、生产可靠性承诺或现网节省比例**。

## 已取得的主要发现

| 问题 | 直接证据 | 当前解释 |
| --- | --- | --- |
| 这些路线能否满足基本接入约束？ | 八候选均能在固定 Docker 镜像中接选定远程模型；七者工具初筛 2/2，Pi 为 1/2；模拟累计调用限额均通过 | 八条路线均有进一步研究价值；暂缓深入不等于能力不支持 |
| 同题任务能否完成？ | 原三种子五类详细任务：DSH 15/15、OpenClaw 7/15、Deep Agents 12/15、Agents SDK 12/15 | 任务完成、分页约束、浏览器预算和拒绝触发存在差异；这些混合用例数量不是生产成功率或综合排名 |
| 状态扩展是否经得起新容器加载？ | 四详细路线均取得原生业务态冷读证据；DSH 曾因自定义必需事件加载失败，改保存接法后另验 6/6；最终 404/505 基本任务 DSH 10/10、Deep Agents 9/10 | 状态接口存在与真实兼容性不同；修订前后镜像和判定版本必须分组，不能拼成一组未执行的统一批次 |
| 暂停是否真的释放 Worker 并能继续？ | 两路线均真实暂停、删除旧 Worker、等待 600 秒、重建代理、在新 Worker 原生续跑，各 3/3；完整业务 DSH 3/3、Deep Agents 1/3 | 原生恢复已有证据；Deep Agents 两条业务分页失败仍保留。等待时 Worker 为零，共享服务与存储仍有成本 |
| 故障恢复到什么程度？ | 非幂等 seed101 四故障冒烟：DSH 4/4、Deep Agents 2/4；后者另外两条分页失败但杀进程恢复等独立检查通过 | 两路线都有真实崩溃后原生恢复线索。DSH 正式矩阵仅 1/24 格有效完成，第二格因采样完整性问题停止，不据此评价框架能力 |
| 多用户边界能否接入？ | Deep Agents removal101 轮真实并发、重连、跨用户拒绝、资源生命周期及两取消通过；B 主任务失败，整体未通过 | 模拟后端接入有部分有效证据，尚非完整多用户能力或同 Worker 复用验证 |
| 按需运行能节省多少？ | Deep Agents 两用户同材料常驻/按需探索均结束；各业务 3/5，整体均失败，观察及生命周期分项通过 | 可观察到空闲内存与唤醒等待的取舍；完整业务、更多用户档位和产品后端证据不足，节省比例保持未知 |

详细阶段的 DSH 原取消缺结束事件、OpenClaw 取消 OOM、Agents SDK 部分敏感任务只由模型口头拒绝等问题，均未被成功批次覆盖。原生能力、业务结果、执行完整性与测试覆盖分别报告。

## 当前投入方向

继续沿既定选择，将专项投入集中到 **DSH 与 Deep Agents**：前者已有完整基本任务和 Goal 续跑证据，后者提供较直接的图状态与协作暂停机制。优先补齐故障矩阵和多用户证据，再讨论生产运行管理与成本。

OpenClaw 保留为现有业务的改造对照，Agents SDK 保留为轻量路线；Pi、ADK、Codex SDK、OpenHands 保留初筛结论。现有产品实际版本、已有功能和回收策略尚未完全确认，不能用参考仓库源码推定迁移范围。
