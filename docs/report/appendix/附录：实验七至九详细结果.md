## 实验七：多人使用与访问控制

**问题：** A、B 同时工作时，能否各自查看状态、事件和文件，暂停/恢复/取消自己的任务；A 把目标换成 B 的任务后，服务是否拒绝且不泄露、不改变 B 的任务？

**两组证据缺一不可：** "本用户成功"和"跨用户拒绝"。**全部拒绝不算权限正确**；只把输出目录分开，也不能证明控制请求不会落到别的任务。断线重连和换执行程序后还要再核对归属，避免权限只在首次创建时有效。

**准备：** 一个小型模拟产品后端，从请求凭据识别用户，保存"任务属于谁、对应哪个原生任务、状态在哪、由哪个执行程序执行"的可信映射。客户端只能提交任务编号和操作，**不能自己指定宿主路径、执行程序或信号目标**；正文里的 `user_id` 也不能覆盖认证身份。A、B 各有独立凭证、工作区、状态库、会话和预算；总配额 **6 GiB / 3 CPU**，单任务 **300 秒 / 20 次调用 / 2 次重试**，恢复沿用原预算。

### 实际怎样执行

1. **准备四个任务。** A、B 的业务主任务用于验证连续执行、暂停恢复和重连；另为 A、B 各设一个取消子任务。不能先取消主任务，再重新提交一次，称作“原任务恢复”。
2. **同时放行业务任务。** 两个真实任务执行程序就绪后一起接收输入。记录双方模型和工具活动的交集；容器同时存在、任务同时排队都不算有效并发。
3. **核对本用户读取和跨用户拒绝。** 状态、事件、产物要与保护侧读取的原生状态、实际文件一致，产物须由任务真实生成。A 对 B 的查看状态、读取事件、读取文件、暂停、恢复、取消六种操作都要实际发出。已有的他人任务应返回固定无内容的 403；错误凭证的 401、目标不存在的 404不能替代越权测试。
4. **核对拒绝没有副作用。** 请求前后独立记录 B 的状态、文件、控制记录和业务账本。运行中的任务会自然变化，所以部分探针放在真实只读工具等待响应的稳定窗口中；这不是原生暂停，也不用于证明并发。跨用户恢复则必须等 B 已被合法所有者真正暂停后再测。
5. **暂停、换任务执行程序、重连。** 合法暂停后等原生状态安全保存，删除旧任务执行容器，用新任务执行程序从原状态继续，不重放最初提示词。另关闭客户端连接，再建立新连接、重新认证，检查同一任务仍可访问；新连接访问 B 仍须实际得到 403。
6. **独立验证取消并收尾。** 两个取消子任务进入真实活动后，先测跨用户取消被拒，再测本用户取消。保留已发出调用的实际副作用，检查取消确认后不再派发新写入。最后独立验收业务、原生控制、权限、并发、资源生命周期和清理结果。

**通过条件：** 原业务结果正确、本用户查询与控制有效、六类跨用户请求全部拒绝且不影响目标、重连后归属不变、具备真实并发和可靠资源记录。服务接受请求不等于框架已经完成动作；暂停后保存了文件，也不证明新进程能接着执行。

**A→B→A 同执行程序复用是另一个目标**，需要证明旧绑定、缓存、凭证和文件不残留。首轮未完成，不把"删旧容器建新容器"称为复用。

### 实际结果与结论

本实验实际接入 **Deep Agents / LangGraph 和 DeepSeek Harness**。其他六条路线未运行这一专项，不能登记为多人实验失败。先列新入口的单用户对照，再列双用户结果，避免把“一个任务能跑”当作“两用户边界已成立”。

| 框架 | 同入口单用户对照 | 对双用户结论的意义 |
| --- | --- | --- |
| Deep Agents / LangGraph | 第一组材料的前两次对照有来源核对、退出或资源采样问题，整体未通过；第三次对照完整通过。后来使用新服务材料的对照，模型、工具、预算、资源和退出轨道通过，但业务失败 | 旧成功、旧失败分别保留。仅业务失败时继续独立控制探索，各双用户任务仍按原业务标准评分，不借旧对照直接判整组成功 |

| 整组结果 | **未通过**；保留业务与恢复通过、取消未确认、并发未验证和采样失败四类事实 |

Deep Agents 的取消采用原生执行步边界的协作停止：等待当前边界安全收束，再禁止继续调度。它不是立即中断所有在途动作，结果通过也没有改变这一语义。DSH 的删除采样失败同样需要具体解释：采样时旧任务执行容器正在删除，实际消失确认晚约 21 毫秒；不能把它描述为误删其他用户任务。

本实验支持“所测 Deep Agents 接法已证明若干多人服务必要机制”。生产身份系统、浏览器使用期隔离、同一任务执行程序换用户复用均未验证；DSH 没有形成完整的多人实验通过结论。下一项成本实验使用另一套常驻入口，也不能直接继承这里的权限结论。

证据：[多人实验设计与三组结果](../../validation/multi-user-design.md)、[DSH 接线设计](../../validation/deepseek-multi-user-design.md)、[DSH 实际执行记录](../../validation/deepseek-multi-user-execution.md)。原判定见 Deep Agents 101（`scope/i24-da-removal-101-001`）、202（`scope/i24-da-removal-202-001`）、303（`scope/i24-da-removal-303-001`）及 DSH 双用户试跑（`scope/i24-dsh-smoke-101-001`）。

## 实验八：持续运行与按需启动的资源比较

**问题：** 云端有大量暂不工作的用户。固定两个活跃任务，把用户总数设为 2/5/10，比较**每用户常驻执行程序**与**只存状态、来任务再启动**两种方案。减少任务、改串行或只留空壳进程都会改变比较对象。

**"每用户常驻"是设定的对照假设，不是已确认的现网事实。** 首轮只有 Deep Agents 真正进入这条流程；DSH 未做完整策略对比，其余六条未运行——**均不登记为成本实验失败**。

**准备：** 每组配对固定入口、镜像、模型、工具、种子、任务和总配额。常驻保留最近业务自然完成后的执行图、模型客户端、工具连接与状态对象；按需正常关闭并删除这些对象，但保留同一份业务状态。用户间目录、凭证、历史和预算全部独立。每个执行程序固定 **2 GiB / 0.75 CPU**，总预算 **6 GiB / 3 CPU**——常驻 5/10 用户因声明配额超限**在启动前被拒绝**，没有实测内存或 OOM 结果。

**观察器本身占 256 MiB / 0.25 CPU**，与模拟业务、工具、代理一并计入资源清单；它不提供用户认证，**不能冒充产品后端**。真实产品后端、宿主虚拟机和存储费用未形成完整计量。

### 一轮的阶段与验收

| 阶段 | 执行动作 | 要验证的事情 |
| --- | --- | --- |
| 全部空闲，60秒 | 常驻保留 N 个真实任务执行程序；按需没有任务执行程序，只保存独立状态 | 空闲用户的实际资源负担，不能漏算共享服务 |
| 两个任务活跃 | 同时执行同口径业务任务 | 双方真实活动和工具进展重叠，重叠内至少有两份资源样本 |
| 结束并回收，60秒 | 常驻保留原对象；按需正常关闭并删除；两边都停止工具和代理 | 回收是否真实完成，以及结束后的空闲占用 |
| 原业务状态读回 | 常驻从原对象读；按需启动新任务执行程序读原状态库 | 同一份已完成业务状态仍在，不是恢复未完成任务 |
| 新任务唤醒 | 两用户分别收到新任务、独立的数据范围和预算 | 从可信请求记录到就绪、首次原生活动的时间；没有产品队列，不评价队列时延 |
| 更多用户轮换 | 五、十用户设计在001/002结束后唤醒此前未做业务的003/004 | 空闲用户确实可开始工作，最多仍为两个活跃任务；其余用户仅保留历史 |
| 单个执行程序故障 | 两个新故障子任务真实活动后，只强制退出 A 的执行程序，观察 B | 精确故障对象、A 退出后 B 的原生进展，以及 B 最终业务是否正确 |
| 独立评分与清理 | 停止付费和分发路径，读取账本、预算及资源证据 | 评分进程健康、结果与退出码一致，确切容器及网络已清理 |

故障阶段不恢复 A，原状态、原预算和在途不确定性都保留。因此，“唤醒新任务”和“B 没被连带终止”都不能证明 A 已成功恢复。

采样以两秒为目标，全部阶段间隔不得超过五秒。每份样本核对前后完整容器清单、配额、内存与进程，不能漏掉同镜像的另一个任务执行程序；缺测不能填零。业务正确、生命周期成立、观测完整三者同时满足，才可能形成完整成本结论。

这些是已观测窗口的描述。按需唤醒在本实验中慢约八秒，包含服务准备时间，不能直接当生产接口延迟。补审计发现旧判分只约束空闲窗口采样节奏：按需136份样本有18处间隔超过五秒，最长23.670秒；常驻140份有14处，最长23.598秒，另有起止和线程完成证据缺口。两份补审计均失败，不能用表中均值推出完整峰值、总成本或节省比例。

五用户按需轮换也已结束，七个可评分业务 **4/7**。此前未活跃的003/004首次任务均通过；三个失败任务只因请求 `page_size=100` 违反每页最多五条的协议。它们返回了全部19件商品，报告和实际写入正确；这属于单次查询数量超限，并未漏读商品。实际只强制退出 A 的执行程序，B 随后仍继续执行；故障复合项失败来自 B 的业务协议验收，不是 B 停止运行。

五用户的148份样本无采样错误，五秒节奏、登记、原状态及预算保留、评分健康和清理检查通过；但回收后空闲阶段有 **29份完整、1份不完整**。第82份样本开始时只有模拟业务服务和观察器，结束时下一阶段用于读取旧状态的执行容器已启动，但缺少该容器的当次资源记录。不能删除这份样本、改阶段或补零，整阶段均值与峰值保持未知。

所以五用户仍是失败的探索轮，十用户未运行，首轮在此收尾。现有结果支持“按需回收降低了所测空闲窗口占用，同时增加启动等待”的初步判断；完整收益、生产容量、三组输入的配对比较、常驻入口的权限验证和真实产品后端费用均未建立。

证据：[实例成本完整记录](../../validation/instance-cost-flow.md)、[生命周期采样设计](../../validation/instance-cost-lifecycle-sampling-design.md)。原判定见两用户按需（`i25-da-od-101-001/protected`）、两用户常驻（`i25-da-resident-101-001/protected`）、五用户轮换（`i25-da-rotation-n5-101-001/protected`）；旧采样按需补审计（`i25-legacy-sampling-audits-001/proof`）和常驻补审计（`i25-legacy-sampling-audits-001/proof`）单独保留。

## 实验九：模型用量与建设维护投入

**问题：** 失败、重试和接线诊断也消耗调用；一次调用又可能带很长历史，**"调用少"不等于"费用低"**。本项分别统计请求记账、模型 token、运行资源和工程改造，回答投入能被证据支持到哪一层。

**token 是模型处理文本的计量单位**，不等于汉字、单词或请求数。输入含任务、历史和工具信息，输出是模型生成内容；缓存与推理计数属于不同子项，必须按供应商实际返回统一。

**核算规则（六条）：**

1. **冻结材料清单**——成功、失败、中止都登记确切预算库、任务范围、原件哈希和结束依据；A/B 共用一个账本只计一次。不扫描即纳入，不在写入进行时统计。
2. **独立读取记账**——断网只读、无密钥容器中读五列元数据，按远程 200 / 未确认 / 在途未知 / 模拟 / 本地注入分类。200 只表示请求记录，**不等于业务成功**；未知不等于零。
3. **提取原生用量**——从框架保存的用量字段读数字，不按输出长度估算；按响应身份去重，避免分块、状态副本、恢复历史重复累计。没有供应商计数的默认零保留为未知。
4. **统一字段**——缓存读取含在输入内、推理 token 含在输出内，**不能再次相加**。缺失用空值，冲突保留原件；没有逐条关联就不算覆盖率。
5. **限定分母**——只有同任务、同变体、同模型、同材料、同预算的一组，才能用"全部尝试消耗 ÷ 完整成功业务数"。失败消耗不能删除；取消、拒绝、校准不算成功。
6. **盘点工程投入**——区分官方能力、必要接入、候选专用改造和实验设施。统计容器须健康退出、精确清理；提取程序成功不代表完整费用已知。
