# 附录：上云核对清单

把实验结论转成可执行的工作项。**不表示现有客户端或任何候选缺少表中全部能力。**

## 一、云端服务需要覆盖哪些环节

| 要检查的环节 | 云端服务需要明确或补齐什么 | 实验要回答什么 |
| --- | --- | --- |
| 任务运行 | 提供可以在后台启动、持续执行和结束任务的入口 | 在独立的后台环境中，选定运行方式能否完成同一段业务？ |
| 工具与浏览器 | 逐项检查桌面程序、本机路径和登录环境等依赖，确定服务端接法 | 在独立运行环境里，助手还能否查询、操作网页和提交结果？ |
| 进度与文件 | 将任务进度、业务记录和工作文件保存到执行程序之外 | 程序关闭或突然退出后，新程序能否继续，且不重复提交订单？ |
| 用户接入与控制 | 将用户身份绑定任务，提供进度查询、暂停、继续和取消 | 自己的任务能否正常控制，别人的任务和文件能否隔开？ |
| 业务规则与过程展示 | 接入工具、执行限制和过程记录，明确各自的维护位置 | 新规则是否真正生效，出了问题能否查清具体步骤？ |
| 资源分配与回收 | 按实际任务安排执行资源，处理空闲、唤醒和回收 | 能否减少等待期间的占用，代价是多少启动时间和额外工作？ |

## 二、客户端上云要拆哪些工作

| 工作 | 本轮已提供什么 | 与实际产品连接时要做什么 |
| --- | --- | --- |
| 后台任务入口 | 官方框架和实验入口可在容器中执行任务 | 核对客户端如何提交任务、查询进度和取回结果，确定产品接口 |
| 工具与浏览器 | 已有由模型逐步操作的工具、网页任务 | 盘点本机路径、桌面进程、账号与网络依赖，逐个决定服务端接法 |
| 进度和工作文件 | 暂停与故障后能使用原状态继续 | 接入持久存储，确定保存范围、版本兼容及恢复责任，保留操作凭据 |
| 运行控制和过程展示 | 已有事件、错误和控制接口；取消仍有路线差异 | 明确暂停何时生效、取消后哪些操作已发生，让用户看到一致状态 |
| 用户身份与归属 | 模拟后端下部分多用户接入已验证 | 将可信产品身份绑定任务、文件、工具与控制请求，覆盖实际使用入口 |
| 资源分配与回收 | 暂停期间执行程序可关闭，按需唤醒与轮换已有探索 | 接入调度、并发限制和回收策略，补完整资源观测及启动延迟评价 |

**故障注入、模拟采购、独立判分属于研究设施**，未来产品不需要原样搬过去；身份绑定、保存进度、运行控制和资源管理这些职责则必须有人承担，可以复用已有产品服务。
