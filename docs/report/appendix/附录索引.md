## 批次术语

各文件里反复出现几个词，含义固定如下：

| 词 | 指什么 |
| --- | --- |
| **初筛** | 每条路线最早的一次工具任务 + 累计额度检查 |
| **正式三组** | 内部编号 101 / 202 / 303 三组固定数据，**5.1 总表的口径就是这一批** |
| **补充测试** | 内部编号 404 / 505 两组新数据，只有 DSH 和 Deep Agents 跑过 |
| **本轮扩展** | 为另外四条路线补齐的五类任务（网页接入、扩展、两类规则） |
| **网页 40 次重跑** | 网页预算提高到 40 次后，八条路线各重跑三组 |

**「通过」默认指正式三组。** 若某条结论涉及初筛或补充测试，文中会注明。

**关于内部编号：** 文中会出现 `I22–I28`、`i25-da-...`、`all_pages_read`、`page_size=100` 这类标识，它们是原始任务表的编号和判分字段名，**保留原文是为了能和执行记录逐条对上**。阅读时可以忽略，不影响结论：`all_pages_read` 即分页检查，`page_size=100` 即一次请求 100 条商品，`I2x` 是内部任务序号。

## 判读约定

**「框架自带」与「实验补充」必须分清。**

- **框架自带**：固定版本官方源码或公开依赖提供的能力，本仓库未改上游源码。
- **实验补充**：本仓库为接通实验写的外层代码。其中一部分是产品化必然要做的（如可信身份绑定），另一部分只服务研究（如故障注入栅栏）。

同样是「通过」，有的靠框架，有的靠我们自己的代码——后者意味着产品化时要自己养一套。

**「未验证」不等于「不支持」。** 八条路线都做了实验一至四；但暂停、故障、多人、成本四项只在 DSH 和 Deep Agents 上做过，其余六条没测过这些，不代表它们不具备。

**数据不合并。** 不同批次用了不同镜像、不同预算或不同判定版本。每份文档都注明了自己的分母，不要跨表格相加。
