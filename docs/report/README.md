# 智能助手如何在云端运行：阶段性分享

这次调研有三个相互关联的出发点。

**已有客户端怎样上云。** 我们已有基于 DeepSeek Harness 的客户端，希望弄清哪些能力可以复用、哪些需要调整、哪些服务需要补建，让任务能在云端持续运行并服务多个用户。

**现有云端业务有哪些改善方向。** OpenClaw 云端业务在过程透明、业务定制和实例成本方面的反馈，提供了需要重点检验的问题。

**更多框架在云端能做到什么。** 我们也希望探索其他开源 Agent 框架的能力：哪些适合长时间运行的任务，哪些便于定制，恢复和多人使用能支持到哪里，做成服务还要补多少工作。这些探索为后续业务积累更多技术选择。

**实际测试对象：** 本轮 DeepSeek Harness 与 OpenClaw 均取自官方开源仓库的固定版本，加上本仓库的工具连接、任务控制等实验接入代码，自行构建容器运行。自有客户端和现有云端业务是研究背景，没有直接使用它们的产品版本或业务容器进行本轮测试。结果说明所测框架与接入方式的能力，应用到实际产品时仍需核对差异。版本依据见[资料说明](sources.md)。

**本次分享聚焦首轮实验的阶段性成果，资料截至 2026 年 10 月 21 日 15:29（北京时间）。** 首轮实验已结束。基本任务、暂停和约定的故障实验已完成；多用户、实例成本和完整费用统计保留未完成项。实验环境已清理，原始结果与失败记录保留。“首轮结束”不等于每项能力都通过。

这条主线最终要回答的是：**不同方案能为云端助手提供哪些能力，适合什么任务，又需要我们补齐什么，才能成为可靠、可维护的业务服务。**

每项详细实验都按“验证问题与设计原因 → 准备条件 → 执行步骤 → 判定标准 → 各参与框架的结果 → 可以得出的结论”展开。结果按框架和测试组分别列出，说明通过、失败与未完成的原因。可以顺着分享主线阅读，也可以从某个问题进入对应实验，查到设计、结果和依据。

## 读完后应带走的判断

官方 DeepSeek Harness 在本轮基本任务、暂停和故障任务中的完整业务表现较好，值得优先做一段真实业务的云端试接。Deep Agents 的进度保存、故障后继续和用户边界也有证据，但多次违反分页要求，说明恢复机制和业务正确性必须分别解决。

目前已经证明，保存任务后可以关闭执行程序，再由新程序继续；还没有证明迁移自有产品需要多少人力，或线上能节省多少费用。多用户接入和资源测量中的未完成项，是下一轮是否值得投入的具体问题。
