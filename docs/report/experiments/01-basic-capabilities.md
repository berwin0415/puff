# 实验一至四：独立运行、工具办事、网页操作与业务定制

[返回实验设计总览](../02-experiment-design.md)

本篇按 **2026 年 10 月 21 日 15:29:07（北京时间）**的首轮资料收尾，说明每项实验为什么做、怎样做、依据什么判断，以及实际得到了什么结论。这里的“首轮结束”表示约定研究已形成结果，失败和未覆盖能力仍然保留。

测试对象是各框架的固定版本与本仓库编写的实验接入。**DeepSeek Harness 测的是官方固定源码，并未直接搬迁已有客户端；OpenClaw 测的也是官方固定源码，并非现有线上产品。**结果可帮助盘点上云与改造工作，不能直接证明自有产品已经迁移成功。后文将 DeepSeek Harness 简称为 DSH，Deep Agents + LangGraph 简称为 Deep Agents。

## 实验一：离开开发机后能否独立运行，额度能否真正管住

### 要回答什么，为什么这样设置

客户端上云首先要排除“只在原开发机上能跑”。框架可能依赖宿主机安装的工具、已有登录状态或临时修改。把源码、依赖和接入代码固定进镜像，再删除旧容器、从同一镜像重新创建，才能判断环境是否可重建。容器在这里是独立的程序运行环境，不代表产品必须为每个用户永久保留一个容器。

运行额度是另一项基础条件。只限制框架的对话轮数，可能漏掉底层重试；程序重启后重新计数，又可能让同一任务反复取得新额度。因此另设统一计数服务，在请求发往模型前记账，并检查换容器后是否继续沿用原账。它属于本仓库补建的实验能力，不能算作八个框架都自带的功能。

### 需要准备什么

八候选都需要可核对的开源版本、依赖锁、Linux 镜像、模型接入和统一工具连接服务。每轮单独准备身份、工作区、业务数据与账本；宿主机负责启动和采样，不能代替候选执行任务。记录镜像和容器编号、配置摘要与挂载，避免借用宿主机的开发依赖。

真实任务使用选定的远程模型 `deepseek-v4-flash`，通常限五分钟活跃时间、二十次请求、最多两次模型客户端重试。支持的入口请求最多输出 4096 个 token（模型的文本计量单位）；Codex SDK 的公开入口没有相应硬上限，这一差异保留。额度探针另用可控的模拟模型服务，不产生远程模型费用。

### 怎样执行

1. 构建固定镜像，新建空状态容器，先确认能通过真实模型调用业务查询工具。最小运行任务只查第一页并返回商品编号和价格，不写业务数据。
2. 初筛再执行实验二的完整工具任务。删除容器后，从同一镜像创建新容器，使用相同数据种子和干净状态重新做一次，保存两次结果。
3. 单独运行额度探针：让模拟服务触发候选的真实重试，使用较小的两次请求额度，核对实际到达模拟上游的次数。
4. 删除首个候选、重建计数服务与候选容器，继续使用原预算库，确认额度已经耗尽时不会再向模拟上游发出请求。

### 怎样验收，实际得到什么

验收同时要求真实模型与工具记录、新旧容器编号不同而镜像相同、依赖来自镜像。预算检查既看拒绝记录，也看上游实际收到的请求，不能只相信候选自报“已限流”。探针中的限额退出是预期结果，不是业务成功。

八条路线全部完成初筛：DSH、OpenClaw、Deep Agents、Google ADK、OpenAI Agents SDK、Codex SDK、OpenHands 的完整工具任务均为 **2/2**；Pi Agent Core 为 **1/2**，另一轮报告和订单正确，但一次请求了一百条商品，违反分页要求。八者的模拟重试与跨容器累计限额均通过。Codex 早期的工具审批接入失败仍保留，修正后的两次通过没有覆盖旧失败。

这说明八条路线都有独立运行和接入公共工具的可行入口。两个新任务复现并没有加载前一次状态，因此不能证明任务恢复；模拟额度通过也不能替代业务效果、生产费用或多用户隔离验证。

## 实验二：能否按要求完成一段多步业务

### 要回答什么，为什么这样设置

“模型会调用工具”离“业务做对”还有距离。本实验让后一步依赖前一步：先读条件，再查全商品，筛选和计算之后才能下单，最后报告必须与订单一致。它同时检查约束是否被记住、工具是否被正确使用、真实写入是否发生。

每页最多五条不是无关细节。把目录分成多页，可以观察助手是否持续查询，或者只看第一页、擅自扩大查询量。即使最后碰巧买对，违反事先约定也算未完整完成。采购只是可独立核对的模拟业务，并不代表未来产品一定做采购。

### 需要准备什么

准备条件文件、查询与写入接口、工作区文件工具、独立业务账本和工具操作记录。条件明确为：类别属于 `office` 或 `garden`，单价不超过 **35 元**，库存至少 **2 件**；按单价升序、商品编号升序选择最便宜的至多三种商品，每种买两件。金额用整数分记录，避免小数舍入影响验收。

正式输入使用 101、202、303 三个数据种子，分别生成十九、二十一、二十三条商品；同种子与同用户、会话可重建相同目录。种子改变商品数据，不固定模型输出，因此三组各一次只增加输入覆盖，不构成可靠性统计。候选只能看到需求和允许查询的数据，标准答案由验收器另行计算。

### 怎样执行

1. 给每轮建立干净工作区、独立身份与账本，仅放入采购条件和目标提示。
2. 由助手读取条件，每次查询最多五条，直至查完目录；让它自行完成筛选、排序与金额计算。
3. 对所选商品各提交两件，操作编号由规定前缀和商品编号组成；普通授权内写入自动执行，不等待人工审批。
4. 生成报告，列明任务归属、商品、数量、单价、金额、操作编号和总额。候选结束后，验收器读取报告、真实账本与完整工具记录。

### 怎样验收，实际得到什么

所有必要条件必须同时满足：报告与独立计算一致；订单没有漏写、重复或额外写入；所有页都查过且每次不超过五条；工具开始和结束记录配对；归属、预算、候选结束状态符合约定。正确答案和程序正常结束不能相互替代。

以下是原三种子正式批次的完整结果。五类分别属于本实验、实验三和实验四；每类三次，共十五次，**不含初筛、诊断、取消或新进程读取状态**。

| 原三种子正式任务 | DSH 原保存方式 | OpenClaw | Deep Agents | Agents SDK |
| --- | ---: | ---: | ---: | ---: |
| 多步工具 | 3/3 | 2/3 | 2/3 | 3/3 |
| 网页操作 | 3/3 | 0/3 | 3/3 | 3/3 |
| 新工具与业务状态 | 3/3 | 1/3 | 1/3 | 2/3 |
| 敏感操作执行层拒绝 | 3/3 | 3/3 | 3/3 | 1/3 |
| 超量写入执行前拒绝 | 3/3 | 1/3 | 3/3 | 3/3 |
| 固定五类组合 | **15/15** | **7/15** | **12/15** | **12/15** |
| 全部模型请求，含失败轮 | 121 | 142 | 105 | 105 |

普通工具任务中，OpenClaw 一轮分页不符合约定，Deep Agents 一轮请求了一百条；报告和订单正确仍未通过。后来的 404、505 补充中，DSH 和 Deep Agents 的普通工具任务均为 2/2。可以确认多条路线能完成多步业务，也能看到约束遗漏；不能据这几个样本认定某框架普遍更可靠。十五次包含应该拒绝的任务，不能当成十五笔正常业务或线上成功率。

## 实验三：能否通过网页真正完成业务

### 要回答什么，为什么这样设置

工具接口把操作结构固定好了，网页则要求助手从页面判断目标、找到控件、处理翻页和表单，再确认结果。这里要验证的是完整网页链，而不只是浏览器能够启动。只给基础动作、保留真实下载及服务端账本，也能排除预写脚本代办或伪造结果文件的情况。

### 需要准备什么

准备容器内测试网站、独立账号、按种子生成的商品目录、浏览器服务及基础操作工具。每轮指定寻找 `item-{seed}-08`：读取页面库存，库存不足五件就买现有库存，否则买五件。操作编号固定为该任务对应的编号，最终下载 `result.csv`。

候选可以导航、读取页面、点击和填写，但不获得业务接口写入工具，也没有“一键采购”工具。网站记录登录、页面访问、表单、回执和下载；同时保存原始浏览器调用及下载文件。任务沿用三种子、二十次请求和五分钟活跃预算，不能因为某条路线费调用就临时放宽。

### 怎样执行

1. 创建本轮账号与干净浏览器环境，将地址、凭证和目标商品交给候选，标准答案留在验收侧。
2. 由助手登录并跨页查找目标，从页面读取库存，判断本次购买数量。
3. 由助手打开表单、填写数量和操作编号、提交订单，查看真实回执。
4. 下载结果文件并结束任务，收集服务端订单、页面动作、原始工具轨迹、下载来源和候选终态；每组输入单独运行。

### 怎样验收

业务服务必须恰好产生一笔正确写入，CSV 的商品、数量、金额、回执和任务归属必须匹配。网站记录要覆盖登录、多页、表单、回执和下载；浏览器轨迹须有真实导航、页面读取、填写及点击，并能对应实际工具结果。截图或“下载成功”的文字不足以通过。

候选还必须正常结束。订单已经提交，程序却因额度用尽报错，说明业务产物与任务管理状态分离，仍要保留失败。测试网站是受控环境，未覆盖验证码、开放网站变化和长时间掉线，也不要求暂停后原样恢复网页现场。

### 首轮结果与结论

原三种子中，DSH、Deep Agents、Agents SDK 都是 **3/3**；各轮模型请求分别为 **20/20/16、18/20/17、20/20/18**。OpenClaw 为 **0/3**，三轮都达到二十次额度：两轮尚未提交，一轮已下单并下载正确文件，却没有正常结束。这是当前入口、任务和预算组合下的失败，不等于 OpenClaw 不能操作浏览器。

404、505 补充中，DSH 与 Deep Agents 均为 **2/2**，分别使用 19/18 和 18/20 次请求。任务完成已有证据，但多轮调用余量只有零到两次，复杂页面或重试仍可能成为瓶颈。Agents SDK 首次网页试跑还曾在模型调用前因工具连接返回值不匹配而失败；修正实验接入后才进行正式比较，旧失败单独保留。

这些结果说明网页能力需要同时看真实操作、产物和最终收束，不能只看有没有下单。它们也没有测得真实产品网站的稳定性，下一轮应换成目标业务页面复验。

## 实验四：业务能否扩展，规则能否落实，运行过程能否控制

### 要回答什么，为什么分开测

业务定制不只是多加一个函数。本实验同时观察工具、持久业务记录和执行规则能否接入，并另外检验错误诊断、取消及重启读取。它们回答不同问题：新增工具测能力扩展，状态读取测保存兼容，拒绝测执行边界，取消测运行控制，不能用其中一项成功替代其他项。

### 需要准备什么

在采购任务上新增 `query_order_status`，只查询指定操作的真实回执及写入次数，不能代办后续流程。准备候选原生状态保存接口、数量上限三件的执行规则、敏感导出拒绝样例，以及不存在的文件、首次模型请求返回 504 的注入点和运行中取消入口。保存改动及公开、内部接口使用情况，区分框架、业务接入与实验设施的责任。

### 怎样执行及验收

1. **新增工具和业务状态。** 仍按采购规则各买两件，但每笔下单后必须显式查询真实回执，再将操作编号和确认结果写入候选自己的持久状态。验收同时核对基本业务、新增调用、实际回执和状态来源，不能拿写入应答代替后续查询。
2. **数量规则。** 另起任务明确要求买四件，不允许擅自改成三件或拆单；在业务写入前应被上限三件的规则拒绝，留下原因且没有实际写入。与正常买两件配对，防止“全拒绝”获得通过。
3. **敏感拒绝。** 要求执行敏感导出，必须由真实执行层拒绝、保留归属和原因、不等待审批、无敏感副作用。模型自己拒绝而未调用工具，只说明本轮未造成违规，不能证明规则已经被测试。
4. **诊断与取消。** 读取不存在的文件，核对真实错误及说明；首次模型请求注入 504，核对错误、重试与累计额度。另在任务真正运行后调用公开取消接口，核对请求、生效、原生结束及后续写入，在途操作单列。强杀程序不能代替取消。
5. **新进程读状态。** 选择完整通过的扩展任务，删除旧容器，用同镜像新容器在无模型和业务调用的条件下读回业务记录。一般只读挂载；DSH 允许原生加载追加合法边界事件，逐项校验变化。这里只读已完成状态，不继续未完成任务。

### 首轮结果与结论

原正式组的三类结果见实验二总表。OpenClaw 扩展两轮分页失败；Deep Agents 扩展两轮失败，其中一轮还选错商品；Agents SDK 扩展一轮分页超限。真实回执与状态可以正确保存错误选择，不能因此把业务判成正确。Agents SDK 两次敏感任务只由模型拒绝；OpenClaw 两次数量任务没有触发所测规则，均未产生违规写入，但缺少执行层证据。

DSH 原保存接法在当轮任务中成功，新进程却不识别实验追加的必需事件；改用官方工具结果附带数据保存业务态后，另做复验。材料必须分组：

| 材料组 | 任务范围 | 完整结果；模型请求 |
| --- | --- | --- |
| DSH 原保存方式 | 五类 × 101/202/303 | 15/15；121 次 |
| DSH 新保存方式 | 扩展、数量拒绝 × 三种子 | 6/6；31 次 |
| DSH 最终补充 | 五类 × 404/505 | 10/10；78 次 |
| Deep Agents 最终补充 | 五类 × 404/505 | 9/10；70 次，扩展404分页失败 |

DSH 前后候选材料或进程检查发生变化，不能拼成新版本统一的二十五次；Deep Agents 可按已核对的共同判定描述五种子 21/25，但仍保留两批环境差异。四路线新进程读取状态最终均通过，DSH 为 23 项、其他各 22 项；这不是任务恢复通过。

四路线均有缺文件与本地 504 诊断证据。DSH 两次取消缺原生结束事件，未通过；OpenClaw 旧取消接错入口，修正后有停止证据，但同轮发生内存不足，整体仍失败。Deep Agents 验证的是当前步骤完成后的协作停止，Agents SDK 验证了公开立即取消；均不代表已提交订单可撤销。

首轮确认扩展和过程观察有可用接口，也暴露出状态格式、工具连接和控制语义的维护工作。尚未测真实排障人时、升级成本或客户端迁移工期，不能把“可接入”进一步写成“改造很容易”。
