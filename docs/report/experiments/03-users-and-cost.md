## 实验七：多人使用与访问控制

### 要回答什么，为什么这样设计

一个助手能独立完成任务，不代表它能直接成为多人使用的云端服务。这项实验检查：A、B 同时工作时，能否各自查看状态、事件和文件，暂停、恢复或取消自己的任务；A 把目标换成 B 的任务后，服务是否拒绝请求，而且没有泄露 B 的内容、改变 B 的任务。

因此要同时有“本用户成功”和“跨用户拒绝”两组证据。所有请求一律拒绝，不能算权限系统正确；只把输出目录分开，也不能证明控制请求不会落到另一个任务。断线重连和更换执行程序后还要再核对归属，避免权限只在第一次创建任务时有效。

### 需要准备什么

先建立一个小型模拟产品后端。它从请求携带的身份凭据识别用户，保存“任务属于谁、对应哪个原生任务、状态存在哪里、由哪个任务执行程序执行”的可信映射。客户端只能提交任务编号和操作，不能自己指定宿主路径、任务执行程序或信号目标；请求正文中的 `user_id` 也不能覆盖认证身份。

A、B 分别有凭证、工作区、状态库、会话和调用预算；每个活跃任务使用独立工具服务与模型代理，远程模型密钥只留在代理侧。后端不直接持有 Docker 控制权，容器创建和删除由可信宿主编排完成。

专项入口要先固定源码、镜像、模型和资源档位，再完成同入口单任务基线。总配额不超过 6 GiB / 3 CPU；每个逻辑任务最多 300 秒活跃时间、20 次模型调用、2 次重试，恢复沿用原预算。正式关键路径使用 101、202、303 三组独立材料。真实浏览器账号、登录信息和运行环境隔离另需实验，不能用配置中的账号名代替。

### 实际怎样执行

1. **准备四个任务。** A、B 的业务主任务用于验证连续执行、暂停恢复和重连；另为 A、B 各设一个取消子任务。不能先取消主任务，再重新提交一次，称作“原任务恢复”。
2. **同时放行业务任务。** 两个真实任务执行程序就绪后一起接收输入。记录双方模型和工具活动的交集；容器同时存在、任务同时排队都不算有效并发。
3. **核对本用户读取和跨用户拒绝。** 状态、事件、产物要与保护侧读取的原生状态、实际文件一致，产物须由任务真实生成。A 对 B 的查看状态、读取事件、读取文件、暂停、恢复、取消六种操作都要实际发出。已有的他人任务应返回固定无内容的 403；错误凭证的 401、目标不存在的 404不能替代越权测试。
4. **核对拒绝没有副作用。** 请求前后独立记录 B 的状态、文件、控制记录和业务账本。运行中的任务会自然变化，所以部分探针放在真实只读工具等待响应的稳定窗口中；这不是原生暂停，也不用于证明并发。跨用户恢复则必须等 B 已被合法所有者真正暂停后再测。
5. **暂停、换任务执行程序、重连。** 合法暂停后等原生状态安全保存，删除旧任务执行容器，用新任务执行程序从原状态继续，不重放最初提示词。另关闭客户端连接，再建立新连接、重新认证，检查同一任务仍可访问；新连接访问 B 仍须实际得到 403。
6. **独立验证取消并收尾。** 两个取消子任务进入真实活动后，先测跨用户取消被拒，再测本用户取消。保留已发出调用的实际副作用，检查取消确认后不再派发新写入。最后独立验收业务、原生控制、权限、并发、资源生命周期和清理结果。

### 怎样算通过

完整通过要求原业务结果正确、本用户查询和控制有效、六类跨用户请求全部拒绝且不影响目标、重连后归属不变，并具备真实并发和可靠资源记录。服务接受请求不等于框架已经完成动作；任务暂停后保存了一份文件，也不自动证明新进程能接着执行。

同一任务执行程序在用户 A→用户 B→用户 A 之间复用是另一个设计目标，需要证明旧绑定、缓存、凭证和文件不会残留。首轮没有完成这项验证，不把删除旧容器、创建新容器称为复用。

### 实际结果与结论

| 路线与材料 | 已取得的结果 | 仍然不能推出什么 |
| --- | --- | --- |
| Deep Agents / LangGraph，更换执行容器后的三组正式实验 | 三组权限边界、真实并发、重连、跨用户拒绝、资源生命周期及取消子试验通过。101 的 B 主任务业务失败，整体失败；202、303 各 20 次模型调用，完整通过，三组为 **2/3** | 不能把局部机制通过写成三组业务全过，也不能外推生产多租户系统 |

Deep Agents 的取消采用原生执行步边界的协作停止：等待当前边界安全收束，再禁止继续调度。它不是立即中断所有在途动作，结果通过也没有改变这一语义。DSH 的删除采样失败同样需要具体解释：采样时旧任务执行容器正在删除，实际消失确认晚约 21 毫秒；不能把它描述为误删其他用户任务。

本实验支持“所测 Deep Agents 接法已证明若干多人服务必要机制”。生产身份系统、浏览器使用期隔离、同一任务执行程序换用户复用均未验证；DSH 没有形成完整的多人实验通过结论。下一项成本实验使用另一套常驻入口，也不能直接继承这里的权限结论。

## 实验八：持续运行与按需启动的资源比较

### 要回答什么，为什么这样设计

云端会有大量暂时不工作的用户。实验要区分“正在做多少工作”和“保存多少用户”：固定两个活跃任务，把用户总数设为 2、5、10，比较每用户常驻真实执行程序与只保存状态、来任务时启动任务执行程序两种方案。减少任务、改成串行或只保留空壳进程，都会改变比较对象。

“每用户常驻、不回收”是明确设置的对照假设，不是已经确认的现网事实。首轮实际接入 Deep Agents；DSH 没有完成这条成本流程。

### 需要准备什么

每组配对固定候选入口、镜像、模型、工具、种子、任务和总配额。常驻方案保留最近真实业务自然完成后使用的执行图、模型客户端、工具连接和状态保存对象；按需方案正常关闭这些对象、删除任务执行容器，但保留同一份业务状态。用户之间的目录、凭证、历史和预算全部独立。

历史准备通过真实原生接口完成，可以不调用模型；它只证明状态可准备，不能计作完成业务。测量前还要验证观察器、阶段记录、资源清单、独立评分和精确清理可靠。第三次不调用模型的生命周期校准留下35份样本、23项检查通过，才进入五用户探索；之前两次失败仍保留。

观察器本身占 256 MiB / 0.25 CPU 档位，连同模拟业务服务、工具和代理计入资源清单，但它不提供用户认证，不能冒充产品后端。真实产品后端开销、宿主虚拟机开销和存储费用未形成完整计量。每个任务执行程序固定分配 2 GiB / 0.75 CPU，总预算仍为 6 GiB / 3 CPU；常驻五、十用户方案因声明配额超限在启动前被拒，没有启动实验容器，也没有实际内存用量或内存不足结果。

### 一轮的阶段与验收

| 阶段 | 执行动作 | 要验证的事情 |
| --- | --- | --- |
| 全部空闲，60秒 | 常驻保留 N 个真实任务执行程序；按需没有任务执行程序，只保存独立状态 | 空闲用户的实际资源负担，不能漏算共享服务 |
| 两个任务活跃 | 同时执行同口径业务任务 | 双方真实活动和工具进展重叠，重叠内至少有两份资源样本 |
| 结束并回收，60秒 | 常驻保留原对象；按需正常关闭并删除；两边都停止工具和代理 | 回收是否真实完成，以及结束后的空闲占用 |
| 原业务状态读回 | 常驻从原对象读；按需启动新任务执行程序读原状态库 | 同一份已完成业务状态仍在，不是恢复未完成任务 |
| 新任务唤醒 | 两用户分别收到新任务、独立的数据范围和预算 | 从可信请求记录到就绪、首次原生活动的时间；没有产品队列，不评价队列时延 |
| 更多用户轮换 |五、十用户设计在001/002结束后唤醒此前未做业务的003/004 | 空闲用户确实可开始工作，最多仍为两个活跃任务；其余用户仅保留历史 |
| 单个执行程序故障 | 两个新故障子任务真实活动后，只强制退出 A 的执行程序，观察 B | 精确故障对象、A 退出后 B 的原生进展，以及 B 最终业务是否正确 |
| 独立评分与清理 | 停止付费和分发路径，读取账本、预算及资源证据 | 评分进程健康、结果与退出码一致，确切容器及网络已清理 |

故障阶段不恢复 A，原状态、原预算和在途不确定性都保留。因此，不能把“唤醒新任务”和“B 没被连带终止”写成 A 已成功恢复。

采样以两秒为目标，全部阶段间隔不得超过五秒。每份样本核对前后完整容器清单、配额、内存与进程，不能漏掉同镜像的另一个任务执行程序；缺测不能填零。业务正确、生命周期成立、观测完整三者同时满足，才可能形成完整成本结论。

### 实际结果与结论

两用户配对完整执行，按需与常驻各有五个可评分业务任务，均为 **3/5**，分别留下33、34条请求计数；被强制退出且无结果的 A 不计业务成功分母，其已发生消耗仍保留。原业务状态读回、新任务唤醒、真实活动重叠，以及 A 被强制退出后 B 仍继续执行均有证据，但故障 B 的业务失败，整轮均未通过。

| 两用户观测项 | 按需启动 | 每用户常驻 |
| --- | ---: | ---: |
| 初始空闲平均总内存 | 31.41 MiB | 282.10 MiB |
| 回收后空闲平均总内存 | 47.85 MiB | 312.63 MiB |
| 两个空闲阶段容器数 | 2 | 4 |
| 两次新任务首次原生活动耗时 | 21.08 / 21.06秒 | 13.26 / 13.26秒 |

这些是已观测窗口的描述。按需唤醒在本实验中慢约八秒，包含服务准备时间，不能直接当生产接口延迟。补审计发现旧判分只约束空闲窗口采样节奏：按需136份样本有18处间隔超过五秒，最长23.670秒；常驻140份有14处，最长23.598秒，另有起止和线程完成证据缺口。两份补审计均失败，不能用表中均值推出完整峰值、总成本或节省比例。

五用户按需轮换也已结束，七个可评分业务 **4/7**。此前未活跃的003/004首次任务均通过；三个失败任务只因请求 `page_size=100` 违反每页最多五条的协议。它们返回了全部19件商品，报告和实际写入正确，因此这里不能写成“漏读”。实际只强制退出 A 的执行程序，B 随后仍继续执行；故障复合项失败来自 B 的业务协议验收，不是 B 停止运行。

五用户的148份样本无采样错误，五秒节奏、登记、原状态及预算保留、评分健康和清理检查通过；但回收后空闲阶段有 **29份完整、1份不完整**。第82份样本开始时只有模拟业务服务和观察器，结束时下一阶段用于读取旧状态的执行容器已启动，但缺少该容器的当次资源记录。不能删除这份样本、改阶段或补零，整阶段均值与峰值保持未知。

所以五用户仍是失败的探索轮，十用户未运行，首轮在此收尾。现有结果支持“按需回收降低了所测空闲窗口占用，同时增加启动等待”的初步判断；完整收益、生产容量、三组输入的配对比较、常驻入口的权限验证和真实产品后端费用均未建立。

## 实验九：模型用量与建设维护投入

### 要回答什么，为什么这样设计

一次任务成功之前，失败、重试和接线诊断也会消耗模型调用。一次调用又可能携带很长的历史，不能简单把“调用少”理解为“费用低”。这项工作分别统计请求记账、模型 token、运行资源以及必要工程改造，回答当前投入能被证据支持到哪一层。

token 是模型处理文本的计量单位，不固定等于一个汉字、一个单词或一次请求。输入通常包含任务、历史和工具信息，输出是模型生成内容；缓存和推理计数还涉及不同的子项口径，必须按供应商实际返回统一。

### 准备、执行与验收

1. **冻结已经结束的材料清单。** 成功、失败和中止都登记确切预算库、任务范围、原件哈希和结束依据；恢复前后的 A/B 若共用一个账本，只计一次。不能扫描到一个库就自动纳入，也不能在写入仍进行时统计。
2. **独立读取请求记账。** 在断网、只读、无模型密钥的容器中，读取限定的五列请求元数据，按远程200、远程结果未确认、在途未知、模拟、本地注入分类。200 只表示请求记录，不等于业务成功；未知也不等于零。
3. **另行提取原生用量。** 从框架保存的模型用量字段读取数字，不根据输出长度估算。按各候选的响应身份去重，避免同一响应的分块、最终消息、状态副本及恢复历史重复累计。没有供应商计数的默认零保留为未知。
4. **统一字段。** 缓存读取是完整输入的一部分，推理 token 是输出的细分，不能再次相加。缺失用空值，冲突保留原件；没有预算行与原生响应逐条关联证据，就不计算请求覆盖率。
5. **限定比较分母。** 只有同任务、同变体、同模型、同材料和预算的一组，才能用“全部尝试消耗 ÷ 完整成功业务任务数”。失败消耗不能删除，取消、拒绝和校准不能算业务成功；没有成功时只列总消耗及原因。
6. **盘点工程投入并核验产物。** 区分官方能力、必要产品接入、候选专用改造和实验设施，记录实际文件、依赖与维护点。统计容器须健康退出、确切清理，输入哈希不变，新截点不覆盖旧失败。提取程序成功仅证明本次计量过程通过，不代表完整费用已知。

### 实际结果与结论

首轮最终统计（第十版）登记 **343个独立预算库、2485条调用记账**，分类如下。第八、九版属于此前的累计截点，不能与第十版相加。

| 类别 | 条数 | 含义 |
| --- | ---: | --- |
| 远程请求记录为200 | 2416 | 已转发并取得200记录，仍须另看任务结果和用量完整性 |
| 远程结果未确认 | 4 | 含断连，不能补成成功或零消耗 |
| 仅留下预留记录 | 1 | 在途结果未知，付费进程已经清理 |
| 内网模拟请求 | 36 | 不是远程模型消耗 |
| 本地故障注入 | 28 | 与真实远程请求分列 |

已知部分为 **10,253,403 token**：输入9,590,870，输出662,533。缓存读取6,105,600已包含在输入中，推理计数163,614已包含在输出中。这些不是研究完整总量，也不是账单金额。

当前还有17个预算库只列路径、未查询：DSH多人实验7个、五用户成本实验8个、旧Deep Agents多人实验2个。没有原预算库的直接探针、已删除临时库等也不在统计范围。未登记不表示零消耗；缺少请求级关联、完整模型用量和可核验价格，不能据这些数字给候选排费用名次。

工程盘点确认，云端能力不是只换启动命令：DSH 需要处理保存格式兼容，以及持久任务何时停止、何时继续；Deep Agents 需要连接进度读取、任务控制和持续运行入口；OpenClaw 需要接通后台服务控制及工具插件；Agents SDK 需要处理工具连接版本、任务状态保存和真实结束状态。这些都是具体的接入与维护工作，资源采样和实验阶段交接也产生了额外改造。

这些改造有代码和原件可追溯，但首轮没有可信人工工时、完整建设费用或实际升级维护实验。代码行数不能换算工时，带缓存的构建耗时也不能充当研发时间。因此完整费用与投入计量仍未完成；已交付的是可核验的已知用量和工程缺口，而非金额、节省比例或长期维护承诺。
