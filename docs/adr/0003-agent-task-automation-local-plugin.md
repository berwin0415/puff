# 0003 Agent 任务自动化采用通用核心、宿主适配和外部能力绑定

- 状态：已接受
- 日期：2026-11-26
- 依据：[v0.1 PRD](../agent-task-automation/v0.1/prd.md)、[技术设计](../agent-task-automation/v0.1/technical-design.md)

## 背景

产品需要扩展现有 Agent 客户端，让用户把任务、交付和通知能力绑定到工作区。不同 Agent 的安装、会话、定时和权限能力不同。任务平台和代码平台也由用户实际环境决定。

用户在安装后选择自己的 skill、MCP、CLI 或宿主能力。业务平台的接口、认证和字段规则由所选能力管理。

## 决策

1. 插件核心只提供安装引导、能力引用、工作区绑定、任务上下文、执行规则和结果模板。
2. 宿主适配独立负责安装、onboarding、工作区上下文、Scheduled Task、会话和权限。Codex 是 v0.1 首个宿主。
3. 外部能力以 CapabilityBinding 引用接入。核心校验角色、类型、操作和启用状态，平台规则由绑定能力处理。
4. 工作区绑定保存路径、worktree、自动执行、运行窗口、活动任务上限和能力引用。
5. Agent 负责调用用户选择的能力完成任务源、代码交付、通知和评审动作。
6. iCafe、iCode 属于用户绑定的外部 skill 示例，不进入核心配置、依赖、宿主适配或业务流程代码。
7. v0.1 不创建业务连接器、业务 API 层、MCP 业务网关、CLI 代理或任务数据库。
8. v0.1 将通用核心和 Codex 适配分别放在同域库 `@puff/agent-task-core` 和应用 `@puff/codex-plugin`。应用通过包公开入口依赖核心，并实现核心定义的宿主接口。

## 后果

- 核心库独立构建和测试。Codex 应用在构建时装配核心资源，用户安装该应用生成的插件产物。接入后续宿主时，新应用复用同域核心库。
- 更换任务平台或交付平台只需更换用户绑定能力，不修改插件核心。
- 核心无法独立验证业务结果，结果和权限由外部能力负责。Agent 必须在工作流中处理能力失败和结果未知。
- 工作区是执行与授权配置的边界。插件可以保存多个工作区，每个工作区可配置不同能力、任务范围和计划。每个工作区独立占用活动名额，跨工作区调度策略仍属于后续规划。
- v0.1 的真实验收需要当前 Codex、当前工作区以及用户选择的外部能力共同参与。

## 验证条件

- Codex 能加载插件 manifest、setup skill 和 task-run skill。
- 当前 puff 工作区能完成绑定和只读试跑。
- 用户选择的能力能够被 Agent 读取和调用。
- Scheduled Task 能关联用户确认的工作区，在触发时读取当前绑定和能力引用。
- 核心配置和代码不包含具体平台字段、API、凭据或业务状态逻辑。
- 两个项目的公开入口、依赖方向和打包后的共享资源引用通过检查。
