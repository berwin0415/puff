## 1. 范围调整依据

最新接入原则：已有Skill时优先由Agent直接使用，生成的首先是绑定、上下文和工作流指令，不重复生成CLI/API客户端。下文保留此前通用生成研究，仅当既有合法能力不能覆盖场景时再评估，不是现行首版主路径。

v0.1 在当前仓库验证 Codex 适配、工作区绑定与安装后选择能力的流程。iCafe、iCode 是内网用户可选择的已有能力示例。v0.2 规划涵盖公开试用、其它宿主适配和面向能力缺口的生成探索。

| 从首版移出的范围 | 后续处理 |
| --- | --- |
| 本地任务文件、Git 补丁独立交付及外网样例 | 作为公开版参考接入，单独验证无需内网也可运行 |
| 通用 API/MCP/CLI/skill 连接器生成 | 根据用户资料生成，不等待官方预置平台实现；详见 §3 |
| 多 profile、多账号选择与隔离 | 作为独立能力设计。当前登录由宿主及所选能力管理 |
| 通用 Webhook 通知及更多通知渠道 | 验证渠道协议、收件范围、凭据与结果核对 |
| 公共包分发及公开与私有能力隔离 | 在首版安装引导基础上验收对外分发与私有资源边界 |
| DSH、Claude Code、更多运行形态 | 分别验证宿主安装、调度、会话、权限和用量能力 |
| GitHub、GitLab、Jira、Linear 官方维护接入 | 可选模板或实现，与用户自行生成接入分别维护 |
| 连接器自动重新生成和版本回退 | 验证活动任务与旧版本兼容，再提供完整生命周期管理 |

v0.2 的范围和优先级根据 v0.1 的宿主、工作区与能力绑定验证结果确认。

## 2. 公开与内网私有边界

- 公开产品提供通用核心、生成向导、协议与公开参考接入，不包含当前 iCafe/iCode 专有实现、内部依赖、企业地址、身份、凭据或接入资料。
- 当前内网接入只在用户有权限的环境中，根据用户提供的资料或已有工具生成、验证和执行；公共服务不代理访问当前内网。
- 生成工具可以公开，用户生成的代码、配置、资料和报告默认用户私有，不自动上传或进入官方公共包。
- 外部用户可在自己的授权环境生成连接器，不能因安装公开产品获得当前内网访问权。
- 多账号是后续产品能力，内部服务仍独立校验每个身份和资源权限，不能用前端选择或网络位置替代认证。
- 公开版默认示例不涉及当前企业服务，安装和试跑不依赖内部账号。

## 3. 通用连接器生成设计（从原 v0.1 草案迁入）

**目标：**用户说明要接入的系统并提供足够资料，宿主 Agent 帮其生成符合产品契约的本地连接器。用户不必手写适配代码，也不必等待官方提供该平台连接器。

### 3.1 触发入口

- 宿主支持安装引导时，展示“配置接入”入口；用户进入现有聊天后由生成 skill 收集资料。
- 宿主不支持安装引导时，在首次使用或发现未配置连接器时启动对话向导。
- 首次使用以用户明确调用为前提；用户跳过后记录提示状态，不在定时任务和普通对话中反复提问。配置失效只标记阻塞，用户主动修复后才重新生成。
- 不假定安装脚本可以直接启动模型或取得用户全部文件、账号与网络权限。
- 用户也可主动要求新增任务源、交付或通知接入，或修复失效的已有连接器。
- 资料收集与生成不注册定时计划、不领取业务任务、不修改真实业务状态。

### 3.2 用户提供什么

按“任务源、交付、通知”分别收集，只询问当前接入所需的信息：

| 输入 | 可接受形式 | 缺少时的处理 |
| --- | --- | --- |
| 系统与用途 | 平台名称、目标接入角色、希望执行的动作 | 先明确读取、回写、提交或通知目的 |
| 已有能力 | 用户选择的 MCP 工具、CLI 路径、skill 或已有连接器 | 询问是否提供 API 文档，不扫描全部本地能力 |
| 接口资料 | 用户指定的文档链接、本地文档、OpenAPI、命令帮助、脱敏请求和返回样例 | 列出缺少的具体接口或参数，不编造地址 |
| 业务语义 | 稳定任务 ID、状态、验收字段、分页、提交与查询流程 | 询问映射关系或明确不支持的能力 |
| 认证 | 已有登录身份、凭据存储引用、允许的连接目标 | 引导使用认证工具或安全存储，不要求把秘密粘贴给模型 |
| 验证范围 | 只读样例、测试仓库或卡片、可用沙箱、允许的测试动作 | 默认只读或离线验证，写能力保持未启用 |

用户可以按需提供一种资料来源，不要求同时具备 MCP、CLI、skill 和 API 文档。向导仅读取用户指定或已授权的资料；任务正文中的链接不能自动成为新接入来源。

### 3.3 如何生成

1. 识别用户选择的能力，优先复用已有 MCP、CLI 或 skill，生成参数与返回结构的薄适配。
2. 没有可复用工具时，依据用户提供的 API 契约生成实现；资料不完整时先列出缺失项。
3. 按接入角色形成标准操作：任务查询、详情、结果回写；交付准备、发布与结果查询；通知发送与结果确认。
4. 明确哪些操作真实存在、哪些操作不可验证，以及源系统是否支持条件领取、版本检查或去重。不能生成虚假的原子领取或提交查询能力。
5. 保存草稿代码、契约、配置模板与验证用例，展示动作、调用目标、依赖和待确认事项。
6. 依赖安装、新增网络目标或真实写入仍受用户授权和宿主规则约束，不能在生成过程中静默执行。

生成结果至少包含：

- 本地连接器实现或已有工具绑定，连接器 ID、版本和角色。
- 输入输出契约、错误转换、能力声明、访问目标与凭据引用方式。
- 配置模板、字段映射与资料来源记录；不包含凭据值。
- 来自用户资料或实际观察的脱敏样例与验证报告，不编造测试通过记录。
- 尚未实现或未验证的能力，以及下一步需要用户补充的信息。

生成只写入用户的连接器数据目录或指定的接入项目，不修改产品核心和宿主自身。默认结果是用户私有，不自动加入公共连接器库。

### 3.4 验证与逐项启用

| 步骤 | 检查内容 | 允许的结果 |
| --- | --- | --- |
| 契约检查 | 必要字段、稳定 ID、错误类型、能力声明、未知结果处理 | 不符合契约则修复或保留草稿 |
| 离线样例验证 | 使用指定样例检查字段映射与错误转换 | 只证明样例转换通过，不证明真实系统可用 |
| 真实只读连接验证 | 当前身份、允许目标、列表与详情、权限和分页 | 验证通过后只启用已核对的读能力 |
| 指定资源上的写验证 | 明确测试目标，检查回写、交付或通知动作及实际结果 | 仅启用验证通过且已授权的具体写能力 |
| 执行 profile 试跑 | 入选任务、仓库映射、验收、交付范围和通知目标 | 用户确认后才进入自动任务执行 |

生成器与验证器不能仅用同一段生成代码的返回值自证成功。应按通用契约核对用户资料和实际结果；真实写入后，通过独立读取或目标系统中的成果确认结果。

没有测试环境或用户未授权写验证时，可以保存连接器并使用已验证的只读能力。提交、回写和通知写能力保持关闭。网络不可达、身份无效或接口缺失不能用模拟响应替代真实验证。

### 3.5 生命周期与重新生成

| 接入状态 | 含义 |
| --- | --- |
| 未配置 | 没有指定接入或资料 |
| 资料收集中 | 缺少必要接口、字段或授权信息 |
| 已生成待验证 | 已有本地草稿，没有完成实际连接核对 |
| 只读可用 | 契约与真实只读操作通过，写能力未启用 |
| 按能力启用 | 指定动作已验证并授权，其他能力仍关闭 |
| 验证失败或已停用 | 接口变化、身份失效、配置冲突或用户停用 |

这些是连接器接入状态，区别于功能开发状态和任务运行状态。产品显示每种能力的验证结果，不能用一个“连接成功”标记代表全部动作可用。

接口资料、工具版本、字段映射或实现变化时，由 Agent 生成新版本并重新验证。旧版本与关联 profile 保留以便回退；新版本不覆盖正在运行任务使用的版本。旧版本只有重新符合当前接口与授权时才可恢复，回滚代码不等于恢复认证或服务兼容性。

### 3.6 内网资料与模型处理边界

内网用户可以通过已有 skill 绑定 iCafe 或 iCode。若后续探索适配生成，使用范围以用户有权提供的资料和工具为准。内部服务继续校验身份与资源权限。

文档和脱敏样例可能进入宿主模型上下文。向导应说明所用宿主及资料处理方式，用户只提供组织允许交给该 Agent 和模型的资料；本地保存生成代码不等于模型在本地推理。凭据值不进入生成提示、代码、样例或报告。

生成失败时保留草稿和缺失项，允许补充资料、选择已有连接器或人工修正。不得扩大网络范围、切换身份、自动发布生成物或绕过验证以完成接入。


## 4. 后续验收规划

| 范围 | 验收依据 |
| --- | --- |
| 公开首次使用 | 外网用户不用内部 CLI 或账号，可完成公开样例并得到可核对成果 |
| 通用生成 | 使用用户指定的 API 文档、工具和脱敏样例生成连接器；资料不足时说明缺失项 |
| 多账号与多配置 | 显式选择身份，任务与凭据不串用；失败不回退到其他身份；切换需重新核对权限 |
| 写能力启用 | 只读通过不等于写能力可用，指定资源上的写验证要确认实际结果 |
| 分发隔离 | 公开包、依赖、默认配置、工具发现和服务均不包含当前内网访问通道 |
| 更多宿主 | 同一业务连接器在各宿主通过对应兼容测试，不假定同名 CLI/桌面/云端一致 |
| 生命周期 | 新生成版本不覆盖活动任务，停用、迁移和回退保留事实及授权记录 |

这些不是 v0.1 的验收项。实施时再形成对应版本 PRD、兼容清单和可执行测试。
