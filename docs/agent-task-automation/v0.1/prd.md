# Agent 任务自动化插件 v0.1 PRD

| 项目 | 内容 |
| --- | --- |
| 目标版本 | v0.1，Codex 宿主和工作区绑定验证 |
| 状态 | 已实现可安装产物，按验收表跟踪实际运行 |

| 首个验证工作区 | 当前 puff 仓库，安装后通过工作区绑定选择 |

插件核心不实现具体业务平台连接器。用户安装后选择已有 skill、MCP、CLI 或宿主能力，Agent 使用这些能力完成业务操作。

## 1. 产品目标

- 在现有 Agent 客户端上配置任务自动化。
- 让用户把任务、交付和通知能力绑定到指定工作区。
- 让 Agent 按工作区规则处理任务。
- 使用宿主 Scheduled Task 周期唤醒。
- 输出任务、验证、交付和待处理事项。
- 为 DSH、Claude Code 等宿主保留适配边界。

## 2. 首版能力

- Codex 宿主适配。
- 插件安装和 onboarding。
- 多工作区发现与绑定。
- 能力引用配置。
- 任务源、交付、通知和评审能力绑定。
- 工作区执行规则。
- 手动和定时触发。
- 任务上下文和结果模板。
- 工作区级暂停和恢复。
- 宿主运行结果展示。

iCafe、iCode 只作为用户绑定的外部 skill 示例。它们不进入插件核心配置、依赖或业务流程代码。

内网验证沿用现有单用户登录环境。宿主及用户绑定的能力分别管理登录和业务权限，核心配置仅记录工作区、规则与能力引用。

## 3. 产品形态

v0.1 由两个同域项目组成。通用核心库提供配置、任务工作流、工作区与能力绑定、任务上下文和结果模板。Codex 插件应用提供 manifest、setup 入口、工作区发现和计划适配，并把核心工作流与模板装入插件产物。

插件安装后通过 onboarding 引导用户配置。配置保存宿主类型、工作区、能力引用和执行规则。

项目目录、包依赖和打包方式见[技术设计 §2](./technical-design.md)。

## 4. 通用配置模型

| 配置部分 | 内容 |
| --- | --- |
| 宿主适配 | 当前宿主、适配版本和宿主计划关联 |
| 工作区绑定 | 用户选定的多个执行目录，每个工作区独立保存绑定 |
| 能力绑定 | 任务源、交付、通知及可选评审的类型、引用、允许操作和启用状态 |
| 执行规则 | 任务范围、允许修改路径、允许动作、工作区模式、时间窗口和活动任务上限 |

用户确认能力范围后保存配置，自动执行默认关闭。具体结构和示例见 [技术设计 §3](./technical-design.md)。

## 5. 安装与首次配置

~~~text
安装插件
→ 识别并确认 Agent 宿主
→ 选择工作区
→ 绑定任务源、交付和通知能力
→ 生成该工作区的执行规则
→ 只读试跑
→ 用户确认
→ 启用宿主定时任务
→ Agent 按绑定能力执行
~~~

setup 根据用户选择和宿主可用的工具说明生成配置。只读试跑展示候选任务、工作区和计划动作。能力缺失时说明缺少的操作，保留配置供用户调整。用户也可保存配置并继续手动使用。

## 6. task-run 工作流

1. 读取宿主上下文和工作区配置。
2. 检查工作区存在并可用。
3. 检查能力绑定状态和允许操作。
4. 加载任务源能力读取候选任务。
5. 读取任务详情并生成任务上下文。
6. 根据工作区规则确认执行范围。
7. 使用宿主 Agent 修改代码并验证。
8. 加载交付能力完成交付。
9. 通过同一交付能力查询实际结果，并按用户授权使用任务源能力回写。
10. 加载通知能力返回结果。
11. 输出结果和待处理事项。
12. 当前任务结束后释放工作区活动名额。

任务上下文包含工作区 ID、任务引用、任务描述和验收要求、目标仓库和分支、允许文件范围、允许交付动作、禁止动作、能力引用和当前运行时段。

## 7. 工作区规则

插件负责多个工作区的路径、worktree 模式、自动执行开关、最大活动任务数、时间窗口、修改范围、结果展示方式和宿主计划绑定。每次配置只追加或更新一个工作区，不能让同一真实目录同时对应多个工作区 ID。

外部能力负责任务字段、任务状态、交付对象、评审和回写规则、业务权限以及外部系统结果确认。

## 8. 宿主适配

Codex 适配负责插件加载、onboarding skill、工作区上下文、Scheduled Task、宿主会话和结果展示、宿主权限以及暂停恢复。

DSH 和 Claude Code 后续分别提供适配层。核心配置中的 host 类型和 workspace binding 结构保持一致。

## 9. 触发与恢复

触发入口包括安装引导、首次配置、用户手动执行、Codex Scheduled Task 到期、用户暂停恢复取消和宿主运行完成后的结果返回。

手动与定时执行共用工作区、能力、窗口和活动任务名额检查。定时执行还需该工作区启用自动执行。宿主无法确认活动任务状态时，允许只读检查并暂缓新任务写操作。

插件只判断通用条件。任务源、交付和通知能力负责各自的业务状态、权限和结果判断。外部结果未知时，Agent 使用同一个绑定能力查询。

## 10. 首版验收

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| AC-01 | 插件安装 | Codex 能加载 manifest 和 onboarding skill |
| AC-02 | 多工作区绑定 | 用户能保存当前 puff 仓库，并继续保存另一个目录的独立 workspace binding |
| AC-03 | 能力绑定 | 用户能绑定任务源、交付和通知能力引用 |
| AC-04 | 独立规则配置 | 不同工作区能保存不同的能力、自动执行、窗口和最大活动任务数 |
| AC-05 | 只读试跑 | Agent 能按绑定能力生成任务上下文，不执行未授权动作 |
| AC-06 | 手动运行 | Agent 能按 task-run 流程处理一次工作区任务 |
| AC-07 | 定时运行 | Codex Scheduled Task 能加载当前工作区和绑定能力 |
| AC-08 | 重复触发 | 活动任务存在时不再领取第二个任务 |
| AC-09 | 能力失败 | 能力不可用时阻塞并说明原因 |
| AC-10 | 工作区失效 | 路径不存在或权限不足时停止执行 |
| AC-11 | 暂停恢复 | 工作区暂停后停止新任务，恢复后按新规则运行 |
| AC-12 | 结果输出 | 宿主能展示任务、验证、交付和待处理事项 |
| AC-13 | 核心解耦 | 核心配置和代码中没有具体平台字段、API、凭据或业务状态逻辑 |
| AC-14 | 能力替换 | 用户可在同一工作区换绑兼容能力，重新试跑后使用新绑定 |
| AC-15 | 未知交付 | Agent 使用原绑定能力查询，确认前保持待核对 |

当前交付产物和实际验收进度见[功能清单](../features.md)。
