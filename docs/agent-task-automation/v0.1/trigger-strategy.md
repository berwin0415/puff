# Agent 任务自动化插件 v0.1 触发策略

| 项目 | 内容 |
| --- | --- |
| 目标版本 | v0.1 |
| 状态 | 运行门槛已实现，实际定时触发待验收 |
| 首个宿主 | Codex |
| 首个工作区 | 当前 puff 仓库 |
| 业务能力 | 用户安装后绑定 |
| 适用范围 | 安装、工作区绑定、手动执行、Scheduled Task 和停止控制 |

## 1. 触发类型

| 触发 | 来源 | 处理 |
| --- | --- | --- |
| install | 用户安装插件 | 提供 setup 入口 |
| configure | 用户首次使用或明确开始配置 | 确认宿主、工作区、能力和执行规则，支持只读试跑 |
| manual-run | 用户手动执行 | 加载工作区规则并执行 task-run |
| schedule-due | Codex Scheduled Task | 加载绑定工作区并执行 task-run |
| resume | 用户恢复工作区 | 重新检查工作区和能力 |
| pause | 用户暂停工作区 | 停止新任务 |
| cancel | 用户取消当前运行 | 使用宿主可用能力停止或标记待确认 |
| host-result | 宿主运行结束 | 展示结果和待处理事项 |

## 2. 触发门槛

手动或定时开始新任务时，按以下顺序检查。

1. 宿主适配可用。
2. 用户绑定的工作区仍然存在，当前执行目录与绑定一致。
3. 当前工作区配置有效。
4. 本次所需能力已由用户确认并启用。
5. 当前时间符合该工作区设置的运行窗口。
6. 该工作区的活动任务名额可用。
7. Agent 能读取并使用所绑定能力的说明。
8. 本次动作在工作区规则、能力和实际宿主权限允许范围内。定时入口还需自动执行已启用且计划属于该工作区。

只读试跑和状态查看可在启用计划前进行。任务源、交付和通知能力负责各自的业务状态、权限和结果判断。任务正文只能提供业务上下文，工作区、能力及操作范围以用户确认的配置为准。

## 3. 默认规则

- 自动执行默认关闭。
- 每个工作区最多一个活动任务。不同工作区的活动名额相互独立。
- 一个 Scheduled Task 关联一个工作区。到期时读取当前绑定，按用户选定的时区和窗口执行。工作日窗口的起点包含、终点排除。
- 同一工作区的手动与计划入口共用活动名额。忙碌时将同一工作区的重复计划触发合并为一次待检查，下一次有效触发重新读取状态。
- 活动状态由宿主确认。无法确认名额时，保留只读检查并暂缓新任务写操作。
- 工作区路径、宿主类型、能力引用或执行规则发生变化时暂停计划。
- 能力不可用时进入阻塞，不自动选择其他能力。
- 外部业务结果不明确时，Agent 使用同一个绑定能力查询。
- 宿主结果负责确认运行是否终止。已有任务仍可展示已取得的结果和待处理事项。

## 4. 工作区暂停与恢复

| 操作 | 新任务 | 当前任务 | 后续处理 |
| --- | --- | --- | --- |
| 暂停 | 停止该工作区的新启动 | 保留原运行，可另行取消 | 保留配置和结果 |
| 恢复 | 重新检查规则和能力 | 保留当前上下文 | 按确认后的配置恢复计划 |
| 取消 | 不启动 | 调用宿主停止能力 | 结果未确认时标记待确认 |
| 配置变更 | 暂停 | 按宿主能力处理 | 重新绑定并确认 |

## 5. 宿主差异

Codex 适配负责计划和工作区上下文。DSH 和 Claude Code 后续分别定义自己的安装、计划、会话和停止接口。

能力引用在宿主之间保持统一结构，实际发现、解析与启用由宿主适配负责。只读试跑、活动名额和停止结果的可观测性纳入 Codex 实现验收。

## 6. 验收

- 安装后用户能进入 setup skill 并进行只读试跑。
- setup 能绑定当前工作区。
- setup 能在已有绑定之外继续绑定其它工作区，并保留各自的规则。
- setup 能保存能力引用。
- 手动运行能携带工作区规则。
- Scheduled Task 能携带工作区规则。
- 运行窗口外不会自动启动。
- 定时计划关闭时，用户仍可在工作区规则允许的范围内手动执行。
- 工作区已有活动任务时不会启动第二个任务。
- 能力不可用时不会静默切换。
- 暂停和恢复状态可见。
- 结果能通过宿主返回给用户。
