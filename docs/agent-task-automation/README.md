# Agent 任务自动化插件产品文档

在现有 Agent 客户端上增加任务接入、工作区绑定、定时执行和结果汇报能力。插件核心处理安装引导、配置、工作区和执行规则。具体 Agent 宿主负责安装、会话、计划和权限。任务源、代码交付和通知通过用户选择的外部能力绑定。

v0.1 以 Codex 为首个宿主。当前 puff 仓库用于插件设计、开发和测试，也是首个工作区绑定验证目标。安装后的任务在用户选定的工作区执行。iCafe、iCode 是内网用户可选的已有 skill 示例。

源码按通用核心库和 Codex 插件应用两个项目组织。Codex 应用依赖核心库，并将共享工作流和模板装入可安装的插件产物。见[构建与本地安装](../../domains/agent-task-automation/apps/codex-plugin/README.md)及[项目划分](./v0.1/technical-design.md#2-目标文件)。

## 四层模型

~~~mermaid
flowchart LR
    H[Codex 宿主适配] --> P[通用插件核心]
    P --> W[工作区绑定]
    P --> C[外部能力绑定]
    H --> S[安装与 Scheduled Task]
    H --> X[宿主会话与权限]
    W --> R[工作目录与执行规则]
    C --> T[任务源能力]
    C --> D[交付能力]
    C --> N[通知能力]
    A[Agent] --> T
    A --> D
    A --> N
~~~

## 首次使用流程

安装插件 → 选择 Codex 宿主 → 选择工作区 → 绑定任务源能力 → 绑定交付能力 → 绑定通知能力 → 生成工作区执行规则 → 只读试跑 → 用户确认 → Agent 按绑定能力手动执行。用户可以另行启用 Codex Scheduled Task。

用户可以选择已经安装的 skill、MCP、CLI 或宿主能力，为每个工作区设置不同的绑定。

## v0.1 范围

| 内容 | 首版设计 |
| --- | --- |
| 宿主 | Codex |
| 工作区 | 安装后由用户选择，首个验证目标为当前 puff 仓库 |
| 能力绑定 | 用户选择已有能力，插件保存引用和操作范围 |
| 触发 | 用户手动执行、Codex Scheduled Task |
| 执行 | Agent 根据任务源能力读取任务，根据工作区规则执行 |
| 交付 | Agent 根据绑定的交付能力执行 |
| 通知 | Agent 根据绑定能力和宿主结果返回 |
| 状态 | 使用宿主运行上下文、外部能力结果和工作区配置 |
| 平台规则 | 由用户绑定的能力解释并执行 |
