# 后续专项先选哪两条路线

日期：2026-10-20。I21 已完成选择，I22 开始接线；本文不是暂停恢复、多用户隔离或成本的运行结论。

先选 **DeepSeek Harness 和 Deep Agents + LangGraph**，用于接下来的暂停恢复、故障和多用户成本验证。前者是用户指定的优先项目，后者用于比较直接控制执行图、checkpoint 的自建路线。选择两条符合实施计划的 2–3 条范围；先集中完成实际换容器续跑，暂不继续为四条路线同时建设完整运行平台。

完整数据和失败归因见各[详细报告](detailed.md)。DSH的原15轮与新接法6轮不拼成21种独立能力；四条路线冷读都没有执行未完成任务，不能当作恢复通过。

选 DSH 的理由是优先级明确、同题业务表现完整，并且可以直接验证“已有Harness迁移到云端还差什么”。代价是需要另外加载官方Goal及checkpoint插件，重新固定工具面和提示。当前取消缺口不会通过改名消失；Goal步边界必须先证明真实blocked结束、flush和正常关闭，否则保留失败。

选 Deep Agents 的理由是已实测公开RunControl、真实GraphDrained及同步checkpoint，下一步可直接验证从原图下一节点继续。任务事件、图状态和工具审计能对应，适合评估可观察、可定制的路线。正式任务仍有分页和业务选择错误，扩展代码、持久化、业务写入一致性及身份接入都需要维护，不能把可控制等同于效果最好。

Agents SDK 保留为轻量对照。它的工具、浏览器和扩展表现有竞争力，未进入本轮专项是投入范围选择，不能写成不支持暂停或多用户。后续若需要更轻的代码架构，可补测公开after_turn与完整RunState；现有脱敏诊断快照不能直接拿来续跑。敏感未触发表示本任务缺执行层测试证据，不是发生了违规写入。

OpenClaw 继续作为现有业务路线的比较基线。已有结果保留其分页、浏览器预算及取消OOM问题，同时承认它的执行层拒绝和业务态冷读已通过。当前所选HTTP任务入口没有已通过的安全暂停/新容器续跑，若现在进入全部专项，还要增加独立运行入口和生命周期接线。本次暂缓这些改造，不将当前每用户实例方式归因成框架只能这样部署，也不取消最终“继续改OpenClaw”的取舍讨论。

两条选中路线仍须分别完成同变体不暂停基线、实际写入后暂停、删除旧Worker、等待600秒、同预算新容器原生继续，以及三种子验收。故障窗口、可信身份接入、真实并发、浏览器使用期隔离及空闲用户成本全部待验；没有业务权重，不据此计算综合名次或现网节省比例。
