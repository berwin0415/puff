# 云端 Harness 调研：当前建议与改变建议的条件

日期：2026-10-21。本文为本轮I27条件化建议交付；依据[调研计划](../../RESEARCH_PLAN.md)、[实施任务表](../../IMPLEMENTATION_PLAN.md)和已结束实验报告整理。I23固定阶段已全部结束，结果包含业务失败；I24/I25未完成项按缺口收尾，本轮不继续修实验台扩跑。010断网Docker SQL/token已通过；完整计量、金额、人工工时及升级实验仍未知，I26本轮未完成，009历史原件保留。本文交付不表示已证实生产迁移、省钱或研发更少。

当前建议是：**继续把 DeepSeek Harness（DSH）作为优先验证路线，把 Deep Agents + LangGraph 保留为需要掌握执行和状态时的备选；在具体业务确定前，不据这轮本地样本决定替换现有 OpenClaw 产品。** 如果后续任务很简单、运行管理需求也很少，再考虑直接用轻量 SDK。

这不是综合排名。DSH 在本轮固定模型和任务里的工具、浏览器、规则及暂停链表现较完整，但后端接入、取消和实例成本仍有缺口。Deep Agents 的执行图、checkpoint 和协作停止已形成可查证据，后端作用域也测得更深，但分页及商品选择失败较多，产品运行管理仍要自己补。两者都还没有证明“迁过去研发更少、线上更省钱”。

## 1. 这份建议服务什么目标

用户要调研的是能调用工具、操作浏览器、办理业务的通用助手。目前没有确定业务场景，现有产品基于 OpenClaw，用户感受是流程黑箱、自定义难，且按用户启动 Agent 实例导致用户增加时资源成本上升。

因此优先考虑五件事：任务办得成；过程能查清；业务工具和规则容易改；等待时能关闭 Worker、之后继续；空闲用户增加时，不必同时增加一整套常驻运行资源。可接受自研，但业务确定后研发时间有限，不能只看框架核心轻巧，就忽略任务管理、身份绑定、恢复和资源回收的建设量。

本轮约束保持不变：候选和工具、浏览器、验收均在本地 Docker 镜像内运行，模型固定为远程 API 的 `deepseek-v4-flash`；不通过换模型解释或绕过结果。未来租户身份由独立产品后端提供，本轮用模拟产品后端验证接点，**不要求连接现网 Hogee 租户系统**。浏览器可以重新打开、重新登录，不要求恢复暂停时的网页现场；使用期间的账号、数据和操作归属仍需验证。

## 4. 成本目前能说什么

暂停链已证明：保存任务状态后可以删除承载任务的Worker，并由新容器继续。成本探索也已证明：在已测按需方案中，空闲用户可以仅保留状态而没有Worker。这支持继续研究“计算资源随活跃任务增长”，没有证明所有用户可以安全共享一个进程，也没有证明未来产品一定省钱。

完整比较仍要把候选、模型代理、工具、浏览器、存储以及产品后端分别计入。I25的observer不能代替产品后端；I24另一个入口的授权结果也不能为resident入口补通过。按需回收可能减少空闲进程，同时增加启动等待和重新构造对象的开销，需在同入口、同配额、有效采样和真实业务完成的条件下评价。

当前[用量台账](costs.md)010已完成断网Docker SQL/token验收，无key、退出0且清理通过：343库/2485条reservation，分为2416条远程200、36条模拟、28条本地注入、4条远程未确认、1条在途未知。未闭合及别名列表为空；17个未登记来源未查、不补0，包括尚未兼容reader的DSH I24七条材料和I25 N5八条任务。

token覆盖307项/285目录；2266份观察输入/输出/总量已知、13份未知，11个材料单元无可用usage。已知输入9,590,870、输出662,533、总量10,253,403。没有请求级join、完整账单或金额，009及旧失败原件保留；这些混合任务的总量不用于费用排名，也不除以某条路线成功数生成“每成功任务成本”。

建设成本同样未闭合。接入和排查过程已展示出要维护哪些组件，但未记录可靠人工工时，也没做上游版本升级实验。当前只能列补齐清单、判断是否符合短研发周期的倾向，不能承诺几天迁移或几人月上线。

## 5. 其余开源候选为什么暂缓

Pi Agent Core、Google ADK、OpenAI Codex SDK和OpenHands均保留为候选，并非因闭源而移除。八者的开源范围及本地材料已核对。它们暂未进入与四详细路线同等深度的恢复、隔离与成本实验，不能因未测而写成不支持。

| 候选 | 已有证据 | 什么变化会使它值得优先补测 |
| --- | --- | --- |
| Pi Agent Core | 两个新容器完整工具任务1/2；真实模型/工具与预算轨道可用 | 目标业务只需薄循环、愿意自己建设运行管理，且其简化收益能覆盖补齐量 |
| Google ADK | 两个新容器工具任务均通过，选定远程模型可接，不依赖更换模型 | 未来业务需要其编排/状态接点，并能提出比现有专项路线更小的补齐清单 |
| OpenAI Codex SDK | 官方开源SDK/CLI与MCP接入，两次新容器工具任务通过；首次审批接线失败保留。固定模型未切换，当前所选接口缺公开输出token硬上限 | 业务更接近现成代码/工作区Harness用途，且能接受其接口和控制边界；应先补同题恢复/资源证据 |
| OpenHands | 核心开源范围已核对，两次新容器任务通过 | 具体业务能够受益于其现成执行环境，收益足以抵消代码Agent假设和额外运行复杂度 |

原始范围见 [初筛结果](screening.md) 及 [专项路线选择](selection.md)。当前不将上述候选全部扩成完整运行平台，也不把代表性Agents SDK的详细结果套给其他SDK。
