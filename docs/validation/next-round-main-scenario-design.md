## 2. 主场景与「更优秀」的判定

**主场景**：把现有客户端搬到云端，持续服务多个用户；本轮用本机 Docker 模拟，不建设生产多租户、云 IAM、自动扩缩容或审批流。任务在作用域和预算内自动执行，敏感操作直接拒绝。

**「更优秀」不是总分，而是同场景下的偏序：**

- 先过「必备项」：用户隔离、恢复不重发、停止/取消有确定状态、禁止写入被拦住。
- 再过「比较项」：任务通过率、单位任务成本、每用户成本、过程可诊断性、维护面。
- **接入成本单独设门槛**：候选超过预算即 `FAIL_INTEGRATION`；DSH 的接入成本是分母，不作为 DSH 的淘汰项——它高，本身就是第一问的答案。
- 候选 A 优于 B，当且仅当两者都通过接入门槛，A 在全部必备项上不差于 B，且在至少一个比较项上严格更好；接入失败的候选不进入比较。否则只报取舍，不排名。
- 换场景（单用户短任务、成本优先、改造现有业务）结论会变；本轮只回答主场景，不给跨场景总榜。

**判定标签**（全轮统一，一个候选只给一个总标签，分项另表记录）：

| 标签 | 含义 |
| --- | --- |
| `PASS` | 场景契约通过，接入成本在预算内 |
| `FAIL_CAPABILITY` | 本机可执行，但能力/业务/隔离/恢复不成立 |
| `FAIL_INTEGRATION` | 本机可执行，能力可能通过，但接入成本超预算或需要维护上游 fork |
| `FAIL_INTEGRATION_GATE` | 门禁预算（10M token / 20 次 agent 迭代）内未做出提交/状态/取消三接口；不进入全量 |
| `SKIP_LOCAL` | 本机明确无法忠实执行；不是候选能力失败 |
| `SKIP_SCOPE` | 不属于主场景可信替代（如纯编码路线）；不是能力失败 |
| `BLOCKED` | 实验设施/环境故障；修复后重跑，不计候选成败 |
| `NOT_TESTED` | 预算/时间用尽，未进入；如实报告 |
| `INCONCLUSIVE` | 材料、采样、接入台账不完整，不能判定 |

总标签按 `SKIP_*` → `FAIL_CAPABILITY` → `FAIL_INTEGRATION`（含门禁失败）→ `PASS` 的顺序取第一个成立项；`BLOCKED`、`NOT_TESTED`、`INCONCLUSIVE` 是过程状态，不参与优劣比较。

## 3. 场景契约（MSC）

**共享场景台负责**：模拟身份、任务 API、归属检查、状态/工作区持久化、按需启停、事件与资源采集、故障注入、独立验收。**候选适配器只负责**：把契约调用翻译成候选的公开接口；不写业务逻辑，不替候选完成缺失步骤。

适配器补的控制/状态映射必须单独标注；报告仍按「框架自带 / 适配器补 / 共享场景台」三栏归因，不能把适配器补的写成框架原生。缺的能力不能用适配器伪造原生语义，只能记「应用层补」并计入接入成本。

**复用而不是重写**：身份/归属/任务 API 复用 `runner/shared_backend.py`、`execution/control_backend.py`；Worker 控制复用 `execution/worker_control*.py`；多用户验收复用 `runner/multi_user*.py`；成本复用 `runner/instance_cost*.py`；故障、证据和测试复用 `execution/tools/`、`runner/`、`tests/`。本轮只加候选 profile 和 MSC 契约，不另起一套实验台；现有 I24/I25 的失败原件保留，不覆盖。

I24 现有入口带 DA 专用假设（事件格式、checkpoint、控制语义）。已新增 `execution/candidate_profiles.py`：DA/DSH 常量与现有 worker 一致，OpenClaw 暂标 unsupported。E0 继续把 worker control 按 profile 分派；抽离工作算共享场景台成本，不摊给候选，也不把抽离工作量算成某个框架的接入成本。

| 能力 | MSC-min（必做） | MSC-full（预算内加做） | 判定 |
| --- | --- | --- | --- |
| 身份与归属 | Bearer 凭证 → principal；任务 → owner；2 用户 | 5/10 用户状态；跨用户六类操作 | 实际 403、无数据泄漏；不能用 401/404 冒充 |
| 任务入口 | 提交、状态、事件、产物、暂停、恢复、取消 | 重连、换 Worker、按需唤醒 | 真实 HTTP/原生接口，不用缓存冒充 |
| 状态与工作区 | 状态/工作区在执行程序之外；重启可读 | 暂停后换容器继续；不重发已提交写入 | 原生 checkpoint/存储可核对 |
| 调度与回收 | 按需启停；最多 2 个活跃任务 | 5/10 用户空闲/活跃；冷唤醒 | 记录真实容器/进程/配额 |
| 规则 | 敏感操作拒绝；超量写入在执行层前拦住 | 多种子、跨用户、重试/恢复后仍生效 | 记录拦截位置：框架/适配器/业务服务 |
| 可观测 | 任务、步骤、工具调用、终态原因可查 | 注入故障后的排障计时 | 原生 trace 是否足够；缺什么 |
| 成本 | 每任务模型调用/token；每用户内存/CPU | 常驻 vs 按需；唤醒延迟；回收后遗留 | 采样完整才报均值/峰值 |
| 接入 | 适配器实现契约；接入 token/迭代入账 | 版本升级/维护点评估 | token + 模型/工具调用 + 代码 + 依赖 + 失败轮次 |

**通过分三层，缺一不可：**

1. 业务是否完整完成（报告、订单、金额、操作过程）。
2. 机制是否成立（真暂停、真换容器、真 403、真不重发）。
3. 实验是否有效（材料、采样、清理、接入台账完整）。

**最小与完整的边界**：MSC-min 用 2 用户、1 个种子、每用户 1 个主任务 + 1 个取消子任务 + 1 次重启；MSC-full 用 101/202/303 三个种子、5/10 用户成本档、20 分钟 soak、3 类故障排障。预算不够时，MSC-full 的未做项标 `NOT_TESTED`，不能拿 MSC-min 冒充完整通过。

**候选分层，避免八条全量：**

| 层级 | 路线 | 处理 | 理由 |
| --- | --- | --- | --- |
| 第一层 | DSH、OpenClaw、Deep Agents | 全量 MSC | 两个现有底座 + 上一轮唯一有恢复/成本对照的替代 |
| 第二层 | ADK、Agents SDK | 门禁；过门禁且预算允许则全量 | 一个有会话服务，一个代表轻量自建；只选真正能接的 |
| 第三层 | OpenHands、Pi、Codex | 门禁；一般只做跳过记录 | 编码专用或过轻，主场景可信度低；不预先判死，按门禁证据说话 |

**第二层最多 1 条进入全量**：两条都过门禁时，按门禁 token 消耗低者优先，另一条记 `NOT_TESTED`，不写成失败；第二层全量只 1 种子，结论标「初步」，不能与第一层三组同权。**第三层只做门禁**：只有第一/二层提前结束、且门禁显示明显更优时，才用剩余预算加做 1 条，否则记 `NOT_TESTED`。

**门禁（每条路线都做，不替代全量）：**

1. 固定版本、开源、许可可审。
2. 本机 linux/arm64 可构建、可启动；不能构建 → `SKIP_LOCAL` 或 `BLOCKED`，写精确错误。
3. 有可用的任务/会话/持久化接点；完全没有且没有可信适配路径 → `SKIP_SCOPE`。
4. **门禁冲刺**：只做单用户提交、状态、取消三个接口；10M token 或 20 次 agent 迭代内未完成 → `FAIL_INTEGRATION_GATE`，不再投入。
5. 门禁通过但全量预算不足 → `NOT_TESTED`，不写成失败。

门禁是**低成本试接**，不是能力结论；门禁通过只说明值得进入全量。

## 5. 接入消耗：记录口径与失败线

**接入消耗 = 候选适配器消耗的模型 token + 模型调用 + 工具调用 + agent 迭代 + 代码/配置变更 + 新增依赖 + 构建调试 + 维护点。** 不含共享场景台，不含候选自身业务逻辑；业务定制（新增工具/规则/状态字段）单列，不混进基础适配器 token。

**接入成本按 token 计。** 接入成本以 token 为主账，代码/依赖/失败次数为辅证；排期不在本轮度量范围。全轮 token 上限 500M，接入与评测分账但合计计入。

| 记录项 | 怎么记 | 用途 |
| --- | --- | --- |
| 接入 token | 按阶段记 input/output tokens、模型调用数；接入与评测分账 | 主成本；算相对 DSH |
| agent 迭代/工具调用 | 每次 agent 回合（模型调用→工具/代码动作→结果）算一次迭代；工具调用、构建/测试单独计数 | 看返工和试错 |
| 代码/配置 | 文件数、增删行、是否改上游核心、Dockerfile/配置行 | 区分「适配」与「fork」 |
| 依赖/服务 | 新增必须常驻的服务、端口、卷、密钥、健康检查 | 运维成本 |
| 构建/失败 | 构建/测试次数、失败原因、重试、回滚 | 隐性成本 |
| 维护点 | 私有 API、未稳定接口、版本升级需重验的文件 | 长期成本 |

**接入台账阶段**（只能选一个）：读文档/源码、环境与构建、适配器编码、配置、调试与返工、校准与测试、文档、复核。失败尝试和返工必须计入；自动构建/等待只记 wall-clock，不计 token，也不作失败线。

### 5.1 接入 token 怎么数

**首选：给接入 agent 套一个 token 计数代理。** 不是事后读候选日志，而是在 agent 和模型 API 之间加一层本地代理；agent 的 base URL 指向代理，代理转发并记录每次请求的 usage。现有 `execution/model_proxy.py` 只记调用次数、不记 token；已新增 `execution/token_proxy.py`（复用鉴权、转发和预算骨架，增加 token 台账和 cap），非流式/流式均已用真实模型 smoke 验证；接入直接使用它。

1. **每个接入 session 一个代理进程**：独立 `session_id`（candidate + phase + attempt）和独立 ledger；不与评测任务共用，避免把评测 token 算进接入。
2. **agent 启动时改 base URL**：OpenAI 兼容用 `OPENAI_BASE_URL=http://127.0.0.1:PORT/v1`，Anthropic 用 `ANTHROPIC_BASE_URL=http://127.0.0.1:PORT`，DSH 用 `MODEL_API_BASE_URL=http://127.0.0.1:PORT/v1`；agent 只拿 session token，真实上游 key 只在代理里。Anthropic 的 key 用 `x-api-key`，OpenAI/DSH 用 Bearer；代理保留 provider 必需头（如 `anthropic-version`）。启动前先发一次 hello 请求，确认代理真的被命中。
3. **代理解析 usage**：
   - 非流式 JSON：读 `usage`；
   - OpenAI Chat Completions 流式：请求体补 `stream_options.include_usage=true`，读最后一个 usage chunk；
   - Anthropic Messages：`message_start` 的输入/缓存字段 + `message_delta` 的输出字段；
   - OpenAI Responses：`response.completed` 的 usage。
   记录 `input/output/total/cache_read/cache_write/reasoning`；字段缺失写 `null`，不补 0。
4. **每次模型请求一行**，写 `token-ledger.jsonl`：时间、session、候选、阶段、provider、model、request_id、是否流式、各 token 字段、`status`（`reported/unknown/conflict`）、上游状态。重试、失败、断连都单独一行；有请求但没拿到 usage 记 `unknown`。
5. **代理按累计 token 执行 cap**：门禁 10M、MSC-min 50M、全量 100M、全轮 500M；到线返回 429，agent 停止，ledger 记 `budget_exceeded`。单次响应已发生就按实际 usage 记账，不截断。
6. **校准**：先用一个固定 prompt 做非流式、流式各一次，代理计数与供应商返回值逐字段比对；再用一次真实小请求与供应商 dashboard 对账。对不上就修解析或标 `unknown`，不能估算凑数。

**次选：agent 原生 session 日志。** DSH 的 `raw-events.jsonl`、Claude Code 的 session JSONL、Codex 的 usage 输出都可能带 usage；按 session/response ID 去重后入同一 ledger，标 `native_log`。与代理计数冲突时保留两行，不取最大值。

**兜底：供应商账单/导出。** 只能校验总量，不能拆阶段；用于对账，不单独作为接入 token 结论。

**不可观测就写 `unknown`。** GUI/IDE 型 agent 不能改 base URL、也没有 usage 导出时，本轮无法按 token 比较该候选的接入成本；标 `INCONCLUSIVE`，不能估一个数让它过门槛。

**不要混进来的**：工具调用、shell/构建/测试耗时不是 token，单独记次数和 wall-clock；子 agent 必须走同一代理/同一 session，绕过就记 `unknown` 并标 `bypass`。平台/供应商不返回 usage 的请求，不能按字符数或平均单价倒推成“精确 token”；估算只能标 `estimated`，不参与成败判定。

**失败线（开工前冻结，不能跑完再改）：**

| 规则 | 阈值 | 判定 |
| --- | --- | --- |
| 相对成本 | 同一 MSC 范围，候选接入 token > DSH 基线的 2 倍 | `FAIL_INTEGRATION` |
| 绝对上限 | MSC-min > 50M token，或 MSC-full > 100M token | 停止并判 `FAIL_INTEGRATION` |
| 上游改动 | 修改候选上游核心源码 > 100 行，或需要长期维护 fork | `FAIL_INTEGRATION`（官方配置/插件不算） |
| 常驻依赖 | 新增 > 2 个必须常驻的第三方服务 | `FAIL_INTEGRATION` |
| 台账缺失 | 接入 token/调用/代码 diff 无法核对 | `INCONCLUSIVE`，不能判通过 |

**能力通过但接入失败，整体就是失败。** 这正是上一轮缺的判断：能跑不等于值得接。

这些数字是本轮预算，不是行业基准；DSH 基线出来后可用它校准一次，但必须在跑候选前冻结。绝对上限先按 50M/100M；如果 DSH 基线超过它，按 DSH 的 1.5 倍上调后再冻结，避免用低于基线的帽子直接判死；上调后总 500M 不变，放不下就减全量条数或标 `NOT_TESTED`，不突破总 cap。

token 是工作量单位，不是金额；不同模型、缓存读写和推理的单价不同，本轮只卡 token，不承诺费用上限；金额另按供应商账单核对。

**公平性：**

- 同一模型、同一 agent 配置、同一提示模板、同一工具预算；不让一个候选享受更强的 agent。
- 先冻结契约，再按固定顺序接适配器；第一条适配器暴露的契约问题算共享场景台成本，不算该候选的接入成本。
- 契约冻结后如再改，改动成本和返工单独列，不悄悄摊回候选。
- 同一候选的读源码、构建、调试都算；不把读源码/熟悉框架的 token 藏到实验设施里。
- 独立复核 token 账本、代码 diff 和失败记录；自报 token 不能直接当结论。

## 6. 本机执行与跳过规则

**环境**：本机 Docker（linux/arm64），总预算沿用 6 GiB / 3 CPU、最多 2 个活跃任务、每任务 20 次调用 / 300 秒；模型远程调用。所有实验在容器内执行，宿主只做编排、采样和清理。

**安全边界**：本地身份是模拟，不证明生产 IAM/网络安全；越权测试只覆盖应用层 403、任务/文件归属与控制路由，不覆盖云网络隔离、主机隔离或凭证分发。

**允许的本地替代**：模拟身份服务、本地 HTTP 任务 API、SQLite/文件系统状态、宿主调度、本地队列/唤醒。替代必须保持场景语义；换掉语义的替代不能用来判通过。

| 标签 | 含义 | 适用情形 | 禁止 |
| --- | --- | --- | --- |
| `SKIP_LOCAL` | 本机无法忠实执行 | 云专有身份/IAM、托管队列、跨区故障等无本地等价物；构建/运行平台不兼容 | 把候选能力失败写成跳过 |
| `SKIP_SCOPE` | 不是主场景可信替代 | 纯编码路线、无服务接点且无适配路径 | 因为「看起来难」而跳过 |
| `BLOCKED` | 设施/环境故障 | Docker、网络、磁盘、镜像源 | 算成候选失败 |
| `NOT_TESTED` | 预算/时间用尽 | 门禁通过但没排上全量 | 算成通过或失败 |

**跳过必须写清五件事：**

1. 尝试了什么（版本、命令、材料）。
2. 精确错误/证据（日志、镜像、配额）。
3. 为什么不是候选能力失败。
4. 这个跳过还能支撑什么结论、不能支撑什么。
5. 什么条件能解除（本地替代、资源、许可、版本）。

**禁止事后跳过。** 跳过理由必须在开跑前登记，或由独立评审确认；不能因为结果不好看改标签。**也不要把框架失败写成跳过**：本机能跑、只是能力不成立，就是 `FAIL_CAPABILITY`。

**可能出现的跳过，不预先判死：**

- Codex SDK：偏编码任务，若门禁确认不适合通用业务 → `SKIP_SCOPE`。
- OpenHands：代码 Agent，若主场景无编码任务 → `SKIP_SCOPE`。
- Pi：没有服务层，但可接适配器；若门禁 token/迭代预算内做不出三接口 → `FAIL_INTEGRATION_GATE`，不是跳过。
- ADK：若强依赖云端组件、本地 runner 不能保持语义 → `SKIP_LOCAL`。
- 5/10 用户常驻档：若 6 GiB / 3 CPU 装不下，按配额计算后 `SKIP_LOCAL` 该档，不报节省比例。

**档位级跳过只影响该档，不改变路线总标签**；汇总写成 `PASS（2 用户）/ SKIP_LOCAL（5/10 成本档）`，不能因为成本档跳过就把整条路线写成跳过。

## 7. 样本、预算与批次

| 项目 | 设定 |
| --- | --- |
| 种子 | 101 冒烟；101/202/303 正式；404/505 仅在预算允许时补 |
| 用户 | 2 个活跃；5/10 用于成本档；同时最多 2 个活跃任务 |
| soak | 20 分钟、3 波任务；本机撑不住则 `SKIP_LOCAL` 并写原因 |
| 预算 | 每任务 20 次调用 / 300 秒；全轮 token 上限 500M（接入与评测合计），到达即停并报 partial |
| 成本档 | 2/5/10；先算 6 GiB / 3 CPU 是否装得下，装不下就跳过该档 |
| 重复 | 正式三组各 1 次；不为挑成功重跑；失败原件保留 |
| 顺序 | E0 → E1 冒烟 → E1 正式 → E2 → E3 → E4 → E5 → E6；独占锁，串行 |
| 透明 | 3 类故障 × 2 条路线；顺序随机；单次 15 分钟上限 |

**500M 的粗略分配**：4 条全量接入 400M（上限，不是目标）、5 条门禁 50M、评测 50M；按账本滚动，超支即停。

**不预填通过。** 批次开始前固定镜像 ID、材料哈希、任务集、阈值；中途改阈值就把该批标为探索批，不能混入正式结论。

**模型行为基线**：正式比较前，用 DSH 在同一任务上跑 3 次，记录分页/格式/拒绝失败率；如果失败率 > 1/3，先修任务或提示并重新冻结，再进入候选比较。否则候选差异会被模型波动淹没。

**soak 细节**：每波 2 用户各 1 个任务，波间 5 分钟；其中一波插入取消；结束检查遗留进程/容器、状态可读、预算未重置。20 分钟只证明有界持续，不外推生产 SLA。

## 8. 证据、归因与判定

每个 trial 至少保留：

- `plan.json`：版本、镜像 ID、任务、用户、配额、阈值、假设。
- `token-ledger.csv`：接入 token/调用/迭代；`code-diff.patch`：实际改动。
- `build.json`、`run.jsonl`、`metrics.json`：构建、运行、资源/调用。
- `verdict.json`：三层判定；`review.md`：独立评审意见。
- 原始失败日志、镜像/材料哈希、清理记录；不覆盖旧原件。

**归因五选一，不能混：**

| 归因 | 例子 | 处理 |
| --- | --- | --- |
| 候选框架 | 原生暂停不产生终态、规则不拦 | 记能力缺口 |
| 适配器 | 我们把事件映射错、漏了鉴权 | 记接入成本，不计候选失败 |
| 共享场景台 | 采样空档、路由错误、清理竞态 | `BLOCKED`，修复后重跑 |
| 环境 | Docker/网络/磁盘/模型服务 | `BLOCKED`，不计候选 |
| 模型行为 | 没按分页/格式执行、自己拒绝 | 记任务失败与模型行为，不记框架缺陷；保留模型、提示、种子 |

**判定顺序**：先看实验有效性（材料/采样/台账），再看机制，最后看业务。有效性不成立时，不评价候选。

## 9. 三个开篇问题怎么回答

### 第一问：现有客户端怎么上云？

**产出**：DSH 的 MSC 工作分解表（组件、要做的事、接入 token/迭代、风险、是否框架原生），加 MSC-min/full 的通过项和单位成本。

- 通过：回答「要改多少」有实测 token/迭代/代码量；仍要注明产品化剩余工作（真实身份、云存储、调度、监控）。
- 不通过：回答「卡在哪」：取消、隔离、成本、服务层各是什么缺口，补它要多少 token/迭代。
- 不再用「能力够/不够」一句话，改为「哪些项已成立、哪些项要补、补的 token/迭代」。
- **工期不在本轮度量范围**：这里的「要改多少」指接入 token、模型/工具调用、代码量和服务/维护点。

**与基线的口径差异**：报告 6.1/6.4 把「要改多少」写成人工时间；本轮改为接入 token/迭代/代码量，不再采集人工工时。报告原文保留为基线，不回填。

**决策规则**：MSC-min 通过且接入在预算内 → 按 WBS 试接；有必备项缺口 → 先补缺口；能力通过但接入超预算 → 缩范围或换路线。

### 第二问：现有云端业务哪里可改善？

**产出**：OpenClaw 的三张表：

1. **过程透明**：3 类故障的根因定位时间、步骤、原生证据是否足够；缺什么日志/事件。
2. **业务定制**：加 1 个工具 + 1 条规则 + 1 个状态字段的 token/迭代；规则是否真在执行层拦住；重试/恢复后是否仍生效；拦截位置（框架/适配器/业务）。
3. **实例成本**：2/5/10 用户的常驻 vs 按需；每用户/每任务内存、CPU、唤醒延迟；采样不完整就不报节省比例。

**排障记录**：根因定位时间（分钟）、操作步数、token 消耗、原生证据是否足够（足够/部分/不足）、是否需要外部日志、诊断结论是否正确。由同一诊断 agent（固定模型/提示/工具）执行，不知道注入的是哪类故障。

**边界**：以上只对模拟业务成立；真实业务需另做一次同口径排障和定制，不能直接外推。排障是 agent 视角的可诊断性，不替代人类操作者体验；人类体验另做定性访谈，不纳入本轮主判定。

**决策规则**：透明、定制、成本三项中至少一项有可核对改善，且没有新增硬伤 → 保留改造；否则先修规则与成本，不先换框架。

### 第三问：有没有其他框架上云更优秀？

**产出**：同场景偏序表，不是总分。

| 路线 | 必备项 | 任务通过 | 接入 token | 每任务成本 | 每用户成本 | 过程可诊断 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |

判定规则：

- 有候选在全部必备项上不差于 DSH，且至少一项严格更好，接入成本在预算内 → **「在主场景下，X 更优秀」**，并写清它赢在哪、代价是什么。
- 没有候选全面占优 → **「没有单一更优秀；按优先级取舍」**，列出每条路线的强项/硬伤。
- 全部失败或跳过 → **「本轮没有证据支持换；缺的是这些」**，不写「没有更优的框架」。
- 任何候选能力通过但接入失败 → 结论里明确写「能跑，但不值得接」。

**能改变结论的条件**：DSH 补验通过/失败；OpenClaw 透明度或成本改善；候选接入成本低于 DSH；本地资源允许 5/10 用户；模型行为变化。结论只对固定版本、固定模型、本机配额负责。

## 10. 风险、停止条件与预注册

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 本机 6 GiB / 3 CPU 装不下 5/10 用户 | 成本档缺失 | 先算配额；装不下就 `SKIP_LOCAL` 该档，不报比例 |
| 模型随机性/分页违规 | 业务失败被误判为框架失败 | 固定模型/提示/种子；把分页作为任务要求；失败归因到模型行为，不归框架 |
| 接入时间自报偏差 | 「要改多少」不可信 | 开始/结束时间戳、类别、产物；独立评审抽查 |
| 共享场景台缺陷 | 重复上一轮 DSH 试跑的采样/取消问题 | E0 先无模型校准；设施问题 `BLOCKED`，不计候选 |
| 候选版本/接口变化 | 结论不可复现 | 固定提交/镜像；不升级；哈希入 plan |
| 为了通过改阈值 | 结论失真 | 阈值开工前冻结；改了标探索批 |

**停止条件**（任一触发即停，保留原件）：

- 单候选接入 token 超过绝对上限。
- 全轮 token 达到 500M。
- 同一设施故障连续 3 次修复仍不能校准。
- 出现凭证泄漏、越权写入、数据损坏风险。
- 预算/时间窗口结束。

## 13. 本轮不做什么

- 不建设生产多租户、云 IAM、自动扩缩容、审批流。
- 不强求浏览器现场恢复；允许重新打开、重新登录。
- 不做候选版本升级/兼容性实验。
- 不重跑八条基础任务，不为「补齐八条」而补齐。
- 不产出跨场景总榜或单一分数。
- 不把共享场景台的成本摊进候选接入成本。
- 不把跳过当失败，也不把失败当跳过。
