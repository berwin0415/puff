# P0 云端 Harness 调研收口

日期：2026-10-19

本文是 P0 调研的收口结论，回答“下一步应沿哪条路线继续”，不是生产选型结论。
证据按统一 T1–T6、同一模型和同一本地执行基线记录；未执行项明确标注，不用推断补齐。

## 结论摘要

1. **推荐 Deep Agents + LangGraph 作为下一阶段的主实现候选。** 它是三个 P0 中唯一
   同时具备真实模型、工具调用、结构化事件、SQLite checkpoint、非审批模型安全点
   暂停和跨进程恢复证据的候选。
2. **OpenClaw 保留为现有业务基线和控制平面对照。** 它的 Gateway、插件和工具面
   可复用，统一适配器与 T1 已通过；但缺少 checkpoint/恢复证据，浏览器导航策略
   仍阻断本地 Fixture。
3. **DeepSeek Harness 保留为专项参考。** T1 和统一 Playwright 基线通过，hsi-desktop
   的 MCP/CDP 轨道和独立 Chromium + Playwright MCP 证明浏览器可迁移；但 headless
   入口没有原生浏览器，生命周期能力最弱。
4. **P1（OpenAI Agents SDK、Google ADK、Pi Agent Core、Codex SDK、OpenHands）
   暂不启动。** P0 已经回答了主路线问题；P1 只应带着具体未解阻断进入，而不是为了
   铺满候选。
5. **当前不进入产品原型。** 下一阶段先补齐主路线的最小验证缺口，再决定是否原型化。

## 判定口径

- **PASS**：有同口径运行证据，结果符合断言。
- **PARTIAL**：只覆盖部分路径，或只证明基础设施/基线，不能归为候选原生能力。
- **BLOCKED**：候选或环境明确阻止该任务，已记录原因。
- **NOT RUN**：尚未执行，不作为通过或失败。

候选原生能力、适配层补齐、Runner/Execution 基础设施能力分开记录。

## T1–T6 证据状态

| 任务 | DeepSeek Harness | OpenClaw | Deep Agents + LangGraph |
| --- | --- | --- | --- |
| T1 确定性工具 | PASS：Fixture GET/POST、sum=60、幂等副作用 201 | PASS：统一 adapter，shell/curl 返回 60 | PARTIAL：`fixture_lookup` 自定义工具通过，未跑统一 Fixture HTTP 链 |
| T2 浏览器 | PARTIAL：统一 Playwright 基线通过；候选 headless 无 browser Connection | BLOCKED：托管 `openclaw` profile 可选，但 loopback 导航被策略阻断，模型回退 curl | NOT RUN：未接入统一 Playwright 桥 |
| T3 人工介入/审批 | BLOCKED：one-shot 入口，无实时输入/审批 | BLOCKED：`agent exec` 一次性入口 | PARTIAL：原生工具审批中断 + 跨进程 resume 通过；实时 `send_input` 未验证 |
| T4 暂停/恢复 | BLOCKED：headless 入口无 checkpoint/pause | NOT RUN：无 checkpoint/resume 证据 | PARTIAL：模型安全点暂停 + 跨进程 resume 通过；容器重启和即时抢占未验证 |
| T5 故障/重试 | PARTIAL：幂等副作用通过；无 checkpoint/恢复 | NOT RUN：无 checkpoint/恢复证据 | PARTIAL：SQLite checkpoint + 跨进程 resume；工具超时/进程退出/容器重启未跑 |
| T6 扩展成本 | NOT RUN | NOT RUN | NOT RUN |

补充证据：

- 统一 Runner 的 T3–T5 控制面测试通过：输入/审批事件、Runner 重建后恢复、
  fail-once 重试、幂等重放、事件序号连续性。
- 无 Electron 的 Chromium + `@playwright/mcp` 通过：导航、表单、snapshot、
  双 tab + `window.open`、截图、重启后 localStorage 恢复；下载未覆盖。
- 以上两项属于本仓库基础设施证据，**不能算作候选框架原生能力**。

## 候选结论

### Deep Agents + LangGraph（主实现候选）

已证明：

- 官方来源、MIT 许可、固定版本、外部 Python 3.12 环境可复现；
- 真实远程模型调用和 `fixture_lookup` 工具调用；
- 结构化 graph 事件、工具节点可见、SQLite checkpoint 可离线读取；
- 非审批模型安全点暂停（`interrupt_after=["model"]`）和新进程
  `Command(resume=True)` 恢复，最终答案 `fixture-alpha`；
- 可选的人工审批中断（`interrupt_on`）。

未证明：

- 统一 Playwright/浏览器桥接；
- Runner/Execution 容器被杀后的恢复；
- 立即抢占式 pause、cancel、实时追加输入；
- T6 扩展成本、多租户隔离；
- 真实业务任务上的效果和费用。

### OpenClaw（业务基线/控制平面对照）

已证明：

- 来源、MIT、固定 commit、依赖安装和构建；
- Gateway health/ready、20 个插件加载、远程模型调用；
- 统一 `agent exec --json` adapter、事件映射、脱敏 manifest；
- T1 工具任务通过（shell/curl，返回 60）；
- 内置 `openclaw` 托管浏览器 profile 可选，不依赖扩展 relay；agent 浏览器调用到达导航策略层。

未证明/阻断：

- T2：托管 profile 被选中后，导航到 loopback Fixture 仍返回
  `browser navigation blocked by policy`，即使配置
  `dangerouslyAllowPrivateNetwork` 和 `allowedHostnames`；模型回退到 curl。
  这是浏览器导航/SSRF 策略问题，不是 relay 缺失。
- checkpoint、pause/resume、人工审批、Runner 重启恢复；
- Gateway 会话恢复、统一浏览器轨道、多租户边界。

### DeepSeek Harness（专项参考）

已证明：

- 来源、MIT、固定 commit、Node 环境；
- 真实 API、T1 bash/curl 和幂等副作用；
- 统一 Execution Playwright 基线；
- hsi-desktop 的 MCP/CDP 链路可迁移；
- 独立 Chromium + Playwright MCP 云端浏览器轨道通过。

未证明/阻断：

- `dsh --profile headless` 没有原生 browser Connection；
- DSH 的 BrowserHost/HostSession、任务 scope、审批尚未接入云浏览器；
- 持久会话、pause/resume、checkpoint、实时输入和取消；
- 统一 T3–T6 证据。

## 工程成本的结构性观察

| 项目 | DeepSeek | OpenClaw | Deep Agents |
| --- | --- | --- | --- |
| 适配器代码量（行，含 worker） | 490 | 565 | 848 |
| 运行时依赖 | Node + pnpm | Node + pnpm + Gateway | Python + 外部 venv |
| 事件透明度 | 有 normalized events；stdout/stderr 交错不可恢复 | JSON envelope + toolSummary；节点级过程有限 | graph update、工具节点和 checkpoint 可见 |
| 恢复基础 | 无 | 无同口径证据 | SQLite checkpoint + 跨进程 resume |
| 浏览器 | headless 无；hsi MCP 可迁移 | 托管 profile 可选，导航策略阻断 | 未接入统一桥 |

代码量只是结构代理，不等于人日；T6 未执行，不能给出“新增一个工具/审批/状态”的
真实改动成本。模型 token 和每任务费用也尚未按同一任务归一化。

## 阻断与未验证清单

1. Deep Agents：统一浏览器桥、容器级恢复、即时抢占、cancel/live input。
2. OpenClaw：loopback 浏览器导航策略、checkpoint/恢复、Gateway 会话恢复。
3. DeepSeek：DSH 云浏览器接入、持久会话和生命周期。
4. 三者共同：T6 扩展成本、多租户隔离、真实业务任务效果与费用。
5. 云浏览器：MCP 下载契约未覆盖。

## P1 决策

**暂不启动 P1。**

理由：P0 已经能回答“主路线选谁、缺什么、下一步验证什么”。P1 候选只有在以下情况
才进入：

- Deep Agents 在统一浏览器桥或容器级恢复上触发硬阻断；
- 主路线 T6 成本明显不可接受；
- 业务场景出现 P0 候选都无法覆盖的明确能力要求。

## 下一阶段的收口动作

在进入产品原型前，只做能改变选型结论的最小验证：

1. Deep Agents：接入统一 Execution Playwright/MCP，验证 T2 和浏览器重启恢复。
2. Deep Agents：验证 Runner/Execution 容器重启后的 pause/resume 和副作用幂等。
3. Deep Agents：执行一次 T6，记录新增工具/审批/状态节点的改动量和首次跑通时间。
4. OpenClaw：定位 loopback 导航策略的实际生效层；若不可解，T2 保持未验证，
   不影响其“控制平面对照”定位。
5. DeepSeek：仅在需要复用 hsi-desktop 浏览器能力时，做 DSH 任务/scope 接入专项。
6. 以上完成后，再决定是否进入产品原型或补 P1。

## 结论边界

P0 收口意味着“调研阶段结束、方向可决策”，不意味着“生产选型完成”。任何候选被
标记为 PASS 的项目只在其证据覆盖的版本、模型、任务和环境内成立。
