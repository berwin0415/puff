# Agent 任务自动化工程规范（拟实施）

适用于 Agent 任务自动化域的核心库和 Codex 插件。详见 [v0.1 PRD](../agent-task-automation/v0.1/prd.md) 和 [技术设计](../agent-task-automation/v0.1/technical-design.md)。

## 四层职责

- 通用核心提供安装引导、配置校验、工作流、任务上下文和结果模板。核心配置字段使用通用角色、能力引用和操作标识。
- 宿主适配负责安装、工作区发现、计划、会话与权限检查。v0.1 的适配目标为 Codex 桌面端。
- 工作区绑定保存用户选定的路径、能力引用和执行规则。各工作区单独配置任务范围、修改范围、时间窗口与交付权限。
- 配置可以保存多个工作区。新增或更新单个工作区时不得覆盖其它工作区，同一真实目录不得绑定到多个工作区 ID。
- 外部能力由用户安装后选择。Agent 按宿主支持的方式使用绑定的 skill、MCP 工具、CLI 或宿主能力。业务字段、状态、登录、评审与回写规则由该能力处理。

## 项目与依赖

- 通用核心库位于 `domains/agent-task-automation/libs/agent-task-core`，包名为 `@puff/agent-task-core`，标签为 `domain:agent-task-automation`、`type:lib`、`lang:ts`。
- Codex 插件应用位于 `domains/agent-task-automation/apps/codex-plugin`，包名为 `@puff/codex-plugin`，标签为 `domain:agent-task-automation`、`type:app`、`lang:ts`。
- 应用通过 `workspace:*` 依赖核心库，代码和共享资源通过包公开入口引用。核心库定义通用宿主接口，Codex 应用实现该接口并装配插件产物。
- 通用核心和 Codex 适配的配置与源码应使用通用角色和宿主能力接口。具体平台代理、SDK 和凭据由外部能力自行管理。
- 复用现有 Node、TypeScript、tsdown、Vitest 和根 Biome。插件运行时采用 Node 标准库，第三方依赖按根 catalog 管理。
- 创建两个项目时，分别补齐 AGENTS.md、project.json、包脚本和维护归属，更新目录文档并执行根目录完成标准。

## 配置与运行

- 以技术设计中的 CapabilityBinding 和 WorkspaceBinding 为配置依据。宿主用当前工作区核对绑定范围，能力引用仅解析到用户选定的能力。
- 安装引导生成本地工作区绑定与执行规则。用户确认规则并通过只读试跑后，可启用该工作区的宿主计划。
- 配置保存通用执行规则、能力引用和宿主计划关联。凭据、私有工具实现和平台原始响应由外部能力或宿主管理。
- 任务内容参与任务上下文构建。有效操作范围取工作区配置、绑定能力与宿主和仓库规则的交集。
- 同一工作区的新运行共用一个活动名额。短时文件锁保护配置和活动记录更新。宿主运行状态无法确认时走只读检查，取消与停止结果由宿主确认。
- 不同工作区的配置、计划和活动记录相互独立。跨工作区的全局并发调度不属于 v0.1。
- 外部结果未知时，由 Agent 使用原绑定能力核对，核对后从相应阶段继续。会话或摘要保存的是观察结果，外部业务状态以所绑定能力的查询为准。

## 验证

- 独立验证核心库的配置结构、工作区隔离、能力引用、时段、重复触发和暂停恢复。
- 验证应用对核心库的包依赖、插件产物的资源引用，以及目标 Codex 版本的 manifest、安装引导、工作区上下文、Scheduled Task 和结果展示。
- 验证更换能力引用后，可在同一工作区按新配置试跑，且通用核心无需识别具体平台字段。
- 设计文档变更执行 pnpm check、差异与文档一致性检查。实现阶段按根目录完成标准执行构建、测试和依赖边界检查。
